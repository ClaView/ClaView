# ClaView

KOSIS Open API 내 한국은행 소관 통계표를 자연어로 탐색하고, 조회한 자료를 표·그래프와 근거 설명으로 제공하는 에이전트 프로젝트입니다.

- 관리: 팀 공동 / 갱신일: 2026-09-23
- 현재 상태: 공통 환경·API·설계·평가 문서와 데이터 조사 자료를 반영했습니다. 검색 문서 기본 349건·상세 16건, 검토용 매핑 76건·후보 CSV 2개, 개발 질문 48건과 골든셋 초안 5건을 보관합니다. 파일 구조 검수와 의미·정답 승인은 구분하며, 서비스·수집·API 실험 코드는 아직 반영하지 않았습니다.
- 개발 기준: Python 3.12, uv. Ubuntu·Colab 및 작성자 외 팀원 환경은 재현 대기입니다.
- 이 README는 저장소 구조와 관리 원칙의 기준입니다. 구현 방식·API 명세·실험 결과는 해당 상세 문서에서 관리합니다.
- 상태 표기는 이 작업 폴더에 반영된 내용과 확보한 기록을 기준으로 합니다. '미반영·미이관·구현 전'은 다른 작업 위치에서 진행한 팀원의 작업이 없다는 뜻이 아닙니다. 최신 팀 현황·합의는 노션 자료와 대조한 뒤 갱신합니다.

## 시작하기

이 환경 설정이 포함된 작업 폴더의 루트에서 실행합니다. 실제 API 키는 필요하지 않습니다.

```sh
uv python install 3.12
uv sync --locked
uv run --locked python -c "import claview; print('claview import OK')"
uv run --locked python -m pytest -q
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
```

최초 설치에는 Python·패키지 다운로드가 필요할 수 있습니다. 위 명령은 개발환경 검사이며 서비스를 실행하지 않습니다.

- [공통 개발환경](docs/setup/공통_개발환경.md): 설정 파일 역할, 설치, 키 관리, 의존성 변경, Colab 안내, 검증 상태
- 기존 원격 main 이력을 기준으로 `setup/project-v1` 브랜치에서 구조 개편을 준비합니다. 이 구성의 원격 반영 여부는 PR 병합 상태를 확인합니다.

## 1. 목표와 수행 범위

| 구분 | 내용 |
| --- | --- |
| 대상 | KOSIS Open API 내 한국은행 소관 통계표 전체 |
| 처리 | 자연어 탐색 → 조회 조건 확정 → 자료 조회 → 필요한 정합·병합·계산 → 표·그래프·근거 설명 |
| 결과물 | E2E 에이전트, MCP 서버 및 외부 클라이언트 연동, 골든셋과 평가·개선 결과 |
| 제외 | 한국은행 외 기관 통계, ECOS 등 KOSIS 외 수치 소스 연동, 상용 인증·과금·운영 |

대표 표는 구현·시험 순서를 정하는 데 사용합니다. 일부 대표 사례를 검증했다고 전체 표의 조회·해석을 검증한 것으로 보지 않습니다.

### 공통 처리 원칙

- 원자료 수치는 API 응답에서 얻습니다. 파생값은 코드로 계산하고 가공 기록을 남깁니다.
- 표뿐 아니라 항목·분류·통계 기준·기간·주기를 확인합니다.
- 의미가 달라지는 조건은 사용자에게 확인합니다. 기본값을 적용하면 적용 조건을 표시합니다.
- 데이터·조회 조건·출처·가공 기록·경고를 구분해 제공합니다.
- 검색 미적중, 범위 밖, 자료 없음, API 오류를 구분합니다.
- 명칭·기준 변경은 적용 시점과 메타정보 버전을 함께 관리합니다.

## 2. 프로젝트 진행 흐름

### 데이터 준비

```text
통계표 목록 수집
→ 메타정보 확보·구조 검수
→ 공식 용어·별칭·선택 기준 정리
→ 검색 문서 생성·색인 구축
```

### 사용자 질문 처리

```text
질문 입력
→ 의도·조건 해석
→ 통계표·계열 후보 검색
→ 메타정보·조회 조건 검증
   ├─ 모호함: 사용자 확인 → 조건 재검증
   ├─ 처리 불가: 사유·가능한 대안 안내
   └─ 조건 확정
      → API 조회
      → 필요한 정합·병합·계산
      → 표·그래프·근거 설명
```

### 검증·개선

```text
골든셋 작성·검수
→ 기능별 평가·전체 과업 평가
→ 오류 분석
→ 기능·정책 개선
→ 같은 조건에서 재평가
```

평가는 개발 마지막에만 수행하지 않습니다. 대표 사례를 준비하고 구현한 기능부터 반복해서 확인합니다.

## 4. 기능별 책임과 연결

| 위치 | 입력 → 처리 → 출력 | 경계 |
| --- | --- | --- |
| `shared` | 공통 모델·설정·오류 정의 | 특정 기능의 업무 로직을 모으는 곳이 아님 |
| `clients/kosis` | 요청 파라미터 → 통신·응답 파싱 → API 응답 | 사용자 의도에 따른 계열 선택은 하지 않음 |
| `clients/ncp` | 요청 → 인증·통신·응답 처리 → 모델 출력 | 프롬프트·검색 전략은 사용하는 기능이 관리 |
| `metadata` | 목록·메타 응답 → 수집·검수·이력 → 구조화 메타 | 검색 점수·사용자 의도 판단과 분리 |
| `retrieval` | 질문·메타·매핑 → 후보 검색·재정렬 → 표·계열 후보 | 후보 점수만으로 범위 밖이라고 확정하지 않음 |
| `statistics` | 조회 계획·메타 → 조건 검증·조회 → 원값·조회 근거 | 임의로 다른 계열·기간으로 바꾸지 않음 |
| `processing` | 조회 자료·명시적 규칙 → 정합·계산 → 가공 자료·기록 | 원값을 덮어쓰지 않음 |
| `visualization` | 검증된 자료·표현 조건 → 표·차트 | 수치 계산·통계 의미 변경은 처리 모듈의 책임 |
| `agent` | 질문·대화·도구 결과 → 판단·호출·설명 → 응답 | API 통신·계산 로직을 중복 구현하지 않음 |
| `mcp_server` | 도구 요청 → 입출력 검사·공통 기능 호출 → 도구 응답 | 별도의 검색·조회 엔진을 만들지 않음 |
| `apps/demo` | 질문·선택·결과 → 입력·표시 | 데이터 처리 로직을 화면에 넣지 않음 |

위 표의 기능 위치는 모두 `src/claview/` 기준이며, `apps/demo`는 저장소 루트 기준입니다.

### 연결 규칙

- 공통 기능은 에이전트·MCP 서버·화면에 의존하지 않습니다.
- 메타 수집·통계 조회는 KOSIS 클라이언트를, 검색·에이전트의 모델 호출은 NCP 클라이언트를 사용합니다.
- MCP 서버는 공통 기능을 도구로 제공합니다. 자체 에이전트가 직접 호출할지 MCP 클라이언트를 거칠지는 연결 단계에서 결정합니다.
- 설명 생성은 에이전트가 담당하고, 설명에 쓰는 수치와 근거는 조회·처리 결과에서 가져옵니다.
- `scripts`는 실행 옵션과 진입점을 제공합니다. 재사용 로직은 `src/claview`에 둡니다.
- 공통 데이터 모델을 구현할 때 `shared`를 실행용 기준으로 둡니다. JSON Schema가 필요하면 생성하거나 동기화 검사를 두고, 문서와 별개로 수작업 규격을 중복 관리하지 않습니다.
- 모델·검색 제품·프레임워크는 미확정입니다. 특정 제품 이름을 기준으로 상위 폴더를 나누지 않습니다.

## 5. 자료와 산출물 보관 기준

| 종류 | 위치 | 관리 기준 |
| --- | --- | --- |
| 검토한 통계표 목록·확보 현황 | `data/catalog` | 수집 기준·표 ID·검수 범위 명시 |
| 공식 용어·별칭·선택 기준 | `data/mappings` | 연결 코드·근거·검수 상태 기록 |
| 선별한 후보 검토 스냅샷 | `data/mappings/review` | 원본·해시 보존. 승인된 매핑과 구분하고 검색에 자동 반영하지 않음 |
| 개발용 대표 자료 | `data/samples` | 출처·조회 조건을 함께 제공 |
| 초기 검색 문서 검토 묶음 | `data/samples/search-review` | 파일 구조 검수와 의미 승인 구분. 이후 대량 생성물은 processed에 보관 |
| 테스트에 고정된 입력·응답 | `tests/fixtures` | 실제 응답과 합성 오류 사례를 구분 |
| 전체 원본·캐시 | `data/raw` | 기본 Git 제외, 공용 확보 방법 필요 |
| 생성한 검색 문서·색인 | `data/processed`, `data/indexes` | 입력 버전과 생성 절차로 재현 |
| 질문과 기대 행동·정답 | `eval/goldenset` | 근거·검수자·검수 상태·기준 시점 관리 |
| 미승인 개발 질문 스냅샷 | `eval/goldenset/review` | 정답셋과 합산·자동 채점 금지, 승인 후 기준 사례에 연결 |
| 검토한 평가 요약 | `eval/reports` | 코드·데이터·모델·평가 조건과 연결 |
| 실행 로그·상세 결과 | `artifacts` | 기본 Git 제외. 필요한 요약만 문서로 반영 |
| 채택 전 실험 | `experiments` | 목적·실행 방법·결과·한계를 기록 |

- 기준 자료와 생성 자료를 구분합니다. 같은 내용을 여러 파일에서 독립적으로 수정하지 않습니다.
- CSV·JSON을 함께 유지한다면 어느 파일이 기준이고 어느 파일이 생성본인지 정합니다.
- 수집 성공, 구조 검수, 실제 조회 성공, 원표 수치 대조를 별도 상태로 관리합니다.
- 표별 수록기간은 지원 주기별로 관리합니다. 요약 화면의 대표 기간을 모든 주기의 수록기간으로 사용하지 않습니다.
- 추정 단위·매핑 후보는 검증된 값과 구분합니다. 메타 수집 완료를 의미 검수 완료로 표현하지 않습니다.
- 원자료를 Git에서 제외하더라도 팀원이 받을 수 있는 위치 또는 재생성 절차가 있어야 합니다.
- 자료 반영 시 `data/README.md`에 파일 목록·출처·수집일·검수 범위·확보 방법을 작성합니다.
