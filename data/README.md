- 관리: 데이터·검색 담당 / 검토일: 2026-09-23
- 현재 공유 범위: 통계표 목록·메타 확보 현황 349개, 대표 메타 3개 표, 통계어 사전 검토용 CSV 2개, 기본 검색 문서 349건·상세 16건·매핑 76건. 별도 개발 질문 48건은 `eval/goldenset/review/`에 보관합니다.
- 실제 수치·전수 메타 캐시·승인된 용어 매핑·검색 색인은 아직 이관하지 않았습니다. 검토용 CSV는 승인 사전과 구분합니다.
- 읽는 순서: [조사 결과](../docs/data/한국은행_통계표_조사결과.md) → 아래 파일 설명 → [검수 기준](../docs/data/메타정보_관리와_검수.md).

CSV는 UTF-8(BOM 허용), 쉼표 구분이며 ID는 문자열로 읽습니다. `catalog/`의 CSV는 원본의 컬럼명·행 순서·셀 값을 보존하고 BOM·줄바꿈을 정리했습니다. 원본과 파일 해시가 달라도 파싱한 행 내용은 같도록 검수했습니다. `mappings/review/`의 두 CSV는 BOM·줄바꿈을 포함한 원본 바이트와 해시가 같습니다.

`.gitattributes`에서 일반 텍스트는 LF, CSV는 Git의 줄바꿈 변환 제외로 설정합니다. 운영체제가 달라져도 공유 파일의 해시와 원본 보존 기준을 유지하기 위한 설정입니다.

파일명을 유지한 것은 기존 조사 자료와 연결하기 위해서입니다. 새 관리 문서는 한국어 이름을 사용합니다.

## 2. 컬럼 해석

### 통계표 목록

| 컬럼 | 의미 |
| --- | --- |
| ORG_ID / TBL_ID | 기관·표 식별 코드 |
| TBL_NM | 제공 목록의 표명 |
| 분류(목록명) / 목록ID / VW_CD | 수집 결과에 남은 목록 위치 정보 |

현재 목록은 표당 한 행입니다. 전체 상위 경로·중복 경로가 모두 보존됐다는 뜻은 아닙니다. 전체 경로가 필요한 검색에는 수집 단계 보완이 필요합니다.

### 메타 확보 현황

| 컬럼 | 의미·주의사항 |
| --- | --- |
| orgId / tblId / 표명 / 분류 | 목록·캐시와 연결할 식별 정보 |
| TBL / PRD / ITM / UNIT / CMMT | 수집 코드가 기록한 메타 종류별 상태 |
| 주기 | 지원 주기 이름을 /로 연결한 요약 |
| 수록시작 / 수록끝 | 월이 있으면 월 기간, 없으면 PRD 첫 행. 모든 주기의 기간이 아님 |
| 단위 | UNIT·ITM의 UNIT_NM을 합친 요약. 실제 선택 계열의 단위는 별도 확인 |
| 분류축수 | ITEM 외 항목의 OBJ_NM 고유 개수. 공식 축 ID 기준 집계와 구분 |
| 항목수 | ITM에서 OBJ_ID가 ITEM이 아닌 행 수. 공통 ITEM 개수·총 관측값 개수 아님 |
| 주석유무 | 저장된 CMMT가 비어 있는지에 따른 Y/N |
| 종합상태 | 수집 코드의 기술적 상태. 의미·수치·원표 검수 완료 아님 |
| 비고 | 자동 생성한 구조 참고 문구. 추가 해석은 조사 결과 문서 참조 |

원래 컬럼명을 바꾸지 않았으므로 위 정의를 먼저 읽습니다. 특히 `항목수`, `종합상태`를 의미상 더 넓은 지표로 사용하지 않습니다.

### 대표 메타 JSON

최상위는 표 객체 3개의 배열입니다. 객체마다 `orgId`, `tblId`, `name`, `cat`, `meta`, `status`가 있습니다. `meta`는 TBL·PRD·ITM·UNIT·CMMT의 파싱 결과입니다.

전체 HTTP 응답·요청 헤더·최초 오류 원문이 아닙니다. 수집 코드의 파싱 보정이 이미 적용됐을 수 있습니다.

### 통계어 사전 검토용 CSV

| 파일·컬럼 | 의미·주의사항 |
| --- | --- |
| 우선순위: 우선순위 / 분류사유 | 원본의 1·2·3·제외 분류. `제외`는 별도 코드 매핑 대상으로 분류한 것이며 표를 프로젝트에서 제외하지 않음 |
| 우선순위: 공식어 / 핵심어 / 유형 | 추출 문자열·전처리 문자열·분류. 핵심어 공백을 원 공식어로 덮어쓰지 않음 |
| 우선순위: 빈도(표수) / 예시tblId | 보고된 출현 표 수와 예시 표 하나. 전체 출처 목록이나 실제 항목·분류 코드가 아님 |
| 우선순위: 유사어_일상어 / 검토자 / 상태 | 제공 파일에서는 전부 공백. 사람의 검수 완료 기록이 없음 |
| 후보: 공식어 / 유형 / 빈도(표수) | 우선순위 파일과 연결되는 정보 |
| 후보: 일상어후보 / 직접유사도 | 생성 표현과 저장된 유사도. 확률·정답 신뢰도로 해석하지 않음 |
| 후보: 최근접공식어 / 자기매칭 | 저장된 최근접 문자열과 생성 대상의 일치 여부. 비교 대상 집합은 별도 확보 필요 |
| 후보: 판정 | 원본의 `자동채택`·`검토`·`폐기후보`. 승인·기각 확정 결과와 구분 |

현재 집계·해시·확인한 문제는 [파일럿 검토 결과](../docs/data/통계어사전_파일럿_검토결과.md)를 기준으로 합니다. 후보 생성 코드·입력 목록이 없어 실험을 재실행한 자료는 아닙니다. `review/`를 검색·색인에서 자동 로드하지 않으며, 승인 기록과 코드 연결을 확인한 자료만 검색용 기준본에 반영합니다.

팀 공용 다운로드 위치는 아직 정해지지 않았습니다. 현재 파일만으로 대표 3개 표 외의 상세 메타 재현이나 전수 수집 재실행이 가능하다고 가정하지 않습니다.

## 4. 갱신과 공유

- 현재 CSV는 고정 스냅샷입니다. 최신 수집본으로 교체할 때 수집 시각·코드 버전·변경 범위·파일 해시를 함께 갱신합니다.
- 현황 CSV를 수작업으로 수정해 수집 사실을 바꾸지 않습니다. 의미 검수·수치 대조 결과는 별도 상태로 추가 관리합니다.
- 대표 샘플을 수정하면 원본 추출인지 설명용 가공인지 구분합니다.
- 전수 원자료·캐시는 `raw/`, 생성 문서는 `processed/`, 색인은 `indexes/`에 두며 기본 Git 제외입니다.
- 팀 검토에 필요한 고정 후보 스냅샷만 `mappings/review/`에서 공유합니다. 대량 생성 결과를 계속 쌓는 위치가 아니며, 원본 판정과 사람의 승인 기록을 분리합니다.
- 초기 검색 입력만 `samples/search-review/`에서 동결 보관합니다. 이후 대량 생성 문서는 `processed/`에 둡니다. 상세 문서·매핑은 승인된 서비스 입력으로 자동 로드하지 않습니다.
- 노션에는 이 안내와 조사 결과의 GitHub 링크를 연결합니다. 스냅샷 숫자를 여러 페이지에서 독립적으로 수정하지 않습니다.

검색 자료의 필드·확인 범위·원본 연결은 [검색 자료 검수 기록](../docs/data/검색자료_이관과_검수.md)을 참조합니다. 오프라인 재검사 명령은 `uv run --locked python scripts/validate_search_materials.py`입니다. API 호출·의미 승인을 수행하는 검사는 아닙니다.
