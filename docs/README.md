## 2. NCP 문서 — 네 가지 역할

| 읽는 순서 | 문서 | 이 문서에서만 상세 관리할 내용 |
| --- | --- | --- |
| 1 | [모델 역할과 적용 방향](api/NCP_모델분석과_적용방향.md) | 9종 구분, RAG 방식과 제품 차이, 사양·선정 시점 |
| 2 | [API 입출력과 사용 가이드](api/NCP_API_활용가이드.md) | 경로·필드·예시·실행 명령·오류·기록 방법 |
| 3 | [초기 호출 검증 결과](evaluation/NCP_초기호출_검증결과.md) | 실측 조건·출력·내용 판정·미검증 항목 |
| 4 | [비용과 이용한도](api/NCP_비용과_이용한도.md) | 공식 단가·시험 비용 환산·계정 확인 사항 |

읽는 흐름: **역할 이해 → 입출력·실행 확인 → 실제 결과와 한계 확인 → 비용·한도 확인**.

모델 사양은 공식 문서, 호출 결과는 실행 증거, 채택은 팀 결정입니다. 최소 연결 성공을 과업 평가 완료로 해석하지 않습니다. 대화 모델·임베딩의 최종 선정은 관련 기능의 구현·평가 일정에 맞춰 진행합니다.

## 3. 문서 연결과 갱신

- 데이터·매핑 담당의 검수 자료 → NCP 모델 비교 입력 → 평가 결과 → 설계 결정 순서로 연결합니다.
- API 필드·재현 명령은 API 가이드에서, 모델별 관측 숫자는 결과 문서에서만 상세 갱신합니다.
- 전체 시스템 설계를 NCP 문서에 복제하지 않고 아키텍처 문서로 연결합니다.
- 멘토링 사전 자료는 위 문서의 현재 상태·미확인 질문을 요약해 노션에서 작성합니다. 아직 별도 작성하지 않았습니다.

## 4. 공유·관리 기준

노션 문서 DB에는 문서명·담당·확인일·검증 상태·GitHub 링크를 기록합니다. GitHub 반영 전 Markdown 복사본을 공유하면 확인일을 표시하고, 반영 후 코드 연관 최신본은 저장소 링크로 연결합니다.

일반 문서명은 한국어를 사용하고 담당·확인일·상태·출처를 남깁니다. 내부 링크는 상대경로, 명령은 저장소 루트 기준입니다. 비밀정보·개인 경로·원본 실행 로그는 공유하지 않습니다. 데이터 집계는 기준 시점·검수 범위를 명시하고 결정 변경에는 이유와 관련 PR을 남깁니다.

커밋 후보·제외 파일은 [팀 공유 문서 목록](팀_공유_문서목록.md)에서 관리합니다.
