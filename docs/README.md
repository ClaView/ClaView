# 개발 문서

팀원이 이 저장소와 공유된 출처만으로 이해하고 재현할 수 있는 개발 문서를 관리합니다. 개인 조사 자료는 검토 후 필요한 내용만 독립적인 팀 문서로 정리합니다. 현재는 문서 분류만 준비한 상태입니다.

## 분류

| 폴더 | 문서 예시 |
|---|---|
| project | 수행 범위·필수 결과물·제출 제안서 안내 |
| setup | 공통 개발환경·실행·환경변수 안내 |
| architecture | 최신 아키텍처·데이터 흐름·모듈 책임 |
| api | KOSIS·NCP 사용 안내·MCP 도구 계약 |
| data | 목록·메타정보 조사·단위·주기·용어 매핑 정책 |
| evaluation | 골든셋 작성·채점 기준·평가 재현 방법 |
| decisions | 합의한 설계 선택과 변경 이유 |

## 문서 작성 우선순위

1. project: 기업 요구사항과 현재 합의한 범위 정리.
2. setup / api: 기존 KOSIS 실행 방법과 NCP 사용 조건 검토.
3. data: 조사 결과·검수 범위·미확인 사항 정리.
4. architecture: 구현에 적용할 최신 구조만 선별.
5. evaluation / decisions: 평가 초안과 팀 합의 사항 축적.

## 문서에 기록할 정보

- 상태: 초안 / 검토 중 / 합의됨 / 대체됨
- 담당자 및 최종 확인일
- 근거: 공식 출처 URL, 팀원이 접근 가능한 노션 링크, 저장소 내 관련 문서의 상대경로
- 확인된 사실 / 구현 계획 / 미확정 사항
- 재현 명령과 결과 위치, 관련 코드·이슈

자료의 수치와 구현 상태는 반영 시 다시 확인합니다. 팀의 가공 문서는 공식 출처와 구분합니다. 키가 포함된 명령·응답·URL은 공유 전에 제거합니다.

## 경로와 재현 기준

- 문서 내부 링크는 해당 문서 위치를 기준으로 작성합니다. 예: 이 문서에서 프로젝트 소개는 `[프로젝트 소개](../README.md)`로 연결합니다.
- 실행 명령은 저장소 루트에서 실행하는 것을 기본으로 하며, 다른 작업 위치가 필요하면 명시합니다.
- 개인 작업 폴더명, 사용자명, 로컬 절대경로, 개인 전용 링크를 넣지 않습니다.
- 재현에 필요한 코드는 scripts 또는 src에, 공유 가능한 소규모 샘플은 data/samples에 포함하고 실제 존재하는 파일만 연결합니다.
- 대형 자료는 팀 공용 보관 위치와 접근 방법 또는 재생성 절차를 안내합니다.
- 개인 작업 일지와 초안은 포함하지 않습니다. 팀 검토용 초안은 상태와 미확정 사항을 명시합니다.

일정과 업무는 노션에서 관리하고, 여기에 복제하여 별도의 최신본을 만들지 않습니다. 이전 발표용 문서와 현재 구현 계약이 다르면 최신 결정과 변경 이유를 명시합니다.
