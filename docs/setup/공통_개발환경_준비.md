| 항목 | 기준 |
| --- | --- |
| Python | 3.12.x |

Python 패치 버전은 공통 고정 전입니다. 실행 결과에 실제 버전을 기록합니다. 모델·데이터 API 호출, 검색 라이브러리, 에이전트 프레임워크, Docker는 별도 기능 작업에서 추가합니다.

## 1. 저장소와 도구 준비

팀 저장소: [ClaView/ClaView](https://github.com/ClaView/ClaView)

저장소가 없는 경우:

```sh
git clone https://github.com/ClaView/ClaView.git
cd ClaView
```

이미 작업 중인 저장소가 있으면 해당 폴더를 사용합니다. 환경 설정이 있는 공유 브랜치 또는 병합된 main을 선택합니다. 작업 파일을 보존한 뒤 브랜치를 전환합니다.

uv는 [공식 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)에 따라 설치합니다.

```sh
git status --short --branch
uv --version
```

## 2. 환경 설치

```sh
uv python install 3.12
uv sync --locked
uv run --locked python --version
```

| 파일 | 역할 |
| --- | --- |
| `.python-version` | Python 3.12 계열 선택 |
| `pyproject.toml` | Python 제약, 패키지 구성, 의존성 정의 |
| `uv.lock` | 의존성 버전 고정 |
| `src/claview/__init__.py` | 프로젝트 패키지 |
| `tests/unit/test_environment.py` | Python 버전·패키지 import·설치 확인 |
| `tests/conftest.py` | 기본 테스트의 외부 연결 차단 |

`uv run`은 프로젝트 가상환경을 사용합니다. 별도의 가상환경 활성화는 필요하지 않습니다. 최초 설치에는 Python·패키지 다운로드가 발생할 수 있습니다.

의존성을 변경할 때는 목적을 팀에 공유하고 `pyproject.toml`과 `uv.lock`을 함께 반영합니다. 선택 의존성 그룹은 기본 설치 대상에서 제외됩니다.

## 3. 기본 실행 확인

```sh
uv run --locked python -c "import claview; print('claview import OK')"
uv run --locked python -m pytest -q
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
```

기본 테스트는 Python 3.12, 패키지 import, 설치된 패키지 버전을 확인합니다. API 키와 외부 API 호출이 필요하지 않습니다. 서비스 기능·데이터 정확성은 별도 테스트 대상입니다.

## 4. 환경변수 관리

API 기능을 사용할 때만 `.env.example`을 `.env`로 복사하고 전달받은 키를 입력합니다. 기존 `.env`는 유지합니다.

PowerShell:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

Ubuntu:

```sh
test -e .env || cp .env.example .env
```

```sh
git check-ignore .env
```

- 키는 편집기에서 입력하고 채팅·문서·로그·명령줄 인자에 남기지 않습니다.
- Python은 `.env`를 자동으로 읽지 않습니다. 해당 기능에서 환경변수 로딩을 구현합니다.
- 설치·기본 테스트에는 `.env` 생성이 필요하지 않습니다.

## 7. 의존성 변경과 팀 공유

1. 팀 채널 또는 해당 업무 댓글에 패키지 이름·사용 기능·추가 이유·영향 범위를 남깁니다.
2. 작업 브랜치에서 패키지를 추가하고 기본 테스트와 관련 기능 테스트를 실행합니다.
3. PR에 추가 이유·버전·테스트 결과를 기록하고 `pyproject.toml`과 `uv.lock`을 함께 포함합니다.
4. 병합 후 팀원에게 변경 내용과 `uv sync --locked` 실행을 안내합니다.

일반 패키지 추가는 목적 공유와 PR 리뷰로 처리합니다. Python 버전 변경, 핵심 프레임워크 도입, 주요 버전 업그레이드는 작업 전 팀과 합의합니다.

공유할 항목:

```text
패키지:
사용할 기능:
추가·변경 이유:
공통 코드·입출력에 미치는 영향:
관련 업무 / PR:
```

패키지 추가 예시:

```sh
uv add pandas
uv run --locked python -m pytest -q
git add pyproject.toml uv.lock
```

TOML의 의존성 항목을 직접 수정했다면 `uv lock`과 `uv sync --locked`를 실행합니다. uv 프로그램 자체의 업데이트는 별도 관리합니다.

팀원은 로컬 변경을 보존한 뒤 병합된 main을 받아 동기화합니다.

```sh
git switch main
git pull --ff-only
uv sync --locked
uv run --locked python -m pytest -q
```

## 문제 해결

| 증상 | 확인 방법 |
| --- | --- |
| uv 명령을 찾지 못함 | 설치 후 터미널 재실행, PATH 확인 |
| Python 버전 불일치 | 저장소 루트에서 uv run으로 실행 |
| 잠금 파일 불일치 | 설정·잠금 파일을 같은 커밋에서 받았는지 확인 |
| hardlink 경고 | 설치 실패 시 uv sync --locked --link-mode copy 사용 |
| import 실패 | 저장소 위치·src/claview·설치 성공 여부 확인 |
| pytest가 테스트를 찾지 못함 | tests/unit 파일과 실행 위치 확인 |

참고: [uv 프로젝트 관리](https://docs.astral.sh/uv/guides/projects/)
