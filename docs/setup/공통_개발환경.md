# 공통 개발환경

- 관리: 팀 공동
- 갱신일: 2026-09-23
- 범위: Python 패키지 설치·기본 테스트·코드 검사. 실제 API와 서비스 실행은 별도 기능 작업입니다.
- 구조 기준: [루트 README](../../README.md)

## 1. 환경과 설정 파일

| 항목 | 기준 |
| --- | --- |
| Python | 3.12.x. 패치 버전은 공통 고정 전이며 재현 결과에 기록 |
| 의존성 관리 | uv와 uv.lock |
| 패키지 | src/claview |
| 기본 개발 도구 | pytest, Ruff |
| 실행 위치 | pyproject.toml이 있는 저장소 루트 |
| 기본 테스트 | API 키 없이 실행, 일반적인 Python TCP 연결 차단 |
| 실제 API 시험 | 별도 실행. 사용 권한·한도·비용 확인 후 수행 |

| 파일 | 역할 |
| --- | --- |
| [pyproject.toml](../../pyproject.toml) | Python 허용 범위·패키지·의존성·검사 설정의 기준 |

| [.python-version](../../.python-version) | uv가 기본 선택할 Python 3.12 계열 지정 |

| [기본 환경 테스트](../../tests/unit/test_environment.py) | Python·import·설치 버전·네트워크 차단 동작 검사 |
| [테스트 공통 설정](../../tests/conftest.py) | tests 아래에 적용되는 오프라인 연결 차단 |

현재 서비스용 의존성은 없습니다. NCP 실험, 검색·데이터 라이브러리, 에이전트 프레임워크, 화면, Docker는 이번 기본 환경에 포함하지 않습니다.

`.python-version`은 Python 선택 기준이고 `requires-python`은 허용 범위입니다. `uv.lock`은 Python 실행 파일이나 운영체제까지 고정하지 않으므로 OS·Python·uv 버전을 함께 기록합니다.

## 2. 준비

팀 저장소: [ClaView/ClaView](https://github.com/ClaView/ClaView)

이 환경 변경이 원격에 반영되기 전에는 원격 main과 로컬 파일 구성이 다를 수 있습니다. 팀에 안내된 PR 또는 병합 커밋을 기준으로 준비합니다. 아래 절차는 설정 파일이 모두 있는 작업 폴더에서 실행합니다.

uv는 [공식 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)를 따릅니다. 설치 후 터미널에서 확인합니다.

```sh
uv --version
```

Git 저장소로 연결된 작업 폴더에서는 브랜치·로컬 변경도 확인합니다.

```sh
git status --short --branch
```

Git에 아직 연결되지 않은 폴더에서도 아래 설치·테스트는 가능합니다. Git 연결·이력 이관은 환경 설치와 별도로 진행합니다.

## 3. 설치

```sh
uv python install 3.12
uv sync --locked
uv run --locked python --version
```

- `uv sync --locked`는 잠금 파일과 설정이 맞지 않으면 실패합니다. 다른 팀원이 받았다는 이유만으로 잠금 파일을 새로 만들지 않습니다.
- 기본 개발 그룹인 dev의 pytest·Ruff가 설치됩니다. 가상환경은 `.venv`에 생성됩니다.
- `uv run`은 프로젝트 환경을 사용하므로 별도 가상환경 활성화가 필요하지 않습니다.
- 최초 설치에는 Python·패키지 다운로드가 필요할 수 있습니다. 설치 과정의 네트워크 사용과 테스트 중 API 호출은 별개입니다.
- 다른 위치에서 사용하던 `.venv`는 복사하지 않고 이 폴더에서 새로 설치합니다.

## 4. 기본 확인

```sh
uv run --locked python -c "import claview; print('claview import OK')"
uv run --locked python -m pytest -q
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
```

| 검사 | 통과 기준 |
| --- | --- |
| Python | 3.12 계열 |
| 패키지 import | claview import 성공 |
| 설치 버전 | 설치된 패키지 버전과 pyproject.toml의 버전 일치 |
| 테스트 연결 차단 | socket.connect·connect_ex·create_connection 호출이 차단됨 |
| Ruff | 코드·포맷 검사 오류 없음 |

현재는 기본 환경 테스트 6건입니다. `testpaths`는 `tests` 전체로 설정되어 있어 향후 계약·통합 테스트도 기본 검사에 포함됩니다. `experiments`는 별도로 실행합니다.

연결 차단은 pytest 실행 중 일반적인 Python TCP 연결을 막는 장치입니다. 별도 프로세스·UDP·네이티브 라이브러리까지 막는 보안 격리는 아닙니다. 기본 테스트에는 실제 API 호출 코드를 넣지 않습니다.

이 검사는 환경만 확인합니다. KOSIS 조회, NCP 모델 접근, 데이터 정확성, MCP·에이전트 동작의 검증 완료를 의미하지 않습니다.

## 5. API 키와 환경변수

기본 설치·테스트에는 `.env`와 API 키가 필요하지 않습니다.

나중에 API 기능을 사용할 때만 `.env.example`을 복사합니다. 이미 있는 `.env`는 덮어쓰지 않습니다.

PowerShell:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

Ubuntu:

```sh
test -e .env || cp .env.example .env
```

- 키는 편집기에서 입력하고 문서·채팅·명령줄 인자·로그에 남기지 않습니다.
- Python은 `.env`를 자동으로 읽지 않습니다. 아직 환경변수 로딩 기능은 구현하지 않았습니다.
- 실제 실행 방법은 해당 API 기능의 안내에 따릅니다.
- Git 연결 후 `git check-ignore .env`로 제외 여부를 확인하고 PR에 실제 키가 포함되지 않았는지 검사합니다.

## 6. 의존성 변경

설치할 때마다 uv 자체를 업데이트할 필요는 없습니다. 프로젝트 의존성 변경과 uv 프로그램 업데이트를 구분합니다.

1. 사용할 기능·추가 이유·영향 범위를 공유합니다.
2. 실제 필요한 의존성만 추가합니다. 테스트 도구는 dev 그룹, 선택 실험 도구는 별도 그룹으로 관리합니다.
3. `pyproject.toml`과 `uv.lock`을 함께 반영합니다.
4. 기본 검사와 관련 기능 테스트를 실행합니다.
5. PR에 변경 이유·검증 결과를 남깁니다. 병합 후 팀원은 `uv sync --locked`로 동기화합니다.

예: 런타임에서 pandas를 사용하기로 합의한 경우에만 실행합니다.

```sh
uv add pandas
uv run --locked python -m pytest -q
```

TOML을 직접 수정했다면 잠금 파일을 갱신하고 설치합니다.

```sh
uv lock
uv sync --locked
```

Python 변경, 핵심 프레임워크 도입, 주요 버전 업그레이드는 작업 전 팀과 합의합니다. 브랜치·리뷰·병합의 상세 규칙은 협업 문서가 마련되면 연결합니다.

## 7. Colab에서 실행할 때

아래는 재현 전 안내입니다. 비공개 저장소를 받을 때 토큰을 노트북 셀·URL·출력에 남기지 않습니다.

설정 파일이 모두 있는 프로젝트 폴더로 작업 위치를 이동한 뒤 실행합니다.

```python
%pip install uv
```

```sh
!uv python install 3.12
!uv sync --locked
!uv run --locked python --version
!uv run --locked python -m pytest -q
!uv run --locked ruff check src tests
!uv run --locked ruff format --check src tests
```

`uv run`은 별도 Python 프로세스입니다. 일반 노트북 셀의 Python 버전·패키지를 바꾸지 않습니다. 노트북 셀에서 직접 import하는 방식은 별도로 호환성을 확인해야 합니다. Ubuntu·Colab 및 팀원 환경 재현은 확인 후 아래에 기록합니다.

## 8. 검증 상태와 완료 기준

| 구분 | 상태 |
| --- | --- |
| Windows / Python 3.12.13 / uv 0.12.5 | 2026-09-23 새 가상환경에서 설치·import·기본 테스트 6건·Ruff 코드/포맷 검사 통과 |
| Ubuntu·Colab | 미검증 |
| 작성자 외 팀원 환경 | 재현 대기 |
| 실제 KOSIS·NCP 호출 | 이번 검증 범위 밖 |

검증은 기존 로컬 캐시를 사용해 `uv lock --offline`, `uv sync --locked --offline`과 `uv run --locked --offline` 명령으로 진행했습니다. 캐시가 없는 신규 PC의 다운로드·설치는 미검증입니다. 설치 중 hardlink 대신 파일 복사로 전환한다는 경고가 있었으며 설치와 검사는 정상 완료됐습니다.

이번 잠금 파일에는 기본 환경의 pytest 9.1.1, Ruff 0.16.8과 해당 의존성이 포함됩니다. NCP 전용 의존성과 실험 코드는 포함하지 않았습니다.

팀 공유 완료 기준은 작성자 외 팀원 최소 1명의 설치·기본 검사 통과와 PR 리뷰입니다.

재현 결과는 다음 정보를 남깁니다. 개인 경로와 키가 섞인 오류 메시지는 제거합니다.

```text
확인일:
OS / Python / uv 버전:
커밋 또는 검토 중인 변경본:
설치 / import / pytest / Ruff 결과:
실패 단계와 오류 요약:
```

## 9. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| uv 명령을 찾지 못함 | 설치 후 터미널 재실행, PATH 확인 |
| Python 버전 불일치 | 저장소 루트에서 uv run을 사용했는지 확인 |
| 잠금 파일 불일치 | pyproject.toml과 uv.lock을 같은 변경본에서 받았는지 확인 |
| 복사·hardlink 경고 또는 오류 | 실제 설치 실패인지 먼저 확인. 필요 시 uv sync --locked --link-mode copy |
| import 실패 | src/claview와 패키지 설치 성공 여부 확인 |
| 테스트 수집 실패 | 작업 위치·tests·pyproject.toml 확인 |
| 테스트 중 Network access is forbidden | 실제 연결 대신 모의 응답 사용. 차단을 해제해 기본 검사를 통과시키지 않음 |
| Colab 셀에서 import 실패 | 셀의 커널과 uv 프로세스가 별도 환경인지 확인 |

참고: [uv 프로젝트 관리](https://docs.astral.sh/uv/guides/projects/)
