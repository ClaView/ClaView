# 프로젝트 개발계획

- 관리: 팀 공동 / 정리일: 2026-09-23
- 상태: 기존 제안서와 2026-09-23 멘토링 내용을 반영한 수행 계획. 세부 계약·기술 선택은 검토 중입니다.
- 근거: 기존 제안서 개발계획·수행 범위 문서, 팀의 범위·기간·주간 업무 운영 합의. 기업 원문을 이번 이관에서 새로 확인한 것은 아닙니다.
- 기준 링크: [목표·범위·처리 원칙](../../README.md), [실행 구조](처리흐름과_연결구조.md), [평가 계획](골든셋과_평가계획.md)
- 요구사항 원문: [기업 프로젝트 소개](https://psychedelic-uncle-650.notion.site/3d631c089bcd806a93dcf46c4dc94c4b), [기업 공통 안내](https://psychedelic-uncle-650.notion.site/39531c089bcd80afaff9d8f24a62ab7c). 기존 문서의 출처 링크를 유지한 것이며 이번에 원문을 새로 검증하지 않았습니다.

## 1. 목표와 결과물

사용자가 원하는 통계를 찾기 위해 해야 하는 표 탐색, 항목·분류·기준 선택, 자료 비교, 수치·출처 확인을 자연어 질문에서 결과까지 연결합니다.

대상은 **KOSIS Open API 내 한국은행 소관 통계표 전체**입니다. 금리 등 대표 사례는 구현과 검증 순서를 정하기 위한 것이며 범위를 제한하지 않습니다. 상세 포함·제외 범위는 README를 기준으로 관리합니다.

| 결과물 | 완료 시 확인할 내용 |
| --- | --- |
| E2E 에이전트 | 질문·조건 확인·조회·필요한 가공·표/그래프·근거 설명이 연결됨 |
| MCP 서버·외부 연동 | 공통 기능을 도구로 제공하고 외부 클라이언트에서 호출·결과 확인 |
| 골든셋 | 질문 유형별 기대 행동·정답 조건·근거·검수 상태가 있음 |
| 평가·개선 결과 | 단계별 오류와 전체 과업 성공을 측정하고 같은 조건에서 개선 전후 비교 |
| 실행·인계 문서 | 환경·설정·자료 확보·실행 방법·제약을 팀원이 재현할 수 있음 |

정확도 목표나 시연 건수는 이 표만으로 확정하지 않습니다. 평가 기준과 실제 구현 상태를 함께 보고 완료를 판단합니다.

## 2. 구현을 시작할 사례

대표 사례는 예금은행 가계대출 금리의 신규취급액·잔액 기준 비교입니다.

- 질문에 대상 기관·통계 기준·기간·주기가 명확한지 먼저 확인합니다.
- 두 기준은 별도 계열로 조회하고 합산하지 않습니다.
- 같은 월별 축에서 비교하고 계열별 조건·출처·주의사항을 제공합니다.
- 과거 조회 기록의 조건은 [KOSIS 가이드](../guides/KOSIS_조회조건과_검증절차.md)에 있습니다.
- 새 저장소에는 대표 메타만 있으며, 수치 원본·원표 대조 자료는 아직 이관하지 않았습니다.

목업이나 문서의 예시는 에이전트 실행 성공의 증거가 아닙니다. 대표 사례를 관통시킨 후 다주기·다축·단위 혼재 등 구조가 다른 사례로 검증을 넓힙니다.

## 3. 주차별 목표와 확인할 결과

수행 기간은 2026-09-21~2026-11-10입니다. 아래 7주차는 계획상의 작업 묶음이며, 정확한 날짜·휴일·마감·담당은 노션 전체일정과 팀 업무에서 관리합니다.

| 주차 | 중심 작업 | 확인할 결과 |
| --- | --- | --- |
| 1주 | 데이터 관찰·개발 기반 | 목록·메타 현황, 구조 사례, 환경 재현, 규격·골든셋 초안 |
| 2주 | 정상 질문 사례·구간별 기본 구현 | 검수한 개발 사례 15~20건, 표 찾기·값 추출·그래프 생성의 독립 시험, HCX·LangGraph 실습 기록 |
| 3주 | 구간별 보완·연결·MCP 초기 구현 | 유효 조회 조건, 대표 수치 재현, 처리 규칙과 도구별 시험 |
| 4주 | 시각화·대화·전체 연결 | 정상·조건 확인·실패 흐름 시연, 외부 클라이언트 연동 확인 |
| 5주 | 종합 평가·오류 분석 | 단계별·도구·E2E 측정 결과, 개선 우선순위 |
| 6주 | 개선·회귀 검증 | 같은 조건의 개선 전후 비교, 회귀 시험, 남은 한계 |
| 7주 | 정리·최종 발표 | 실행 안내, 최종 자료, 시연·리허설, 최종 발표 |

평가를 5주차에 처음 시작하지 않습니다. 기능이 생기는 대로 대표 사례를 검사합니다. 데이터·매핑·골든셋 보완도 전 기간 병행합니다.

## 4. 매주 업무를 정하는 방법

매주 직전 또는 첫날에 다음을 정합니다.

1. 이번 주에 확인할 결과와 최소 완료 조건.
2. 그 결과를 만드는 작업과 앞뒤 의존 관계.
3. 담당자·검토자·기한·공유할 파일.
4. 연동에 필요한 최소 입출력 예시.
5. 미완료 작업의 영향과 다음 주 조정.

기능 폴더는 개인 소유 영역이 아닙니다. 담당 배정은 노션에서 하고 공통 규격 변경은 영향을 받는 담당자와 함께 검토합니다.

## 5. 현재 기반과 다음 구현

현재 공유된 기반은 공통 개발환경, NCP API 조사·초기 호출 요약, 목록·메타 현황·대표 메타, 검색 문서·매핑·개발 질문 스냅샷입니다. 공통 규격과 골든셋 5건은 검토용 초안입니다. 파일 구조 검수를 마친 것이 서비스 구현·정답 승인을 완료한 것은 아닙니다. 최신 파일과 검수 범위는 [데이터 안내](../../data/README.md)를 따릅니다.

먼저 세 구간을 각각 시험하고, 검수한 대표 자료를 연결해 아래 흐름을 검증합니다.

```text
메타·매핑 검수 → 검색 후보 → 조회 계획 확인
→ 대표 수치 조회·원표 대조 → 표·그래프·근거 출력
→ 같은 사례를 공통 규격·골든셋으로 연결
```

프레임워크·모델·벡터 저장소·화면은 아직 최종 선택하지 않았습니다. 선택 시 이유·비교 근거·재검토 조건을 [설계 결정 기록](설계결정과_검토사항.md)에 남깁니다. 심층 보고서 등 확장 기능은 핵심 흐름의 구현·검증 이후 검토합니다.

## 6. 현재 자료에서 구현으로 넘어가는 순서

| 순서 | 작업 | 다음 단계로 넘길 결과 | 관련 주차 |
| --- | --- | --- | --- |
| 1 | 전체 메타 구조와 한국은행 공개 자료에서 질문 후보 확인 | 정상 질문 15~20건과 표·항목·분류·기간·주기·그래프의 기대 결과 | 2주 |
| 2 | 구간별 최소 입출력과 고정 입력 준비 | 앞 구간의 실패와 관계없이 다음 구간을 시험할 표·자료·조회 조건 | 2주 |
| 3 | HCX-007·LangGraph 기능 실습 | 구조화 출력·도구 호출·상태 전달의 실행 기록과 적용 판단 | 2주 |
| 4 | 표 찾기·값 추출·그래프 생성을 각각 구현·측정 | 우선 검수한 약 10건의 구간별 결과와 실패 원인 | 2주 |
| 5 | 메타·매핑 검수와 대표 수치 조회 보완 | 실제 코드·원표 대조 근거, 구조별 예외와 수정 규칙 | 2~3주 |
| 6 | 세 구간 연결과 MCP 도구 시험 | 공통 입출력, 도구별 시험, 대표 정상 사례의 연결 결과 | 3~4주 |
| 7 | 대화·실패 흐름과 종합 평가·인계 | 조건 확인·불가 안내, 개선 전후 비교, 실행 안내 | 4~7주 |

1~4는 담당을 나눠 병행할 수 있습니다. 2주차의 15~20건은 개발용 초기 사례이며, 정답 검수 전에는 확정 골든셋으로 부르지 않습니다. 각 구간은 앞 단계 대신 고정한 정답 입력을 넣어 시험합니다. 수치 포함 전체 평가에는 실제 코드·응답·원표 대조가 필요합니다.

세부 담당과 날짜는 노션에서 정합니다. 2주차 실험 결과를 보고 이후 구현 순서를 조정합니다. 역방향 순위 방식은 추가 실험 검토안이며 필수 구현 일정으로 넣지 않았습니다.

## 7. 팀에서 먼저 확인할 내용

- 검색: 대표 문서의 관찰 내용을 실제 메타·코드로 연결할 범위, 매핑 승인 책임.
- 평가: 5건·48건의 중복과 기대 행동, 개발용/최종 비교용 구분, 단계별 승인 기준.
- 공통 규격: 미확정 코드·모호함·부분 실패 표현, 복수 계열과 근거 전달.
- 환경·협업: 팀원 환경 재현과 구조 개편 PR 검토. 기존 원격 이력은 유지하며 병합 전 원격 main과 파일 구성이 다를 수 있습니다.

문서·자료는 구현의 입력이고, 완료 판단은 실제 재현·검수·실행 결과로 합니다.
