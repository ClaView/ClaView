# 설계결정과 검토사항

- 관리: 팀 공동 / 갱신일: 2026-09-23
- 상태: 기존 방향과 추가 검토 항목을 구분한 정리본. 이번 문서 작성이 새로운 팀 합의나 멘토 승인에 해당하지는 않습니다.
- 회의·멘토링 질문과 일정은 노션에서 관리하고, 구현에 영향을 주는 결정과 근거를 이 문서에 연결합니다.

| 의미 확인 | 의미가 달라지는 조건은 확인. 기본값을 적용하면 표시 | [처리 흐름](처리흐름과_연결구조.md) |

## 2. 팀 검토가 필요한 항목

| ID | 결정할 내용 | 확인할 근거·선행 작업 |
| --- | --- | --- |
| D-01 | 공통 입출력의 필드·상태·필수 근거, 복수 계열 표현 | 정상·복수·모호·오류 사례로 초안 대조 후 계약 테스트 작성 |
| D-02 | 되묻기 조건·횟수, 기간 등 기본값, 사용자 응답 후 재검색 조건 | 매핑의 구별 조건과 대화 사례. 통계 의미가 바뀌는 기본값은 자동 적용하지 않음 |
| D-03 | 검색 문서 단위·중복 처리·Top-k·검색 기준선 | 실제 메타 구조, 정답 표·계열 회수율, 입력량·지연 |
| D-04 | 별칭 승인 기준과 모델 생성 후보 검수 범위 | 공식 코드·통계 정의 연결, 유사하지만 다른 개념의 반례. 유사도를 신뢰 확률로 해석하지 않음 |
| D-05 | 단위 추출·기준시점 변경·다주기·결측 처리 | 대표 구조별 실제 조회 검수. 요약 수치만으로 단위 추론·자동 변환을 확정하지 않음 |
| D-06 | 주기 변환·병합·비교 불가·부분 결과 정책 | 계열의 통계 의미, 집계 규칙, 사용자 요청. 공통 기간 절단·보간을 일괄 적용하지 않음 |
| D-07 | 자체 에이전트의 직접 호출 또는 MCP 경유, 외부 클라이언트 시험 범위 | 같은 공통 기능의 재사용, 도구 입출력, 상태 보관·실패 처리 |
| D-08 | 대화·임베딩 모델과 재정렬·RAG Reasoning 채택 | 같은 사례의 품질·비용·지연 비교. 초기 호출 성공만으로 확정하지 않음 |
| D-09 | 골든셋 건수·유형 비율·목표 점수·수치별 허용 오차 | 정답 근거 확보, 다른 팀원의 검수, 기준선 측정 |
| D-10 | 재시도·타임아웃·캐싱·키 사용량 관리 | API별 오류·한도·사용 리소스 조건. 민감정보를 제외한 실행 기록 |
| D-11 | 전체 목록과 특수 형식 자료의 확보·검색 방법 | 일반 표 조사 목록과 전체 범위를 대조. 미확보 자료를 임의로 범위 밖 처리하지 않음 |

담당과 기한은 노션 업무에서 지정하고, 확정 시 관련 문서·테스트·영향 범위를 연결합니다.

## 3. 기존 초안에서 그대로 확정하지 않은 규칙

[노션 공통 규격 초안](https://app.notion.com/p/3e2ae2ab0625802fb892ddcc18c116db)의 본문·JSON 예시를 확인했습니다. 아래는 구현 전에 필요한 수정·검토 제안이며 새 팀 합의가 아닙니다.

| 원문 내용 | 확인한 문제 | 반영 방향·관련 결정 |
| --- | --- | --- |
| 요청 trace는 덮어쓰기 없이 누적, status는 단계마다 갱신 | 현재 상태와 과거 실행 기록의 구분이 필요 | 현재 요약과 단계별 기록 분리, 요청·조건 버전 연결 · D-01 |
| selection 단일 객체 | 두 표 또는 같은 표의 복수 계열을 표현하는 방식 부족 | selections 배열과 계열별 근거 제안 · D-01 |
| 점수차 0.1 미만이면 되묻기, 최고점수 0.4 미만이면 범위 밖 | 검색 방식별 점수 척도가 다르고 낮은 점수는 범위 판정 근거가 아님 | 임계값은 실험 후 검토, 검색 미적중과 범위 밖 분리 · D-02/03 |
| 신규취급액·가계, M2 원계열·말잔, 물가→소비자물가, 최근 36개월을 기본 적용 | 통계 의미·대상·지원 주기를 임의 확정할 위험. API 성공만으로 기본값 적절성을 입증할 수 없음 | 의미 차이는 확인, 기본값은 제안과 실제 적용을 구분. 대상 표의 소관·조회 가능성 확인 · D-02 |
| 빈 배열·err30이면 no_data, 부모 노드는 조회 불가 | 잘못된 코드·조합·응답 해석 문제와 실제 자료 부재를 혼동할 수 있음 | 요청 유효성·기간·응답을 확인하고 판정. 부모 여부만으로 배제하지 않음 · D-01/05 |
| raw는 그대로 보존하지만 예시가 숫자이며 소수자리 정규화 후 완전일치 | 원본 문자열 보존 검사와 숫자 동등성 검사가 섞임 | 원 DT 문자열·해석값·가공값을 분리하고 각각 검사 · D-01/09 |
| 가공값을 한 개의 raw/value 쌍과 transform으로 기록 | 전년동월비 등 여러 입력을 쓰는 계산의 재현 근거 부족 | 입력 관측값 참조 목록과 계산 기록 연결 · D-01/06 |
| api_params 선택, fetched_at을 최신성 근거로 사용 | 조회 조건 없이는 재현이 어렵고 조회 시각은 공표·개정 시각이 아님 | 키 없는 실제 파라미터 보존, 조회·공표·개정 시각 구분 · D-01 |
| 모든 오류를 일시 오류로 안내 | 인증·입력·지속적 파싱 오류에 반복 호출할 수 있음 | 단계·원인·재시도 가능 여부와 사용자 안내 구분 · D-10 |
| 모든 복수 표를 교집합 기간·이중축으로 표시 | 요청 기간이 잘리거나 불필요한 축이 추가될 수 있음 | 요청·주기·단위·통계 의미에 맞는 정합·표시 선택 · D-06 |
| 모든 가공값에 상대오차 1e-6 또는 소수 2자리 일치 적용 | 계산·규모별 오차와 원값 정밀도 차이를 반영하지 못함 | 계산별 허용 오차·반올림 규칙 정의 · D-09 |
| 데이터 계약 v1 및 일부 정책을 확정으로 표기 | 페이지 검토 상태·잔여 확인 항목과 혼재 | 실제 사례 검수·팀 합의 후 계약 버전 부여 · D-01 |
| 드라이런 사례에 체크 표시와 예시 숫자가 있음 | 실제 실행·원표 대조의 증거로 해석될 수 있음 | 논리 검토 예시로만 사용. 예시 숫자를 정답셋에 옮기지 않음 · D-09 |

우선 논의할 것은 D-01의 최소 공통 필드와 D-02의 조건 확인 방식입니다. 구체적 Top-k·점수·기본 기간·오차는 평가 계획 및 실제 사례 검수와 연결해 결정합니다. 검색 문서 JSON은 확보했고 공통 규격에 필드 대응을 추가했습니다. 항목·분류 코드가 null이므로 후보·근거 인계와 실행 가능한 조회 계획 생성을 구분합니다.

검색 자료를 확인한 뒤 D-03/04/09에 다음 검토를 추가합니다.

- 기본 349건과 상세 16건의 동일 표 중복 후보 처리, scope의 적용 문맥과 실제 조회 대상 구분.
- 의미 별칭 14건과 표기 정규화 8건 분리, 관련 개념·조건 보존 규칙 검수.
- 역방향 순위를 주 판정으로 쓰고 직접 유사도를 보조로 쓰자는 팀원 제안 검증. 실험 코드·비교 대상·행별 결과·사람 판정 확보 전에는 채택이나 성능 개선으로 확정하지 않음.
- 개발 질문 48건과 골든셋 초안 5건의 중복·관련 사례 연결, 모호 질문과 오연결 방지의 기대 행동 검수.

이 항목들은 기존 작업을 폐기하는 것이 아니라, 구현 전에 확인할 가정과 정책을 분리한 것입니다. 원값 보존·근거 추적·오류 구분·평가 연결 방향은 공통 규격에 반영했습니다.

## 4. 결정 기록 작성 방식

작은 결정은 아래 양식으로 이 문서에 추가합니다. 선택지와 영향 범위가 커지면 이 폴더에 별도 문서를 만들고 링크합니다.

```md
### D-XX. 결정 제목

- 상태: 제안 / 검토 중 / 합의 / 대체됨
- 작성·변경일:
- 검토 참여자:
- 해결할 문제:
- 비교한 선택지:
- 결정 또는 현재 제안:
- 근거·실험 결과:
- 영향 받는 기능·문서·데이터·테스트:
- 검증 방법·완료 조건:
- 다시 검토할 조건:
- 관련 회의·이슈·PR:
```

합의하지 않은 안은 제안 상태로 남깁니다. 결정을 바꾸면 이전 기록을 지우기보다 대체된 이유와 새 기록을 연결합니다. 문서의 갱신일을 실제 합의일로 사용하지 않습니다.

## 5. 다음 검토 순서

1. 공통 대표 사례를 정하고 입출력 초안에서 빠진 정보를 찾습니다.
2. 필요한 확인 질문·실패 상태·수치 검증 기준을 팀원이 함께 판정합니다.
3. 확정한 최소 규격부터 구현하고 테스트로 확인합니다.
4. 검색·모델·정합 방식을 같은 사례에서 비교합니다.
5. 결정 내용을 명세·샘플·테스트에 반영하고 주간 계획에 연결합니다.
