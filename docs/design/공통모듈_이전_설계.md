# 공통 모듈 이전 설계 (llm · catalog · periods · settings)

- 상태: **제안**(결정 항목 6절은 담당 합의 필요). 이 문서는 코드를 바꾸지 않는다.
- 작성: 2026-10-26, 기준 커밋 `1f5ddfe`
- 대상: 두 개 이상의 모듈이 각자 구현한 공통 기능을 `common/claview_common/`으로 모은다.

## 1. 원칙

1. **두 모듈 이상이 같은 일을 하면 `common`으로, 한 모듈만 쓰면 그 모듈에 둔다.** KOSIS 클라이언트(B만 사용), 각 모듈의 프롬프트·스키마·판단 규칙, A의 해석용 텍스트 처리는 옮기지 않는다.
2. **`common`은 판단하지 않는다.** 파일 읽기, 외부 호출, 형식 변환, 측정만 한다. "어떤 표를 고를지", "어떤 기간이 맞는지" 같은 도메인 결정은 모듈에 남긴다(기간 해석기 예외는 4.3절, 6절 D4).
3. **동작을 바꾸지 않고 옮긴다.** 단계마다 "옮기기 전후 결과가 같다"를 시험으로 보인다. 동작을 바꾸는 통일(재시도 정책, B가 공용 기간 해석기를 쓰는 것)은 별도 단계로 나누고 담당이 결정한다.
4. **모듈의 바깥 인터페이스는 유지한다.** B의 `SelectionModel.complete(...)`, A의 `ModelReply`처럼 모듈 안 코드가 기대하는 모양은 얇은 어댑터로 지킨다. 모듈 내부 코드 변경을 최소화한다.

## 4. 인터페이스

### 4.1 settings (경로·키·모드)

```python
@dataclass(frozen=True)
class Paths:
    root: Path                 # PROJECT_MAIN_DIRECTORY 또는 레포 루트
    data: Path                 # root / "data"
    catalog_file: Path         # data / "catalog" / "search_catalog.json"
    meta_raw_file: Path        # data / "raw" / "boK_meta_raw.jsonl"
    eval_cases: Path           # root / "eval" / "cases"
    runs: Path                 # root / "runs"

class Secret:
    """키 값. repr·str·json에 값이 나오지 않는다. 쓰는 곳에서만 .reveal()."""
    def reveal(self) -> str: ...
    def __bool__(self) -> bool: ...          # 설정 여부만

@dataclass(frozen=True)
class Settings:
    mode: Literal["synthetic", "replay", "live"]
    paths: Paths
    hcx_key: Secret | None
    openai_key: Secret | None
    kosis_key: Secret | None
    hcx_min_interval: float
    def public(self) -> dict: ...            # /info 용: 키 설정 여부만

def load(env: Mapping[str, str] | None = None) -> Settings: ...   # env 주입 가능(시험)
def usable_key(value: str | None) -> str | None: ...              # A의 usable_api_key를 옮김
```

- 환경변수 이름은 지금과 같다: `CLAVIEW_MODE`, `CLOVASTUDIO_API_KEY`, `OPENAI_API_KEY`, `KOSIS_API_KEY`, `HCX_MIN_INTERVAL_SEC`, `PROJECT_MAIN_DIRECTORY`.
- 환경변수를 읽는 곳은 `settings.load()` 하나다. A의 `decompose_provider`·`jev`처럼 모듈 안에서 직접 읽는 곳은 키를 인자로 받게 바꾼다. 가져오는 쪽(스크립트, `claview_a_api`)이 `settings`에서 꺼내 넘긴다.
- A의 `paths.py`, C의 `paths.py`, B service·pipeline의 경로 상수는 `settings.load().paths`를 쓴다. A의 레포 밖 경로(417문항 `CORPUS_DIR`)처럼 A에만 있는 경로는 A `paths.py`에 남긴다.

### 4.2 llm

```python
@dataclass(frozen=True)
class LLMRequest:
    task: str                  # 호출 이름(로그·측정·캐시 키). 예: "B:301:DT_200Y101", "A:INTERP"
    system: str
    payload: dict              # user 메시지로 JSON 직렬화
    schema: dict               # JSON Schema(구조화 출력)
    max_tokens: int
    temperature: float = 0
    seed: int | None = 42

@dataclass(frozen=True)
class Usage:
    tokens_in: int = 0
    tokens_out: int = 0
    reasoning_tokens: int | None = None

@dataclass(frozen=True)
class LLMReply:
    data: dict                 # 파싱한 JSON (스키마 검사는 호출한 모듈이 한다)
    text: str                  # 원문 JSON 문자열(A의 ModelReply.text 호환)
    usage: Usage
    latency_ms: int
    attempts: int
    model: str                 # "HCX-007", "gpt-..." 등
    rate: dict                 # 응답의 속도 제한 헤더(키·인증 정보 제외)

class LLMError(Exception):
    kind: Literal["transient", "auth", "schema", "limit", "other"]
    code: str                  # "hcx_http_429", "hcx_transport_error", "openai_http_400", "schema_not_json" ...
    http_status: int | None
    retry_after: float         # 429 쿨다운(초)
    # 메시지에 키·헤더·URL·응답 원문을 넣지 않는다 (클래스명과 코드만)

@dataclass(frozen=True)
class CallPolicy:
    min_interval: float = 0.0      # 호출 간 최소 간격(초). HCX TPM 보호: 서비스 35
    retries: int = 0               # 재시도 횟수
    retry_on: frozenset = frozenset({"transient"})
    backoff: float = 0.25          # 0.25 * 2**attempt, 최대 2초
    max_retry_after: float = 30.0  # 429 retry-after 상한
    timeout: float = 60.0

class Trace(Protocol):             # B의 Trace와 같은 모양. 없으면 기록하지 않는다
    def add(self, event: str, **fields) -> None: ...

class LLMClient(Protocol):
    name: str
    def complete(self, req: LLMRequest, *, trace: Trace | None = None) -> LLMReply: ...
    def close(self) -> None: ...
```

구현:

| 클래스 | 출처 | 비고 |
|---|---|---|
| `HcxClient(key: Secret, policy: CallPolicy, transport=None)` | A `HcxClient` + B `HcxModel` | httpx. 요청 본문은 두 구현이 같은 필드(`thinking.effort=none`, `responseFormat.json`, `temperature 0`, `seed 42`, `maxCompletionTokens`). A의 HCX용 스키마 변환(`_schema_for_hcx`)은 옵션 `schema_adapter`로 둔다 |
| `OpenAIChatClient` | B `OpenAIModel` | `/v1/chat/completions` |
| `OpenAIResponsesClient` | A `OpenAITransport` | `/v1/responses`, `json_schema strict`, `store: false` |
| `ScriptedClient(replies: dict[task, list])` | B `ScriptedModel` | 재생·시험 |
| `CachingClient(inner)` | A `CachingClient` | 같은 요청의 n번째 결과를 순서대로 재사용(오류 포함) |
| `CountingClient(inner)` | `claview_b_api.service._Counting` | 호출 수·토큰 합계(모듈 API의 meta에 사용) |

모듈 쪽 어댑터(모듈 안 코드는 그대로):

```python
# B: claview_b/models.py — SelectionModel 모양 유지
class HcxModel:
    def __init__(self, client: LLMClient): ...
    def complete(self, task, system, context, schema, max_tokens, trace) -> Json:
        try:
            reply = self.client.complete(LLMRequest(task, system, context, schema, max_tokens), trace=trace)
        except LLMError as e:
            raise StageFailure(e.code, "unresolved" if e.kind == "auth" else "error") from None
        self.last_metrics = {...reply.usage, latency_ms: reply.latency_ms, attempts: reply.attempts}
        return reply.data

# A: claview_a/reused/model.py — ModelReply/ModelError 모양 유지
class HcxClient:
    def complete(self, node, system, payload, schema) -> ModelReply:
        try:
            r = self.client.complete(LLMRequest(node, system, payload, schema, self.max_tokens.get(node, 512)))
        except LLMError as e:
            raise ModelError("transient" if e.kind == "limit" else e.kind, e.code,
                             http_status=e.http_status, retry_after=e.retry_after) from None
        return ModelReply(r.text, r.usage.tokens_in, r.usage.tokens_out)
```

`common/llm`에 두지 않는 것: 각 모듈의 프롬프트, 작업별 스키마, 출력 검사(B `check_output`, A 검증), A의 외부 판정 서비스 `jev_provider`(A만 사용).

### 4.3 periods

```python
Frequency = Literal["Y", "H", "Q", "M"]

class PeriodError(ValueError):
    code: str          # "invalid_period", "invalid_metadata_period", "period_range"

def period_index(period: str, frequency: Frequency) -> int        # 연속 번호 (B period_number = C period_index)
def periods_between(start: str, end: str, frequency: Frequency) -> list[str]   # 양끝 포함, 최대 20000
def period_label(period: str, frequency: Frequency) -> str        # "2024년 1분기" (C)
def normalize_meta_period(value: str, frequency: Frequency) -> str  # "2024 1/4" → "202401" (B normalize_period)
```

- B는 `PeriodError`를 받아 지금처럼 `StageFailure(code)`로 바꾼다. C는 `ValueError`로 그대로 받는다(`PeriodError`가 `ValueError`의 하위라서 기존 `except ValueError`가 그대로 동작).
- 질문에서 기간을 해석하는 일(A `period_core`, B `stages.resolve_*_period`)은 도메인 판단이라 이 파일에 넣지 않는다. 공용 해석기는 결정 D4를 따른다.

### 4.4 catalog

```python
@dataclass(frozen=True)
class RawCatalog:
    documents: dict[str, dict]     # "org:tbl" → search_catalog.json 문서 (path_ids/path_names 분해 포함)
    records: dict[str, dict]       # "org:tbl" → boK_meta_raw.jsonl 한 줄 원형
    catalog_sha256: str
    meta_sha256: str
    def record(self, org_id: str, table_id: str) -> dict          # 없으면 CatalogError("metadata_missing")
    def document(self, org_id: str, table_id: str) -> dict

class CatalogError(ValueError):
    code: str          # "duplicate_catalog_id", "invalid_catalog_path", "duplicate_metadata_id", "metadata_missing"

def load_raw(paths: Paths | None = None) -> RawCatalog         # 프로세스당 한 번(캐시), 읽기 전용
```

- 1단계: 파일 읽기·중복·경로 검사·지문만 공통으로 옮긴다. B `MetadataStore`는 `RawCatalog`를 받아 지금의 `get()` 화면을 만들고, A `load_catalog`는 `RawCatalog`에서 `Catalog`를 만든다. C `composition.metadata_contract`는 `load_raw().record("301", "DT_161Y008")`를 쓴다.
- 2단계(결정 D3): A의 `Catalog`(Item·Axis·Period·Table, 영문명·부모·깊이 보존)를 공통 모델 `catalog/model.py`로 올리고, B의 `get()` 화면을 그 위에서 만든다. 두 모듈이 같은 축·값 해석을 쓰게 되지만, B 화면의 세부 규칙(이름 없는 축 처리 등)이 바뀔 수 있어 B 골든 비교가 필요하다.

## 6. 결정 항목

### D1. A 패키지 규칙 완화 (필수, A 담당)

지금 `claview_a`는 표준 라이브러리와 langgraph만 import할 수 있고, 이 규칙을 `modules/a/tests/test_boundary.py`(정적 검사)와 `claview_a._guard`(실행 중 가드)가 강제한다. 이대로면 A는 `common`의 어떤 기능도 쓸 수 없다.

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **(가) 허용 목록에 추가 (추천)** | `claview_common.{settings, periods, catalog, llm}`과 `httpx`를 허용. `test_boundary`의 `ALLOWED_THIRD_PARTY`·`_check_absolute`, `_guard`의 `FORBIDDEN_PACKAGES`/`FORBIDDEN_DIRS`(common 하위 4개 폴더 예외)를 고친다. `claview_common.api`·`testing`은 계속 금지 | 공통화의 효과를 A도 얻는다. 규칙의 취지(웹·다른 모듈·옛 코드 차단)는 유지 | A 가드·경계 시험 수정 필요. A가 공통 패키지 변경의 영향을 받는다(CODEOWNERS 리뷰로 관리) |
| (나) 주입만 허용 | A 본체는 그대로 두고, `claview_a_api`가 공통 클라이언트를 만들어 A에 넘긴다. A는 프로토콜(덕 타이핑)로만 받는다 | A 규칙 무변경 | A 안의 HCX·OpenAI·카탈로그 구현을 지울 수 없다. 중복이 남는다 |
| (다) 유지 | A는 공통화에서 제외 | 변경 없음 | LLM·카탈로그 중복이 계속된다. 정책(재시도·간격)이 모듈마다 달라진다 |

결정에 필요한 확인: A 담당이 `_guard`를 유지하려는 이유(옛 A 코드 혼입 방지·네트워크 차단)가 (가)에서도 지켜지는지. (가)는 옛 `claview` 패키지 차단과 네트워크 차단을 그대로 둔다.

### D2. LLM 호출 정책 통일 (A·B 담당)

| 항목 | A 지금 | B 지금 | 제안 |
|---|---|---|---|
| 전송 | urllib | httpx | httpx (D1 (가) 전제) |
| 재시도 | 없음(호출자가 판단) | 전송 오류·5xx·429를 기본 2회(서비스 경로는 0회), 지수 대기(최대 2초) | `CallPolicy.retries`·`retry_on`으로 호출하는 쪽이 정한다. 기본값은 각 모듈의 현재 값 유지 |
| 429 | `retry-after`(최대 30초)를 다음 호출 전 쿨다운으로 두고 바로 오류 | 속도 제한 헤더(없으면 30·60초…)만큼 기다려 재시도, 60초 넘으면 `hcx_http_429` | 공통 구현은 대기 시간 계산을 한 곳에 두고 `CallPolicy.max_retry_after`로 상한. 남은 재시도가 없으면 `LLMError(kind="limit")` |
| 오류 표현 | `ModelError` 4분류 | `StageFailure` 코드 | 공통은 `LLMError(kind, code)`. 모듈 어댑터가 기존 표현으로 변환 |
| 측정 | 토큰 수 | 지연·시도·토큰·속도 제한 헤더 | `LLMReply`에 모두 담는다 |

### D3. 카탈로그 공통 모델 범위 (A·B 담당)

1단계(파일 읽기·검사·지문 공통화)는 동작 변화가 없어 바로 진행한다. 2단계(A의 `Catalog`를 공통 모델로, B 화면을 그 위에서)는 B의 표 화면이 바뀔 수 있으므로 B 골든 비교 후 결정한다.

### D4. 공용 기간 해석기 (B 담당 주관, A 협의)

A의 `period_core`(0.2.0)를 `common/claview_common/period_resolver/`로 옮기고, B의 `stages.resolve_*_period`를 이것으로 바꿀지 결정한다. B 쪽 결과가 바뀌는 변경이라, B 기간 골든(`eval/cases/b/period`)과 골든 22의 전후 비교를 PR에 붙인다. 옮기더라도 정책 파일(`period_policy.json`)과 버전은 그대로 둔다.

## 8. 하지 않는 것

- 각 모듈의 프롬프트·작업 스키마·출력 검사, A의 해석용 텍스트 처리와 사전, B의 KOSIS 클라이언트·조회 정규화, C의 차트 정책은 옮기지 않는다.
- 이전 단계에서 재시도 횟수·호출 간격·오류 메시지 문구를 바꾸지 않는다(바꾸려면 D2 결정 후 별도 PR).
- 실제 HCX·OpenAI·KOSIS 호출로 검증하지 않는다. 가짜 전송·재생으로 동일성을 보이고, 실제 호출은 별도 승인 뒤에 한다.
