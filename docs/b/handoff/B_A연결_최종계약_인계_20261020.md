## 3. 공유 기간 해석기

### 3.1 호출 계약 (현재 코드 그대로)

```python
def resolve_period_for_table(
    conditions: list[Json],          # 필수. 조건 dict 목록 {id, kind, quote, value, attrs}
    table_meta: Json,                # 필수. 저장 메타(아래)
    as_of: str | None,               # 필수 위치 인자, None 허용. "YYYY-MM-DD"
    calc_hints: list | None = None,  # 선택. [{quote, kind: change|rate}]
    inferred: list | None = None,    # 선택. [{kind: "frequency", value, from_condition_id, rule}]
) -> Json
```

- 동기 함수. 표준 라이브러리만 import(`period_resolver.py:17-19`). 파일 읽기·전역 캐시·환경변수·모델·네트워크 없음(코드 확인). 입력을 바꾸지 않음(**시험 확인** `test_period_resolver.py:342` `test_inputs_are_not_changed`).
- 읽는 조건: `kind`가 `period`·`frequency`·`calc`인 것만(`_of_kind` `:166`). 그 밖의 종류는 무시(**시험 확인** `:349`). dict가 아닌 항목은 버림(`:409`).
- `table_meta` 필수 필드: `periods = {주기: {"start", "end"}}`, 주기는 `Y`·`H`·`Q`·`M`, 기간 표기는 표 형식(`"2024"`, `"202403"`). B `MetadataStore.get`(`src/claview/metadata.py:101`)의 출력이 이 모양이다. 다른 필드는 읽지 않는다.
- 반환(정상): `{status: "ok", issue: None, frequency, applied: {frequency, start, end}, source, assumptions, slots: {frequency: {value, source, confirmed, applied, rule, alternatives}, period: {value, source, confirmed, applied, rule}}, relative, show_period, notice, alternatives: [{frequency, applied}]}` (`:438-466`).
- 반환(실패, 예외 아님): `{status: "unresolved" | "table_unsuitable", issue: {code, detail}, frequency, applied: None, ...}` (`_failed` `:372`). 현재 나오는 `code`/`detail` 전체:

| code | detail | 위치 |
|---|---|---|
| table_unsuitable | table_without_periods, frequency_not_in_table, period_unit_not_in_table | `:414`, `:217`, `:228` |
| conditions_incomplete | frequency_value, several_frequencies, period_unresolved_by_interpretation, period_expression, period_form, recent_amount_or_unit, recent_unit_coarser_than_frequency, relative_sub_unit_frequency, half_value, sub_value, malformed_condition | `:210`, `:214`, `:135`, `:143`/`:150`, `:160`, `_recent_count`, `_expr_span`, `_months_of`, `:423` |
| invalid_period | start_after_end | `:156` |
| metadata_refresh_required | outside_coverage, end_after_latest_period, start_before_first_period | `:272`, `:277`, `:315` |

- 예외가 나는 경우(정상 반환과 구분): `table_meta`가 dict가 아니면 `:411`에서 `AttributeError`(try 밖). 그 밖의 조건 내용 오류는 `:422`에서 잡아 `conditions_incomplete/malformed_condition`으로 돌려준다. `as_of`가 형식이 틀리면 `_notice`에서 `ValueError`가 나고 같은 `malformed_condition`으로 바뀐다(사유가 오해를 부를 수 있음, **구현됨·미검증**).
- 기준일·끝점: 기간 계산은 표의 최신 수록 시점(앵커 `periods[f].end`) 기준이고 `as_of`는 계산에 쓰지 않는다. `as_of`는 지연 안내(`notice`)에만 쓰인다(`_notice` `:340`). 시작·끝 모두 포함 구간(index 기반 `first..last`).
- **공유 배포·의존 경계 미확정**: 모듈은 이 저장소의 `src/claview/b/period_resolver.py`. A 작업 저장소(`src/`)에도 `claview` 패키지가 있어(확인), B를 같은 이름으로 설치하거나 `sys.path`를 바꾸면 A의 옛 `claview`와 충돌한다. 지금 가능한 것은 B 체크아웃 안에서의 호출뿐이다. 배포 방식(별도 패키지 이름, 복사본 판본 고정 등)은 정해야 한다(11절 1번).

### 3.2 주기 결정 순서 (현재 `_decide_frequency` `:203`)

1. 명시 주기(`kind: frequency`): 둘 이상 다르면 `conditions_incomplete/several_frequencies`, 표에 없으면 `table_unsuitable/frequency_not_in_table`, 있으면 `source question, rule question_word, confirmed true`.
2. 기간 단위 주기: `inferred`가 **None(칸 없음)** 이면 B가 기간 조건의 단위를 직접 읽고(`_period_units` `:175`, 최근 N개월·분기·반기, 시작·끝 표현의 하위 단위), **목록이면** 그 목록의 `kind: frequency` 값만 쓴다(`_inferred_units` `:189`). 여러 단위면 가장 세밀한 것 하나를 고르고(`:226`), **그 주기가 표에 없으면 `table_unsuitable/period_unit_not_in_table`**(`:227-228`). 쓰면 `source question, rule period_unit, confirmed false`와 가정 기록(`:425-426`).
3. 표 주기가 하나: `source catalog, rule table_single, confirmed true`.
4. 여럿: 가장 긴 주기(Y>H>Q>M, `:23`) `source default, rule longest_frequency, confirmed false`, 가정 기록, 나머지 주기의 기간을 `alternatives`로 계산(`:429-436`).

합의 대조:

| 합의 | 현재 | 상태 |
|---|---|---|
| 1. 명시 주기 없음과 추론 주기 없음을 구분 | 서로 다른 detail(`frequency_not_in_table` / `period_unit_not_in_table`)로 구분은 됨 | 구현됨 |
| 2. 추론 힌트만으로 표 부적합 판정 금지 | **반대**: 추론 주기가 표에 없으면 table_unsuitable(`:227-228`). 시험도 이 반대 동작을 고정함(`test_period_resolver.py:118`) | 구현 전(시험 기대값 변경 필요 → 11절 2번) |
| 3. 혼합 단위 → 표가 지원하는 가장 세밀한 주기, `period_unit_finest` | 현재는 단위 중 가장 세밀한 것을 먼저 고르고 표 지원 여부를 그 뒤에 봄. rule은 `period_unit` | 구현 전 |
| 4. 혼합 단위 주기는 명시 조건·반증 근거 아님 | `confirmed false`, 가정 기록. 반증 쓰임새는 B에 없음 | 일부(가정 기록만) |
| 5. `inferred: []` = 일관 단일 단위 없음/기간 조건 없음 | 현재 `[]`이면 단위 추론을 하지 않고 단일/가장 긴 주기로 감 | 일부 |
| 6. 칸 없음 = 옛 A | 칸 없음(None)이면 B가 단위를 직접 읽음 | 구현됨 |
| 7. 빈 배열·칸 부재 모두 원 조건 재해석 가능, 결과는 가정으로만 | 칸 부재는 재해석+가정, 빈 배열은 재해석 안 함 | 일부(빈 배열 처리 다름) |

추가 사실: 어댑터 `to_b_request`는 `hints.inferred`를 **채우지 않는다**(`adapter_v3.py:86-112`). 따라서 현재 A→B 경로에서는 언제나 "칸 없음 = B가 직접 읽음"이다.

## 4. 공용 기간 정책 파일

**구현 전.** 현재는 코드 상수: `period_resolver.py:26` `DEFAULT_RECENT_YEARS = {"Y": 10, "H": 5, "Q": 5, "M": 3}`, 주기 정렬 `:23` `FREQUENCY_ORDER = ("Y","H","Q","M")`(긴 것부터), 연당 칸 수 `:24`. 값은 합의 표(연 10/10, 반기 5/10, 분기 5/20, 월 3/36)와 같다.

- 최근 N년 계산: 앵커 포함 거꾸로 N×(연당 칸 수)개(`:298-300`). 수록 범위가 더 짧으면 수록 시작으로 자르고 `notice`(가정 기간은 '부드러운' 기간으로 취급, `:269`).
- 기본값 적용 기록: `source: "default"`, `assumptions[{dimension: "period", value: applied, rule: "recent_years:M=3"}]`(`:322-326`, `:300`).
- 정책 누락·잘못된 값·판본 불일치 처리: 정책 파일이 없으므로 **구현 전**.
- A·B가 같은 판본을 쓰게 하는 방법: 미정(11절 1번). **A가 이 숫자를 별도 상수로 복사하지 말 것.** 정책 파일이 생기기 전까지 A는 B 해석기 반환의 `assumptions`/`rule`을 읽는 쪽이 안전하다.

## 5. 묶음 공통 기준점 계약

**구현 전.** `context = {anchor, anchor_source, bundle_id}` 인자는 해석기·실행기 어디에도 없다. 현재 앵커는 표마다 그 표의 최신 수록 시점(`period_resolver.py:292`)이고, 결과에 앵커·묶음 ID를 남기는 칸도 없다.

- 현재 여러 표 scope: 표마다 따로 해석하고, 표마다 기간이 다르면 `notices`에 `{kind: period, code: period_differs_by_table, by_table}`(`run.py:63-66`). **구현됨·미검증**(여러 표·서로 다른 기간 시험 없음).
- 동시점 비교(상대·기본 기간): 합의대로라면 A가 선택 묶음 구성표의 가장 늦은 공통 수록 시점을 `bundle_common`으로 넘겨야 한다. B는 받지 못한다(구현 전).
- 과거·현재 판 연결(명시 기간): **현재 동작은 막힐 수 있다**. 명시 기간이 한 판의 수록 범위를 넘으면 그 표의 계획이 `metadata_refresh_required`가 되고(`:275-277`), B context가 그 표에서 실패하므로(`stages.py:1358-1366`, `_context_from_plan`이 `plan["status"] != "ok"`면 StageFailure) scope 전체가 unresolved가 된다. 시험 없음. 합의(원 요청 구간 보존, 공통 시점 부재로 막지 않음)와 반대.
- 캐시: 해석기에는 캐시가 없다. B `MetadataStore.get`이 표 메타만 `org:table` 키로 캐시한다(`metadata.py:101-104`). 기준점이 들어와도 메타 캐시와 충돌하지 않는다(추정, 구현 전).

### 6.3 조건 보조 칸 병합

**구현 전.** 합의 위치 `analysis.decomposition.condition_fields[condition_id] = {source, confirmed, applied, period_diagnosis}`를 어댑터가 읽지 않는다. 그래서 현재는:
- 조건 ID 병합·충돌 규칙·`source`/`confirmed` 보존: 없음.
- A 예정 값이 `applied`에 들어가는 일: 구조상 생기지 않는다. B는 A의 `applied`를 읽지 않고, `applied`는 해석기 반환 `slots.*.applied`에서만 만든다(`period_resolver.py:450`, `:458`). 이를 확인하는 시험은 없다.
- 옛 A 입력(보조 칸 없음): 지금 동작 그대로.
- 누락·중복·알 수 없는 조건 ID: 요구가 참조한 ID가 `analysis.conditions`에 없으면 조용히 빠진다(`adapter_v3.py:49`, 이전 검수 선택 지적, 미반영). `condition_fields`에만 있는 ID를 계약 오류로 보는 규칙은 구현 전.
- 대안 해석의 보조 칸이 섞이는 문제: 대안을 읽지 않으므로 지금은 없음.

### 6.4 가정과 실제 적용 차이

**합의한 공용 가정 스키마는 구현 전.** 현재 B 결과의 가정은 요구별 `assumptions[{dimension: "period" | "frequency", value, rule}]`(`contract.py:129`)뿐이고, `assumption_id`·`requirement_ids`·`refs`·`reason_code`·`adopted`·`source`·`confirmed`·`stage`·`supersedes`가 없다. 계약 검사는 `source default`인 기간·주기가 assumptions에 있는지 확인한다(`contract.py:631` `_check_assumed`). A 계획과 다르게 적용했을 때의 사유·범위 기록도 없다. 필요한 입력: A 가정 씨앗(ID·참조), A 예정 기간 계획, 두 값이 다를 때의 사유 코드 목록.

## 7. 수기 계약 예시

모두 **수기 계약 예시**다(이번에 실행하지 않음). 공통 표 메타 `T = {"periods": {"Y": {"start": "2000", "end": "2025"}, "Q": {"start": "200001", "end": "202602"}, "M": {"start": "200001", "end": "202608"}}}`, `as_of = "2026-10-20"`. 조건은 `{id, kind, quote, value, attrs}` 모양이고 아래에서는 필요한 칸만 적는다. 반환은 해석기 출력 중 주요 칸만 적는다.

**예시 1 (번호 1) 명시 주기·명시 기간**
입력 `[{kind: frequency, value: "Q"}, {kind: period, attrs: {form: range, start_expr: {year: "2020"}, end_expr: {year: "2023"}, relative: false, extract_status: explicit}}]`, 메타 T.
반환 `{status: ok, applied: {frequency: Q, start: 202001, end: 202304}, slots.frequency: {source: question, rule: question_word, confirmed: true}, assumptions: []}`. 시험 `test_period_resolver.py:76`.

**예시 2 (번호 2) 기간 미지정 기본값**
입력 `[{kind: frequency, value: f}]`. 반환 `applied`: Y `2016~2025`, Q `202103~202602`, M `202309~202608`. 반기 표 `{"H": {"start": "201001", "end": "202601"}}`이면 `202102~202601`(코드상 계산, 시험 없음). `source: default`, `assumptions[{dimension: period, value: applied, rule: "recent_years:Q=5"}]`, Q·M은 as_of보다 표가 늦어 `notice` 있음. 시험 `:164`, `:176`.

**예시 3 (번호 3) 일부만 수록**
(a) 상대: `[{freq Y}, {period recent amount 40 unit year relative true}]` → `applied 2000~2025`, `notice.code: period_requires_confirmation`(빠진 구간 기록 없음). 시험 `:241`.
(b) 명시: `[{freq Y}, {period range 1990~2001}]` → 현재 `{status: unresolved, issue: {code: metadata_refresh_required, detail: start_before_first_period}}`. **합의는 2000~2001만 조회 + 빠진 1990~1999 보존.** 시험 `:236`(현재 동작 고정).

**예시 4 (번호 4) 완전 비겹침**
메타 `{"M": {"start": "202601", "end": "202608"}}`, `[{period point alias 작년 relative true}]` → 현재 `metadata_refresh_required/outside_coverage`. **합의는 `no_data_in_range` + 수록 범위.** 시험 `:382`.

**예시 5 (번호 5) 명시 주기가 표에 없음**
`[{freq H}]`, 메타 T → `{status: table_unsuitable, issue: {code: table_unsuitable, detail: frequency_not_in_table}}`. 합의와 같음. 시험 `:91`. 실행기에서는 모델 호출 없이 scope가 table_unsuitable(`test_run.py:145`).

**예시 6 (번호 6) 추론 힌트 주기만 표에 없음**
`[{period point start_expr {year 2024, sub_unit H, sub_value 상}}]`, 메타 T(반기 없음) → 현재 `table_unsuitable/period_unit_not_in_table`. **합의는 부적합 아님: 단일/가장 긴 주기 + 대안, 가정.** 시험 `:118`(현재 동작 고정).

**예시 7 (번호 7) 혼합 단위, 빈 힌트와 칸 부재**
`[{period range start_expr {year 2024, sub_unit Q, sub_value 3}, end_expr {year 2025, sub_unit M, sub_value 5}}]`, 메타 T.
- 칸 부재(`inferred=None`): 단위 [Q, M] → 가장 세밀한 M, 표에 있음 → `frequency M, rule period_unit, confirmed false`, 가정 기록. 기간 `202407~202505`. (코드 경로 기준, 이 조합 시험 없음)
- 빈 힌트(`inferred=[]`): 단위 추론 안 함 → 가장 긴 Y, `rule longest_frequency`, 기간 `2024~2025`. 시험 `:427`(단일 단위로 확인).
- **합의 차이**: rule 이름 `period_unit_finest`, 빈 배열에서도 원 조건 재해석 허용(가정으로만), 가장 세밀한 단위가 표에 없으면 표가 지원하는 것 중 가장 세밀한 것.

**예시 8 (번호 8) unsupported와 malformed**
- `attrs.extract_status: "unresolved"` → 현재 `conditions_incomplete/period_unresolved_by_interpretation`, 최근 N년으로 대체 안 함. 합의 `period_unsupported`. 시험 `:314`.
- `attrs: [1]`(객체 아님) → 빈 attrs로 읽혀 같은 `period_unresolved_by_interpretation`. 합의는 계약 오류. 시험 `:415`(예외 없음만 확인).

**예시 9 (번호 9) 두 표 상대 기간에 공통 기준점**
구현 전. 현재: 표 A(M, 끝 202608)와 표 B(M, 끝 202606)에 "최근 1년" → 표 A `202509~202608`, 표 B `202507~202606`, scope `notices`에 `period_differs_by_table`. 합의대로면 A가 `context {anchor: "202606", anchor_source: bundle_common, bundle_id}`를 넘겨 둘 다 `202507~202606`. 시험 없음.

**예시 10 (번호 10) 동시점 묶음에 공통 수록 시점 없음**
구현 전. 합의: A가 동시점 아님 표시 + 표마다 최신(`table_latest`). 현재는 언제나 표마다 최신이고 표시 칸이 없음. 시험 없음.

**예시 11 (번호 11) 과거·현재 판으로 명시 기간 덮기**
구현 전·현재 반대. 옛 판 `{"Y": {"start": "2000", "end": "2015"}}`, 새 판 `{"Y": {"start": "2010", "end": "2025"}}`, "2005~2024년". 현재 해석기는 표마다 원 요청 전체를 대조하므로 두 표 모두 명시 범위 밖으로 `metadata_refresh_required` → scope 실패. 합의: 원 요청 구간 보존, A의 요청 칸 배정대로 표마다 담당 구간 조회. 시험 없음.

**예시 12 (번호 12) 세 표 묶음 + 첫 대안·참고 후보**
