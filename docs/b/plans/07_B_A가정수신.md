# 07 B: A 공개 가정 수신·반환과 supersedes 검사 (2026-10-21, 사용자 전달문 "완료 2 — B 담당 구현")

범위: 이 저장소만. 추가 모델·조회 호출 없음. B 그래프·기간 정책·옛 입력 경로는 바꾸지 않는다. 기존 구조·기간 계약 유지.

## 1. 수신 계약

- `BRequest.a_assumptions`(선택): `{version: "a-assumptions/2026-10-21.1", items: [...]}`. 없으면 구형 입력.
- 항목: 정확히 `{assumption_id, stage, requirement_ids, requirement_keys, refs, reason_code, adopted, source, confirmed}`. `requirement_keys` 원소는 `{reading_id, requirement_id}`, `refs`는 `{segment_ids, mention_ids, condition_ids}`, `adopted`는 `{value, interpretation}` — 모두 필수 칸만.
- 값: ID·`reason_code`·`interpretation`은 비어 있지 않은 문자열, 참조 목록은 중복 없는 문자열 목록, `value`는 JSON 값, `source` ∈ question·user·catalog·default, `stage` = "A", `confirmed` bool. `requirement_ids` 집합 = `requirement_keys`의 `requirement_id` 집합. `assumption_id`는 봉투 안에서 유일.
- 검사 함수 `contract.check_a_assumptions(envelope, requirement_ids=None)`: 모양·판본·유일성. `requirement_ids`를 주면(어댑터가 가진 A 요구 목록) 항목의 요구가 그 안에 있어야 한다(scope_id가 아니라 A 요구 ID로 대조).
- 미지원 판본·잘못된 모양·없는 요구는 요청 수준 `input_contract_error`로 모든 scope가 모델·조회 전에 끝난다. 실행기도 봉투 모양을 다시 검사한다(어댑터 밖 요청 대비).

## 2. 반환

- `run_b_request` 결과 최상위 `a_assumptions`에 받은 봉투를 그대로(깊은 복사) 돌려준다. stage B 목록(`shared_assumptions`)에 섞거나 ID를 다시 만들지 않는다. 봉투가 없으면 결과에 칸을 두지 않는다.
- `shared_assumptions[].supersedes`: 단일 A `assumption_id` 또는 null. B는 대체 근거(같은 요구·같은 조건을 대신한다는 판정 근거)를 가진 정보가 없어 연결하지 않는다(봉투가 있으면 `supersedes: null`을 명시). 검사 함수 `contract.check_b_result(result, request)`: 봉투 왕복 동일성, `supersedes`가 문자열이면 요청 봉투에 있는 ID이고 그 항목의 요구가 그 scope의 요구(`requirement_key.requirement_id`)여야 한다.
