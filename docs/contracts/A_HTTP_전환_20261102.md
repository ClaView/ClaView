# 새 A HTTP 전환 (2026-11-02)

기본 A HTTP는 새 A의 표 선택·조건 검사·되묻기·답 적용을 실행하고 `AView`를 반환한다. 상태는 서버에 저장하며, 클라이언트는 세션 ID와 질문별 답만 보낸다. B·KOSIS·C를 실행하거나 새 B 전달 계약을 도입하는 변경은 아니다.

## 경로와 하위 호환

| 경로 | 입력·동작 | 결과 |
|---|---|---|
| `POST /a/select` | 새 질문을 시작하고 세션 저장 | `AHTTPResult` |
| `POST /a/answer` | 저장 세션에 질문별 답 적용 | `AHTTPResult` |
| `GET /a/records/{session_id}` | 저장한 최신 A 결과 읽기. 모델 호출 없음 | `AHTTPResult` |
| `POST /a/legacy/select` | 기존 `{query, as_of}` | 기존 `AResult` |
| `POST /a/legacy/answer` | 기존 `{state, option_id}` | 기존 `AResult` |

새 POST 요청의 `contract_version`은 **필수**이고 값은 `a-http/2026-11-02.1`이다. 판이 없거나 다르면 422로 거절한다. 기존 클라이언트가 같은 URL에서 다른 응답을 조용히 받지 않도록 한 경계다. 새 요청은 정의하지 않은 추가 필드도 거절한다.

옛 호출자는 `/a/legacy/*`로 옮기거나 새 형식을 사용한다. 골든 22 생성기의 `common/fixtures/a_request`·`a_result`는 기존 A 형식이다. A HTTP의 판, A 모델 출력 계약 판, AView 판은 서로 다른 계약이다.

## 새 질문

```json
{
  "contract_version": "a-http/2026-11-02.1",
  "query": "2024년 M2를 월별로 보여줘",
  "as_of": "2026-10-29"
}
```

- `query`: 빈 공백이 아닌 1~2,000자 문자열.
- `as_of`: 선택 값. 지정하면 유효한 `YYYY-MM-DD`여야 한다. 지정하지 않으면 요청 시작 시점의 서울 날짜를 한 번 확정한다. 답변·기록 조회에서 기준일을 다시 계산하지 않는다.
- 실행 모드, 판단기, 기록 경로, 승인 기록, checkpoint, 모델 원응답은 요청에 넣지 않는다.

위 기준일은 고정 비교용 예시다. 서비스의 보통 사용에서는 생략하여 실행 당일을 사용한다.

## 응답과 답 적용

응답의 최상위 필드는 `contract_version`, `view`, `execution_mode`, `meta`이다.

- `view`는 공용 `AView`이며 `session`, `status`, `statistics`, `questions`, `handoff` 등을 담는다.
- `view.session.session_id`를 저장하고, 되묻기가 있으면 `view.questions`를 그대로 표시한다.
- 답에는 응답의 `question_id`, `question_version`을 사용한다. 선택형은 실제 `option_id`, 텍스트 입력형은 `text`를 보낸다. 두 칸 중 하나만 허용한다.
- `execution_mode`는 이 A 실행의 `synthetic` 또는 `live` 출처다. 저장 기록을 읽거나 답을 적용하는 요청 자체가 모델을 새로 불렀다는 뜻은 아니다.
- 서버 checkpoint·원장·키·내부 파일 경로는 응답에 포함하지 않는다.

```json
{
  "contract_version": "a-http/2026-11-02.1",
  "session_id": "응답의 세션 ID",
  "replies": [
    {
      "question_id": "응답의 질문 ID",
      "question_version": 0,
      "option_id": "응답의 선택지 ID"
    }
  ]
}
```

위 ID는 설명용 자리표시자다. 실제 세션 ID는 서버가 돌려준 8~64자리 소문자 16진 문자열을 사용한다. `question_version`도 예시의 0을 고정하지 않고 해당 질문의 값을 복사한다. 텍스트 답이면 `option_id` 대신 `text`를 보낸다. 한 번의 요청은 1~100개의 답을 받는다.

답은 저장된 최신 세션에 적용한다. 같은 답의 중복 제출이나 오래된 질문 버전, 다른 세션의 선택지를 거절하며, 사용자 답 적용 중에는 모델을 추가 호출하지 않는다. 선택지 사용 가능 여부와 부분 답 보존은 A의 기존 정책을 따른다.

기록 확인은 `GET /a/records/{실제 session_id}`로 한다. 응답의 `view.status`가 ready여도 A 조건 확정·송신 준비 상태이며, KOSIS 조회나 차트 완료를 뜻하지 않는다.

## 실행 모드·기록·승인

- 서버의 `CLAVIEW_MODE` 기본값은 `synthetic`이다. 합성 판단은 배선·상태·답 적용 확인용이며 실제 모델 품질 결과가 아니다.
- `live`는 기존 A 승인 게이트를 사용한다. 승인 문항·코드/설정·유효시간·질문별 및 전체 호출 상한 등의 기존 검증을 생략하지 않는다. 승인 없이 자동으로 합성 실행이나 옛 A로 바꾸지 않는다.
- `replay`는 저장 응답 공급 경로를 구현하지 않은 상태이므로 `replay_source_required`로 거절한다. 이번 HTTP에는 임의 저장 응답을 주입하는 API가 없다. `GET /a/records`는 기존 결과 읽기이며 모델 응답 재검사 실행기와 다르다.
- `CLAVIEW_A_RUN_ROOT`는 서버의 기록 저장 위치다. 지정하지 않으면 저장소의 `runs/a_http`를 사용한다. 실행 중 요청이 경로를 바꾸거나 새로운 원장을 만드는 기능은 없다.
- live 승인은 이 기록 위치와 기존 실호출 원장 위치에 묶인다. HTTP 설정 때문에 승인 기록의 경로나 원장을 초기화하거나 재사용하지 않는다.
- 프로세스를 다시 시작해도 같은 기록 경로를 사용하면 세션을 읽는다. 컨테이너 교체 뒤에도 기록을 유지하려면 배포 환경에서 해당 위치를 영속 저장소로 연결해야 한다. 이번 전환이 Docker 볼륨 구성을 자동으로 바꾸지는 않는다.
- 이 모듈은 A만 실행한다. B 모델·KOSIS 비용이나 C 결과를 포함한 승인이 아니다.

## 오류의 의미

| HTTP 상태 | 의미 |
|---|---|
| 422 | 필수 판 누락·불일치, 요청 모양/날짜/답 필드 오류 |
| 400 | 세션과 맞지 않는 답 등 적용할 수 없는 입력 |
| 404 | 해당 기록 없음 |
| 409 | 오래된·중복 답, 같은 작업 중복 실행 등 상태 충돌 |
| 410 | 현재 코드와 호환되지 않는 저장 기록 |
| 403 | 승인·호출 상한, 이미 사용한 질문(`question_budget_used`)에서 거절 |
| 503 | live 실행 불가 또는 replay 공급원 없음 |

오류의 세부 코드는 서버가 반환한 값을 사용한다. 422를 받은 옛 클라이언트가 legacy 호출을 자동 재시도하도록 만들지 않는다. 어떤 A 판을 실행할지는 호출자가 명시적으로 선택한다.

## 이번 전환 밖의 연결

- 프론트엔드는 계속 파이프라인 API를 호출하고, 파이프라인은 A Python service를 직접 호출한다. 모듈 A HTTP로 네트워크 요청하는 구조로 바꾸지 않는다.
- 현재 main 화면의 live 게이트는 여전히 별도 후속 연결 범위다. 모듈 A HTTP에 승인을 연결했다고 화면 live도 켜지는 것은 아니다.
- B·C·공용 `BRequest`·최소 C2 기간 수신부·basis/evidence 추가 전달 계약은 이번에 변경하지 않는다.
- 기존 `claview` 명령과 골든 22 통합 평가의 legacy 경로도 유지한다.

구현 위치는 `common/claview_common/contracts/a_http.py`, `modules/a/claview_a_api/http.py`, `api.py`다. HTTP 판 상수는 공용 `versions.py`의 `A_HTTP_VERSION`이며 기존 AResult·B·C 판은 바꾸지 않는다. `common/fixtures/a_http_request`·`a_http_result`는 기존 합성 AView를 감싼 예시이고 실제 모델 응답이 아니다. 검증은 합성 판단·가짜 전송·시험용 기록 폴더로 수행하고, 실제 모델 결과와 구분해 PR에 보고한다.
