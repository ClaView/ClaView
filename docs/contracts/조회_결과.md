# 조회 결과 (data_result)

코드: `modules/b/claview_b/fetch.py`(`fetch_data`, `normalize_rows`, `build_api_request`, `KosisClient`). C가 받을 입력이다.

## 봉투

```text
{
  "stage": "fetch",
  "status": "ok" | "partial" | "no_data" | <실패 상태>,
  "result": {"series": [...], "period_notices": [...]} | None,   # period_notices는 b_result에 있을 때만, 실패 시 아래 참고
  "issues": [{"code", "message", "field", "series_id", "retryable"}],
  "trace_ref": <실행 ID>
}
```

- `ok`: 모든 계열에 문제 없음. `partial`: 결측값(`missing_value`)·값 해석 실패(`value_parse_error`)·결측 기간(`missing_periods`) 등 문제가 하나라도 있음. 응답 행이 있으면 값이 모두 결측이어도 `points`가 생기므로 `partial`이다. `no_data`: 모든 계열의 `points`가 비었음(응답 행이 하나도 없음).
- 실패(검증·전송·응답 오류)는 실패 상태로 돌려준다. 이미 모은 계열이 있으면 `result = {"series": [...]}`, 첫 계열을 모으기 전에 실패하면 `result = None`이다(`result`를 쓰기 전에 확인한다).

## series

```text
{
  "series_id", "selection": <b_result의 계열 그대로>,
  "frequency": "Y"|"H"|"Q"|"M",
  "unit": <응답 단위(NFKC로 맞춘 값) | 선택 단위>,
  "points": [{"period", "raw_value", "value": <10진 문자열 | None>, "value_status": "observed"|"missing"|"parse_error"}],
  "coverage": {"expected", "returned", "missing_periods": [...]},
  "provenance": {"params": <KOSIS 요청 파라미터(키 제외)>, "metadata_snapshot", "fetched_at", "raw_response_ref"}
}
```

- 응답 행의 기관·표·항목·분류 코드가 선택과 다르면 `unexpected_response_series`, 주기·기간이 다르면 `unexpected_response_period`, 같은 기간이 두 번이면 `duplicate_response_period`로 실패한다.
- 단위는 응답(`UNIT_NM`)과 선택 단위를 NFKC로 맞춰 비교한다(전각 "2020＝100"과 "2020=100"을 같게 본다). 둘 이상이거나 다르면 `response_unit_conflict`.
- 원값(`raw_value`)은 응답 그대로 두고, 파생값은 C가 코드로 계산한다.
- 키는 요청 파라미터·trace·예외 메시지에 남기지 않는다. 응답에 키가 비치면 `kosis_credential_reflected`로 실패하고 응답을 기록하지 않는다.

## 정렬 결과 (alignment)

코드: `modules/b/claview_b/align.py`(`align`, `combine_results`; 파이프라인은 `claview_b_api.service`로 부름). 조회가 끝난 `data_result`를 C에 넘기기 전에 거치며, 입력은 바꾸지 않고 정렬된 사본을 돌려준다. 모델·네트워크를 쓰지 않는다. 지표를 둘 이상 함께 그릴 때(복수 표, 복수 요구)만 의미가 있고, 계열이 하나면 `status="unchanged"`이다.

```text
data_result["alignment"] = {
  "version": "align/1",
  "status": "unchanged" | "aligned" | "needs_choice",
  "frequency": "Y"|"H"|"Q"|"M"|None,          # 정렬 뒤 모든 계열의 주기(섞이면 None)
  "frequency_policy": "freq_mean"|"freq_last"|"freq_sum"|"freq_none"|None,
  "frequency_conversions": [{"series_id","from","to","method","dropped_buckets","incomplete_buckets","outside_span"}],
  "unit_conversions": [{"series_id","from_unit","to_unit","factor"}],
  "common_period": {"frequency","start","end"} | None,
  "axes": [{"axis_id","side":"left"|"right","unit","kind","series_ids","draw":"column"|"line"}] | None,
  "axes_reason": None | "single_series" | "mixed_frequency" | "too_many_units",
  "notices": [{"code","message","series_ids"}],
  "choice": {...}                              # status="needs_choice"일 때만
}
```

정렬 규칙은 다음과 같다. `raw_value`와 `selection`은 어떤 경우에도 바꾸지 않는다.

| 차이 | 처리 |
|---|---|
| 같은 통화, 배율만 다름 (십억원 / 백만원) | Decimal로 정확히 환산한다. 계열이 가장 많이 쓰는 배율이 기준이고, 같으면 먼저 나온 계열이 기준이다. `unit_conversions`에 환산 계수를 남긴다. |
| 통화가 다름 (원 / 달러) | 환산하지 않는다. 별도 축으로 나누고 `currency_not_converted` 안내를 남긴다. |
| 단위 종류가 다름 (금액 / % / 지수) | 환산하지 않는다. 별도 축으로 나눈다. |
| 조회 기간이 다름 | 공통 기간으로 자르고 `common_period_applied` 안내를 남긴다. 겹치지 않으면 자르지 않고 `no_common_period` 안내를 남긴다. `requested_period`도 공통 기간 안으로 맞춘다. |
| 주기가 다름 | `align(frequency_policy=None)`은 `needs_choice`와 `choice`(질문·선택지)를 돌려주고 계열을 바꾸지 않는다. 사용자가 방법을 고르면 같은 입력으로 `align(frequency_policy=...)`을 다시 부른다. |

주기 선택지(`choice.options[].option_id`)는 `freq_mean`(기간 평균), `freq_last`(기간 마지막 시점 값), `freq_sum`(기간 합계), `freq_none`(맞추지 않고 주기별로 따로 보기)이다. 가장 긴 주기(월 < 분기 < 반기 < 연)로 맞추며 더 짧은 주기를 합친다. 짧은 주기를 길게 늘리지는 않는다. 비율·지수가 하나라도 합쳐지는 쪽에 있으면 `freq_sum`은 선택지에서 빠지고, 강제로 보내도 `alignment_policy_not_allowed`로 거절한다. 기간 안의 값이 하나라도 없으면 그 기간 값은 비우고(`value_status="missing"`), 기간의 일부만 조회 범위에 든 경우는 제외한다.

정렬이 바꾼 계열에는 다음 필드가 붙는다.

```text
unit 변경:       series["source_unit"] = 원래 단위, series["unit"] = 맞춘 단위 (points[].value는 환산값, raw_value는 원값)
주기 변경:       series["source_frequency"], series["source_points"](원래 points), series["frequency"], series["aligned_period"]
                 points[].raw_value = None (여러 시점의 값을 합친 값이므로)
기간 자름:       series["aligned_period"] = {frequency, start, end}, coverage를 다시 계산
```

`aligned_period`가 있으면 C는 `selection.period` 대신 이것을 기준으로 시점을 검증한다. 정렬 안내(`notices`)는 `data_result["period_notices"]`에도 덧붙어 화면 안내로 나간다.

`axes`는 단위가 1종 또는 2종이고 주기가 하나일 때만 만든다. 2종이면 금액 단위가 왼쪽 축이고, 왼쪽이 금액이고 오른쪽이 비율·지수·기타면 왼쪽은 막대(`column`), 오른쪽은 선(`line`)으로 그린다. 3종 이상이거나 주기가 섞이면 `axes=None`이고 C는 기존처럼 단위·주기별 카드로 나눈다.

### 여러 요구를 한 차트로 (combine_results)

`combine_results([data_result, ...])`는 요구별 결과를 하나로 합친다. 계열 ID에 `R1-`, `R2-` 접두어를 붙이고(상하위 관계 `relations`의 ID도 같이 바꾼다), 선택 조건이 같은 계열은 한 번만 둔다. `requested_period`는 모든 요구가 같을 때만 남기고, 다르면 지우고 `requested_period_not_shared` 안내를 남긴다. 현재 C 연결층은 질문에 "한 그래프", "이중 축", "겹쳐" 같은 표현이 있을 때만 합친다. 그 밖에는 요구별 카드를 유지한다.

### C의 입력과 출력

- 입력: 정렬된 `data_result`(`alignment` 포함). `alignment.status="needs_choice"`인 자료를 렌더러에 넘기면 `invalid_c_input`으로 거절한다.
- 출력: `axes`가 있으면 `views`에 `dual_axis`("이중 축")가 첫 번째로 들어가고 기본 보기가 된다. 한 축에 그릴 수 없는 `line`·`bar`·`horizontal`은 선택지에서 빠지고 사용할 수 없는 이유가 `blocked_views`에 남는다. 화면 카드는 한 장이며 `axes`(`side`/`unit`/`draw`)와 계열별 `unit`·`axis`(축 번호)를 가진다.
