# KOSIS 조회 조건과 검증 절차

- 관리: 데이터·API 담당 / 팀 공동 검수
- 정리일: 2026-09-23
- 상태: 2026-09-16 조회 기록 기반의 구현·검수 안내. 이번 이관에서 실제 API 호출과 원표 재대조는 하지 않았습니다.
- 근거: [KOSIS 개발 가이드](https://kosis.kr/openapi/devGuide/), 기존 팀 조회 기록

## 1. 범위와 확인 수준

대상은 KOSIS Open API 내 한국은행 소관 통계표입니다. 기관 코드 `301`을 조회 조건과 결과 검수에 함께 사용합니다. 공식 검색·목록 API의 지원 파라미터는 서로 다르므로 일반 검색 결과가 자동으로 이 기관에 한정된다고 가정하지 않습니다.

- **목록 확보:** 표 ID·명칭·기관·목록 경로를 확보한 상태.
- **메타 확보:** 조회 가능한 항목·분류·주기·기간·단위·주석을 수집한 상태.
- **실제 조회:** 선택한 조건으로 수치 응답을 받은 상태.
- **원표 대조:** 같은 조건의 KOSIS 화면·내려받은 원표와 수치를 비교한 상태.

표 개수, 수치 행 수, 조회 가능한 계열 수는 다른 수치입니다. 목록의 중복 경로는 기관·표 ID 조합으로 구분하되 경로 자체는 검색 근거로 보존합니다. 수집 개수는 기준일과 제외·예외 항목을 함께 기록합니다.

## 2. API를 사용하는 순서

| 단계 | 확인할 것 |
| --- | --- |
| 목록·검색 | 한국은행 기관 범위와 후보 표 ID·명칭 |
| 표 메타 확인 | ITEM, 분류별 선택값, 주기·기간·단위·주석 |
| 조회 계획 | 실제 코드·기간·주기를 확정하고 조건 유효성 검사 |
| 자료 조회 | API 응답과 키를 제거한 요청 조건 보존 |
| 원표 대조 | 같은 표·항목·분류·기간·주기로 값과 주석 확인 |
| 비교·가공 | 단위·기준·기간 차이와 변환 규칙 기록 |

검색 결과에 표가 나타나는 것만으로 요청한 지표를 포함한다고 판단하지 않습니다. 표 전체의 수록기간도 개별 계열의 완전한 수록을 보장하지 않습니다.

## 3. ITEM과 분류값을 구분하는 예시

기록 기준일: 2026-09-16. 새 호출 전 현재 메타로 코드·기간을 확인합니다.

| 조건 | 신규취급액 기준 | 잔액 기준 |
| --- | --- | --- |
| orgId | 301 | 301 |
| tblId | DT_121Y006 | DT_121Y015 |
| itmId | 13103134553999 | 13103134612999 |
| objL1 | 13102134553ACC_ITEM.BECBLA03 | 13102134612ACC_ITEM.BECBLB0202 |
| 분류 의미 | 가계대출 | 가계대출 |
| 기록된 조회 기간 | 202308~202607 | 202308~202607 |
| 주기 | M | M |

‘가계대출’은 분류값이며 공통 ITEM 코드와 구분합니다. 두 기준은 개별 계열로 비교합니다. 조회 기록은 각각 36개 월 자료이며, 골든셋 등록 전 공용 원자료·원표와 대조합니다.

## 4. 재현 결과에 남길 항목

- 키를 제거한 실제 요청 조건과 실행 코드 버전
- 원 응답과 사람이 확인할 표 형태의 자료
- 기간별 행 수·중복·누락·단위·항목·분류 검사 결과
- 원표 대조 조건·확인일·대조한 시점과 값·불일치 내역
- 잠정치·개편·소급 수정 등 선택 계열에 해당하는 주석
- 조회 실패 시 응답 종류·재시도·미확인 원인

‘최근 N개 시점’이 반드시 결측 없는 연속 N개월이라는 뜻은 아닙니다. 비교 재현에는 고정 기간을 우선 기록하고, 최신 자료를 조회할 때는 실제 반환된 종료 시점도 남깁니다.

DT 원문과 숫자 해석 결과를 구분해 결측 기호·정밀도를 보존합니다. 갱신된 수치와 과거 저장값이 다르면 곧바로 오류로 단정하지 말고 조회 시점과 개정 여부부터 확인합니다.

## 5. 구조별 확인 기준

| 항목 | 확인·처리 기준 |
| --- | --- |
| 다주기 표 | 월·분기·연별 지원 여부와 수록기간을 각각 확인. 월 자료의 단순 평균이 공식 분기값이라고 가정하지 않음 |
| 항목·분류 | 공통 ITEM과 각 분류 축의 선택 코드를 구분. 분류 조합의 실제 조회 가능 여부도 시험 |
| 단위 | 단위 응답·항목별 메타·주석/표기에서 근거 확인. 이름에서 추정한 단위는 확인값과 분리 |
| 기준시점·통계 기준 | 지수 기준년·명목/실질·계절조정·말잔/평잔 등 의미를 바꾸는 조건 확인 |
| 주석 | 잠정치·개편·소급 수정의 적용 계열과 기간 확인 |
| 빈 응답 | 해당 정보 미제공, 파라미터 오류, 일시 장애를 구분. 빈 응답만으로 원래 없다고 확정하지 않음 |
| 파싱 오류 | 정상 JSON 파싱 실패를 별도 기록. 보정이 필요하면 원문 보존·원인·적용 조건·회귀 테스트를 남김 |

서로 다른 단위를 일괄 변환하거나 모든 주기를 하나로 합치지 않습니다. 비교 목적과 통계 의미에 맞는 처리 규칙을 정하고, 판단할 근거가 부족하면 확인 질문이나 비교 불가 안내를 사용합니다.

## 6. 구현 위치와 실행 코드 인계

KOSIS 수집·조회 스크립트의 새 저장소 통합과 팀원 재현은 진행 전입니다.

| 위치 | 책임 |
| --- | --- |
| `src/clients/kosis.py` | 통신·응답 파싱·API 오류 처리 |
| `src/metadata.py` | 목록·메타 수집·상태·이력 관리 |
| `src/extract.py` | 조회 계획 검증·수치 조회·필요한 정합·병합·파생값 계산 |
| `scripts/` | 수집·검수 작업의 실행 진입점 |
| `data/catalog/`, `data/samples/` | 검토한 목록·확보 현황, 공유 가능한 대표 응답 |
| `tests/fixtures/` | 키 없는 검사를 위한 고정 응답·오류 사례 |

상세 책임과 저장 원칙은 [저장소 README](../../README.md)를 따릅니다.

코드 인계 시 상대경로, 의존성, 환경변수, 키 마스킹, 실패 기록, 소규모 샘플과 테스트를 확인하고 이 문서에 실행 방법을 추가합니다. 원 응답·대형 자료는 기본적으로 Git에서 제외하며 팀 공용 보관 위치 또는 재생성 절차를 제공합니다.
