# 공통 개발환경

Python 3.12와 루트 `requirements.txt`를 모든 서비스에서 사용한다. 개발 시험은 `requirements-dev.txt`를 설치한다. Node.js 24는 frontend 시험에 사용한다.

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements-dev.txt
$env:PYTHONPATH = "common;modules/a;modules/b;modules/c;pipeline"
.venv/Scripts/python pipeline/scripts/check.py
.venv/Scripts/python -m ruff check .
.venv/Scripts/lint-imports
$tests = Get-ChildItem frontend/tests -Filter *.cjs | ForEach-Object FullName
node --test $tests
```

묶음별 실행은 `check.py --suite a`, `--suite a-tl`, `--suite a-api`, `--suite b`, `--suite b-api`, `--suite c`, `--suite common`, `--suite pipeline`, `--suite pipeline-api`다. A의 import 차단과 B의 네트워크 차단 때문에 각 묶음을 별도 프로세스로 실행한다. 시험의 합성 응답은 정확도 근거가 아니다.

배포·포트·기록은 [루트 README](../../README.md), 실제 호출의 승인·키 준비는 [Docker 안내](Docker_실호출_실행.md)를 따른다. `ruff check .`는 pyproject의 명시 제외 범위를 적용한다. 통과가 기존 본체 전체의 스타일 검사를 뜻하지 않는다.
