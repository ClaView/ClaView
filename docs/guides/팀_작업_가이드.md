# 팀 작업 가이드

1. [루트 README](../../README.md)에서 실행 구조·모드·검증 방법을 확인한다.
2. [공통 개발환경](공통_개발환경.md)에 맞춰 환경을 만들고 해당 모듈 시험을 실행한다.
3. main 기준의 별도 브랜치에서 목적이 같은 변경을 모은다. 기존 미커밋 작업을 옮기거나 지우지 않는다.
4. 계약 변경은 사용하는 모듈·파이프라인 시험과 fixture를 함께 확인한다. 기대값을 바꿔 시험을 통과시키지 않는다.
5. Python 묶음, frontend 시험, ruff, import-linter, Docker 합성 전체 흐름을 통과한 결과를 PR에 적는다.
6. 관련 담당자 리뷰 후 합친다. CODEOWNERS 자동 지정과 보호 규칙이 실제로 강제된다고 가정하지 않는다.

기본 제품은 AView 단일 경로다. A HTTP는 A만, pipeline HTTP는 A→B→조회→C 전체를 실행한다. 합성·저장 재생·실호출의 결과를 구분한다. 실제 호출은 호출 수·비용을 확인한 뒤 진행하고 키는 기록하지 않는다.

공동 소유·브랜치·PR 규칙은 [CONTRIBUTING](../../CONTRIBUTING.md), 진행 중 변경은 [계획 58](../plans/58_새A_단일경로_배포정리.md)을 따른다.
