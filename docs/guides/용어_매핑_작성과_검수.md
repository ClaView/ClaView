# 용어 매핑 작성과 검수

- 관리: 용어 매핑·검색 담당 / 메타정보 담당 공동 검수
- 정리일: 2026-09-23
- 상태: 작성·검수 기준 초안. 용어 우선순위·생성 후보 CSV를 검토용으로 반영했습니다. 승인된 검색 사전과 자동 승인 규칙은 아직 없습니다.
- 관련: [메타정보 검수](메타정보_관리와_검수.md), [검색 문서 구성](검색문서_구성과_색인준비.md), [NCP 모델 활용](../design/NCP_모델분석과_적용방향.md)

## 1. 목적

사용자의 표현을 공식 통계 용어와 연결하되, 의미가 다른 계열을 같은 것으로 취급하지 않습니다. 매핑은 검색과 확인 질문을 돕는 자료이며 조회 코드 검증을 대신하지 않습니다.

| 관계 | 의미 | 작성 원칙 |
| --- | --- | --- |
| 동의어·별칭 | 특정 문맥에서 같은 대상을 가리키는 표현 | 적용 범위와 근거를 확인한 뒤 연결 |
| 관련 개념 | 관련은 있지만 같은 뜻은 아닌 표현 | 후보 탐색에 사용하고 자동 확정하지 않음 |
| 조건부 연결 | 추가 조건에 따라 연결 대상이 달라짐 | 구별 조건과 확인 질문을 함께 기록 |

예를 들어 ‘대출 부담’은 금리·부채 규모·상환액 등을 뜻할 수 있습니다. 이를 ‘가계대출 금리’의 동의어로 고정하지 않습니다. 관련 개념을 정리하더라도 실제 제시할 통계 후보는 프로젝트 범위와 메타정보에서 확인해야 합니다.

### 현재 자료와 역할

| 자료 | 역할 | 확인 상태 |
| --- | --- | --- |
| 공식 용어 우선순위 CSV | 추출된 공식 명칭을 어떤 순서로 검토할지 정리 | 파일 구조·집계 확인. 모든 용어의 정의·코드 연결을 검수한 것은 아님 |
| 일상어 후보 CSV | 모델이 제안한 표현과 유사도 기반 분류를 검토 | 후보 기록 확인. 원본의 `자동채택`도 사람의 승인으로 간주하지 않음 |
| 기존 의미 매핑·표기 정규화 | 별칭·관련 개념·선택 기준과 표기 차이를 정리한 초안 | [JSON 76건](../../data/mappings/review/검색용_의미매핑_초안.json) 확보·구조 검사 완료. 의미 매핑 68건과 정규화 8건, 전체 의미 검수·후보 CSV와의 통합은 대기 |
| 승인된 검색용 매핑 | 검수한 관계·근거·적용 조건을 검색에서 사용 | 기준 파일 작성 전 |

집계, 발견한 문제, 원본 해시는 [통계어 사전 파일럿 검토 결과](../research/통계어사전_파일럿_검토결과.md)에 기록합니다. 이 문서는 작성·검수 절차를 관리합니다.

공식 명칭 하나가 여러 표와 계열에서 쓰일 수 있습니다. 문자열이 같다고 같은 통계 개념으로 합치지 않으며, 숫자 접두사·괄호를 제거할 때도 원문과 출처를 남깁니다. 원본의 `예시tblId` 하나는 모든 출처나 조회 코드를 대신하지 않습니다.

## 2. 작성할 항목

다음은 논리 항목이며 CSV·JSON의 확정 스키마는 아닙니다.

| 항목 | 작성 내용 |
| --- | --- |
| 매핑 식별자 | 수정·검수 이력을 연결할 ID |
| 사용자 표현 | 원 표현과 필요한 문맥 |
| 공식 후보 | 기관·표 ID, 항목·분류 명칭과 연결 코드 |
| 연결 수준 | 개념 / 표 후보 / 항목·분류 조건까지 확인한 계열 |
| 관계 유형 | 동의어·별칭 / 관련 개념 / 조건부 연결 |
| 구별 조건 | 대상·통계 기준 등 선택에 필요한 조건 |
| 근거 | 메타 버전, 공식 정의·주석, 확인 위치 |
| 확인 질문 | 부족한 조건을 구체화할 질문 |
| 시점·이력 | 적용 시점, 확인일, 구명칭·변경 관계 |
| 생성 경로 | 수기 / 실제 질의 / 모델 생성 후보 |
| 검수 | 작성자·검토자·상태·판정 이유 |

생성 후보의 점수·판정과 사람의 검수 결과는 별도 필드로 관리합니다. 원본 `판정`을 덮어쓰기보다 원본 파일 버전·공식어·후보 표현으로 연결한 검토 기록에 관계 유형, 적용 범위, 연결 코드, 승인/보류/기각 사유를 남기는 안입니다. 검토 기록의 정확한 스키마는 팀 합의 후 정합니다.

한 표현에 여러 후보를 연결할 수 있습니다. 표 ID만 확인한 항목을 완성된 계열 매핑으로 표시하지 않습니다. 여러 항목·분류 코드를 함께 저장할 때도 모든 조합이 조회 가능하다고 가정하지 않습니다.

## 3. 작성·검수 순서

1. 검수할 표의 메타 버전과 공식 용어·정의·연결 코드를 확보합니다.
2. 일상어 후보를 작성하거나 모델로 생성합니다.
3. 관계 유형을 구분하고, 여러 의미로 나뉘는 표현에는 구별 조건을 적습니다.
4. 코드 존재 여부를 자동 확인하고, 의미가 맞는지는 사람이 검토합니다.
5. 대표 질의로 검색·확인 질문·조회 조건 선택을 시험합니다.
6. 승인·보류·기각과 이유를 기록하고 검색 반영 범위를 정합니다.

검수 상태 예시는 `초안 → 검토 중 → 승인 / 보류 / 기각`입니다. 최종 상태 이름은 팀에서 정합니다. 자동 검사 통과만으로 승인하지 않습니다.

### 검수 체크리스트

- 사용자 표현과 공식 후보가 정말 같은 뜻인지, 단지 관련 있는지 구분했는가?
- 기관·표·항목·분류 코드가 해당 메타 버전에 존재하는가?
- 대상이나 통계 기준을 임의로 추가하지 않았는가?
- 같은 표현의 다른 의미를 누락하지 않았는가?
- 확인 질문의 선택지가 실제 후보와 연결되는가?
- 기간·주기 등 남은 조회 조건이 무엇인지 구분했는가?
- 잘못 연결되면 어떤 결과가 나오는지 반례를 확인했는가?

## 4. 모델을 활용할 때

```text
공식 용어·정의 제공
→ LLM으로 일상어 후보 생성
→ 코드·중복 등 자동 검사
→ 임베딩 등으로 검토 순서 조정
→ 사람의 의미 검수
→ 대표 질문으로 검색·조회 연결 확인
```

위 흐름은 적용안입니다. 임베딩 유사도는 정답 확률이 아니며, 높은 점수가 통계 의미의 일치를 보장하지 않습니다. 현재 파일럿은 고점수 후보를 포함한 136행 전체를 첫 검수 대상으로 삼는 안을 제안합니다. 이후 물량이 늘면 표본 검수 범위와 자동 반영 여부를 검토 결과에 따라 정합니다. 낮은 점수의 후보도 바로 기각하지 않습니다.

`자기매칭=Y`는 후보 표현의 최근접 공식어가 생성 대상 공식어와 같다는 기록입니다. 별칭 정답의 증거는 아닙니다. 반대로 `N`인 경우도 번호·공백·표기 차이인지, 다른 개념인지 먼저 확인합니다.

모델명, 프롬프트·입력 목록, 임베딩 입력·정규화·비교 대상 집합, 점수 계산법, 판정 규칙, 실행 시점을 확보해야 생성 실험을 재현할 수 있습니다. 현재 CSV의 점수만으로 모델 품질이나 검색 성능을 평가하지 않습니다. 모델에 표 ID를 전달하지 않더라도 내부 출처·코드 연결은 보존합니다.

사전에 없는 표현은 일반 검색으로 처리할 수 있어야 합니다. 매핑을 보강한다고 모든 질문을 사전에 등록하는 방식으로 제한하지 않습니다.

## 5. 작성 예시

다음은 형식 설명용 예시이며 승인된 매핑 데이터가 아닙니다.

| 사용자 표현 | 연결 수준·후보 | 관계 | 추가 확인 |
| --- | --- | --- | --- |
| 최근 가계대출 금리 | 예금은행 신규취급액·잔액 기준 후보 표 | 조건부 연결 | 예금은행을 뜻하는지, 어떤 통계 기준인지, 기간 |
| 새로 받은 가계대출 금리 | 신규취급액 기준 후보 | 조건부 연결 | 대상 기관, 공식 정의와의 일치, 조회 기간 |
| 대출 부담 | 금리·대출 규모·상환 관련 개념 | 관련 개념 | 사용자가 어떤 부담을 알고 싶은지 |

금리 후보 표와 과거 조회 코드는 [KOSIS 가이드](KOSIS_조회조건과_검증절차.md)에 있습니다. 이 표만으로 해당 코드의 현재 유효성이나 모든 표현의 의미 검수가 끝난 것은 아닙니다.

## 6. 보관과 변경

- 검토한 매핑 기준본: `data/mappings/`
- 팀 검토용으로 선별한 고정 스냅샷: `data/mappings/review/`. 승인된 사전이 아니며 런타임 검색·색인 입력으로 자동 로드하지 않음
- 미검수 생성 후보·대량 실험 결과: `data/processed/` 등 Git 제외 영역
- 생성·비교 방법: `scripts/`와 `docs/research/`
- 검수된 기대 행동과 정답 근거: `eval/cases/`

CSV·JSON을 모두 제공한다면 기준본 하나를 정하고 나머지는 생성본으로 관리합니다. 표명·코드·통계 기준 변경 시 연결된 매핑을 재검수하며 구명칭은 이력과 함께 보존합니다.

`review/`의 두 CSV는 제공받은 원본 바이트를 보존한 검토 스냅샷입니다. 검수 결과를 반영한 사전을 만들 때 원본을 수정하지 않고 승인 기록으로 연결합니다. 현재 자료만으로 모든 공식 용어의 출처 목록을 재생성하거나 후보 생성 실험을 재실행할 수는 없습니다.

매핑 작성에 쓴 질문과 최종 평가 질문은 구분합니다. 같은 질문으로 매핑을 보강하고 그 점수만 보고 일반화 성능이 좋아졌다고 판단하지 않습니다.

## 7. 구현 전 합의할 내용

- 기준 파일 형식과 매핑 승인 책임.
- 미검수 후보를 실험에 사용할 범위와 서비스 검색 반영 기준.
- 확인 질문과 기본값을 적용할 조건.
- 자동 검토 우선순위·임계값의 검증 방법.

## 8. 다음 작업

1. 후보 생성 입력 40개와 출력에 남은 공식어 35개의 차이, 원본 `폐기후보`와 노션의 저유사도 검토 설명 차이를 생성 담당자와 확인합니다.
2. 파일럿 후보를 검수하며 고득점 오연결, 약어, 상하위 개념, 같은 표현의 복수 후보를 함께 점검합니다.
3. 확보한 의미 매핑 JSON과 후보 CSV를 표현·공식 개념·관계·적용 범위로 대조합니다. 추출 원본·전체 출처 코드는 추가 확보해야 하며, 한 자료로 다른 자료를 덮어쓰지 않습니다.
4. 승인된 연결과 확인이 필요한 조건을 구분해 검색 기준 파일에 반영합니다.
5. 대표 질문으로 매핑 추가 전후의 후보 검색과 잘못된 연결을 비교합니다. 최종 평가용 질문을 튜닝에 사용하지 않습니다.

추가 검토안은 역방향 순위를 주 판단으로, 직접 유사도를 보조로 쓰는 방식입니다. 실제 비교 결과·대상 집합·사람 판정이 확보되기 전에는 성능 향상이나 자동 승인 정책으로 확정하지 않습니다. 순위 1위도 동의어 정답을 보장하지 않습니다. 현재 이관한 JSON은 이 실험의 결과 파일이 아닙니다.
