# 한국은행 카탈로그·메타 갱신

A와 B는 같은 `data/catalog/search_catalog.json`과 `data/raw/boK_meta_raw.jsonl`을 읽는다. A의 검색 카드와 B의 항목·분류 선택 자료는 용도가 달라 변환 결과 전체가 같을 필요는 없지만, 원본 판·해시와 표별 주기·수록 범위는 같아야 한다.

## 수집 범위

- KOSIS 기관별 목록 `MT_OTITLE`, 시작 목록 `301`(한국은행)의 하위 목록.
- 표마다 `TBL`, `PRD`, `ITM`, `UNIT`, `CMMT` 설명 메타. 통계 수치와 모델은 호출하지 않는다.
- 공식 안내: [통계목록](https://kosis.kr/openapi/devGuide/devGuide_0101List.do), [통계표설명](https://kosis.kr/openapi/devGuide/devGuide_060101List.do).
- 목록의 빈 가지와 `UNIT`·`CMMT`의 자료 없음은 기록한다. 필수 메타의 자료 없음, 전송 오류, 상한 초과는 중단한다. 자동 전송 재시도는 없다.

## 절차

1. 현재 목록·원메타·manifest를 별도 보관하고 SHA-256을 기록한다. Git의 이전 판도 보존한다. 기존 실행·평가 원응답·정답·원장은 고치지 않는다.
2. 명시적으로 승인된 메타 수집만 새 디렉터리에서 수행한다. `KOSIS_API_KEY`는 실행 환경에서만 사용하며 URL·예외·로그에 출력하지 않는다. 키가 없는 환경에서 합성 자료로 대신하지 않는다.

```bash
python -B pipeline/scripts/refresh_catalog.py \
  --catalog data/catalog/search_catalog.json \
  --output runs/catalog-refresh/new \
  --max-requests 2500
```

`collected_not_applied`는 수집 종료 상태이며 운영 반영 승인이 아니다. 새 폴더에 원 HTTP 응답, 요청 종류·키를 제외한 매개변수·시각·해시, 통합 메타, 목록, manifest를 남긴다. 목록에서 기존 표가 사라지면 자동 삭제하지 않고 중단한다. 추가 발견 표를 신규 공표 표라고 단정하지 않는다.

중단 전 응답을 재사용할 때는 `--reuse <이전 수집 디렉터리>`를 지정한다. 요청 매개변수·파일 경로·크기·SHA가 맞는 원문만 재사용하고, 새 네트워크 요청과 재사용 건수를 구분한다. 이전 시도의 전송도 전체 수집량에 포함해 남은 `--max-requests`를 정한다. 임의의 JSON 오류는 고치지 않는다. 공식 문자열에 잘못 들어간 역슬래시 escape만 파싱용 사본에서 보정하고, 원 HTTP 바이트와 보정 개수는 보존한다.

3. 구·신 자료에 실제 A·B 어댑터를 적용한다. 아래 검증기는 외부 연결을 차단한다.

```bash
python -B pipeline/scripts/verify_catalog_snapshot.py --repo . \
  --catalog data/catalog/search_catalog.json --metadata data/raw/boK_meta_raw.jsonl \
  --out runs/catalog-refresh/before.json
python -B pipeline/scripts/verify_catalog_snapshot.py --repo . \
  --catalog runs/catalog-refresh/new/search_catalog.json \
  --metadata runs/catalog-refresh/new/boK_meta_raw.jsonl \
  --baseline runs/catalog-refresh/before.json --out runs/catalog-refresh/after.json
```

검증 대상은 ID 집합, 중복·미지원 주기, A/B 정규화 기간, 분류·항목 코드와 부모 관계, A 축 역할·override 연결, B 단위 보완이다. 빈 단위나 주석을 모두 오류로 세지 않는다. 기존 오류와 새 오류를 구분하며, 기존 오류가 있어도 검증기 종료코드는 1이다. `new_errors`와 상세 차이를 함께 검토한다. 이름·구조·보완 연결 변화와 기간 축소는 자동 승인하지 않는다.

4. 같은 코드에서 구·신 메타를 각각 사용해 저장 응답을 비교한다. 원질문·기준일·기대값·응답은 고정한다. 첫 후보의 집합·순서·패밀리와 실제 사용한 카드 참조를 별도로 비교한다. 선택 결과가 같아도 모델 입력 후보는 달라질 수 있다. A 카드 참조가 다른 표로 이동하거나 새 복구 응답이 필요하면 재생 공백으로 남긴다. KOSIS 요청이 달라지면 기존 수치를 붙이지 않는다. 구메타를 보고 만든 모델 응답 재검사는 새 메타에서의 모델 정확도 측정이 아니다.
5. 확인한 목록과 메타를 함께 반영하고 `pipeline_manifest.json` 및 `metadata_snapshot.json`의 해시·수집 시각·검증 범위를 갱신한다. 옛 CSV·검색 초안·골든 자료는 해당 판의 자료로 보존한다. 판본 관계, 축 역할 판단, 사전 승인 상태를 자동으로 새로 정하지 않는다.
6. 관련 회귀를 실행한다. 옛 메타 고정 시험만 명시적으로 고정 fixture를 사용하고, 기본 시험은 갱신 메타를 읽게 한다. 메타·고정 fixture 변경으로 A·B·pipeline CI가 실행되는지 확인한다. Docker 이미지를 다시 만들 때 모든 A·B 실행 경로에 동일 두 파일이 들어갔는지 해시로 확인한다. A/B는 프로세스 안에서 자료를 캐시하므로 실행 중 파일만 덮어쓰지 않는다. 서버 기록 volume과 실제 호출 원장은 유지한다. 갱신 전에 표시한 되묻기 선택지의 날짜가 달라지면 답 적용이 거절될 수 있으므로 새 세션에서 다시 질문하도록 안내한다.

## 별도 작업

사전 연동은 메타 갱신과 분리한다. 갱신한 공식 표명·항목·축에 사전 표제어가 연결되는지 확인한 뒤 검색 확장으로 평가한다. 사전으로 원질문·확정 조건을 덮어쓰거나 표 정답을 강제하지 않는다.
