# 메타정보 관리와 검수

- 관리: 목록·메타정보 담당 / 팀 공동 검수
- 정리일: 2026-09-23
- 상태: 검수 기준 초안. 목록·현황 파일과 대표 메타는 이관했으며, 수집 코드·전수 캐시는 미이관입니다.
- 범위: KOSIS Open API 내 한국은행 소관 통계표의 목록·구조·변경 이력.
- 관련: [조회 조건과 검증](KOSIS_조회조건과_검증절차.md), [용어 매핑](용어_매핑_작성과_검수.md), [검색 문서](검색문서_구성과_색인준비.md)

## 1. 목적과 산출물

질문에 맞는 표를 찾은 뒤 실제 항목·분류·기간·주기를 선택할 수 있도록 메타정보를 준비합니다. 메타 수집 완료를 전체 표의 의미 검수나 수치 조회 완료로 표현하지 않습니다.

| 산출물 | 내용 | 보관 위치 |
| --- | --- | --- |
| 목록·수집 현황 | 기관·표 ID, 목록 경로, 메타 종류별 상태, 미확인 사항 | `data/catalog/` |
| 원 응답 | 수집 시점별 원문과 키를 제거한 요청 조건 | `data/raw/`, 기본 Git 제외 |
| 대표 샘플 | 구조를 설명하고 재현할 수 있는 작은 응답 | `data/samples/` |
| 검수 기록 | 확인 범위·근거·예외·남은 작업 | `docs/research/` 및 현황 파일 |
| 파싱 회귀 사례 | 정상·빈 응답·확인된 오류 패턴 | `tests/b/fixtures/` |

수집 개수는 현황 파일을 기준으로 집계합니다. 문서에 수치를 쓸 때는 파일 버전·기준일·분모를 함께 적습니다. 기존 조사값을 최신 전수 검증 결과로 복사하지 않습니다.

## 2. 표별로 확보할 정보

| 구분 | 확인할 내용 |
| --- | --- |
| 식별 | 기관 코드, 표 ID·표명, 목록 경로, 원표 링크 |
| 항목·분류 | ITEM과 각 분류 축, 선택값 코드·명칭, 부모 관계 |
| 주기·기간 | 지원 주기별 시작·종료 시점 |
| 단위 | 표·항목·계열에 적용되는 단위, 출처, 미확인 여부 |
| 해석 | 정의·주석·통계 기준, 개편·잠정치·소급 수정 안내 |
| 이력 | 수집 시각, 원문 식별값, 메타 버전, 검수 상태 |

기관·표 ID가 같은 목록 경로는 하나의 표로 연결하되 경로 정보는 보존합니다. 이름이 같은 서로 다른 표는 합치지 않습니다.

## 3. 검수 순서

1. 목록의 기관·표 ID·중복 경로·누락을 확인합니다.
2. 메타 종류별 응답을 저장하고 통신 오류·빈 응답·파싱 오류를 구분합니다.
3. 항목·분류 코드와 계층, 주기별 기간, 단위 근거를 확인합니다.
4. 구조가 다른 대표 표를 골라 사람이 실제 표와 대조합니다.
5. 대표 계열의 조회 조건을 조회 담당자에게 넘겨 수치 응답을 시험합니다.
6. 결과와 미확인 사항을 현황 파일에 반영합니다.

전수 자동 점검은 식별자·응답·필수 구조 등을 대상으로 하고, 사람이 볼 범위는 구조 유형과 예외를 기준으로 정합니다. 대표 사례 통과를 나머지 표의 검수 완료로 확장하지 않습니다.

### 상태를 따로 기록할 항목

| 상태 축 | 구분 예시 |
| --- | --- |
| 수집·파싱 | 성공 / 빈 응답 / 통신 오류 / 파싱 오류 / 미시도 |
| 구조·의미 검수 | 미검토 / 일부 확인 / 확인 / 보류 |
| 자료 조회 | 미시도 / 성공 / 실패 |
| 원표 수치 대조 | 미시도 / 일부 대조 / 지정 범위 일치 / 불일치 |

상태 이름과 필드명은 구현 전 합의할 초안입니다. 하나의 `ok` 값으로 모든 검증을 대신하지 않습니다. “확인”에는 확인한 범위와 근거를 붙입니다.

## 4. 예외 처리 기준

- UNIT 또는 CMMT가 비어 있어도 바로 “단위·주석 없음”으로 확정하지 않습니다. 요청 조건과 다른 메타·원표를 확인합니다.
- 항목명에서 추정한 단위는 공식 응답에서 확인한 단위와 구분합니다. 확인되지 않은 단위로 자동 환산하지 않습니다.
- 다주기 표는 주기별 기간을 보존합니다. 요약 기간 하나로 모든 주기를 대표하지 않습니다.
- 부모·합계 항목도 실제 조회 가능 여부를 확인합니다. 말단 항목만 유효하다고 가정하지 않습니다.
- JSON 보정이 필요하면 원문·실패 원인·변경 내용·적용 조건을 남깁니다. 확인한 패턴에 한정하고 정상 응답을 바꾸지 않는 테스트를 둡니다.
- API로 바로 처리하지 못한 항목은 사유와 후속 확인 대상으로 남깁니다. 처리 미지원과 프로젝트 범위 제외는 구분합니다.

## 5. 변경 관리와 인계

수집 시각과 통계 기준의 적용 시점은 다릅니다. 적용 시점을 확인하지 못하면 미확인으로 남깁니다.

메타 변경 시 다음 순서로 확인합니다.

```text
이전·새 메타 비교
→ 코드·명칭·주기·기간·기준·주석 변경 구분
→ 연결된 매핑·검색 문서 영향 확인
→ 필요한 자료 재검수·검색 문서 재생성
→ 변경 이유와 검수 범위 기록
```

수집 담당자는 실행 코드·의존성·키 값을 노출하지 않는 재현 명령·현황 파일·대표 응답·예외 기록을 함께 인계합니다. 실제 API 수집에는 인증이 필요하며, 키 없이 실행하는 모의 테스트와 구분합니다. 원자료가 Git 제외라면 팀 공용 확보 방법도 필요합니다.

최소 인계 항목은 다음과 같습니다.

```text
기관·표 ID / 수집 시각·버전 / 메타 종류별 상태
항목·분류 코드 / 주기별 기간 / 단위와 근거 / 주석
검수자·범위 / 조회·원표 대조 상태 / 예외·미확인 사항
원 응답 위치 또는 확보 방법 / 실행 코드 버전
```

현재 문서는 작업 기준입니다. 제공 파일의 대조 결과는 [조사 결과](../research/한국은행_통계표_조사결과.md), 파일·컬럼·확보 상태는 [데이터 안내](../../data/README.md)에서 확인합니다. 이관한 스냅샷이 현재 API의 최신 상태를 보장하지는 않습니다.
