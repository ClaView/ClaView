# 다중 통계표·이중 축 시험 가이드

- 상태: 개발·검토용. 골든셋 v3의 정답은 승인 전 초안이며 성능 점수 집계 대상이 아님.
- 2026-10-30(PR #24)부터 서비스 B의 선택 모델은 `gpt-6.1-terra`임. 이 가이드의 HCX 절차(`--mode hcx`)는 보관된 `HcxModel`로 재현하는 비교용이며 서비스 경로가 아님. 비교 결과와 교체 근거는 [B 모델 교체 기록](../modules/b/research/B_모델_교체_GPT_고정_및_후속개선_기록_20261102.md)에 있음.
- 근거: [계획 31](../plans/31_B_C_고도화_복수표_이중축.md), [계획 32](../plans/32_A_B_표별_지표_focus_제안.md), [조회 결과 계약](../contracts/조회_결과.md)
- 실행 명령은 저장소 루트 기준이며 Windows PowerShell 형식임. Python 3.12와 `requirements-dev.txt` 환경이 전제이고, 모듈 경로는 README 3절처럼 `PYTHONPATH`로 준다.
- 모듈 구조(`modules/`·`pipeline/`)로 옮긴 판이다. 시험 위치: `modules/b/tests/test_align.py`, `pipeline/tests/staged/test_c_alignment.py`·`test_golden_multi_table.py`, `pipeline/tests/test_table_focus.py`. 도구: `pipeline/scripts/golden_replay.py`, `golden_inspect.py`.

## 1. 무엇을 시험하는가

두 개 이상의 통계표에서 지표를 가져와 한 그래프로 합칠 때 다음 동작을 확인함.

- B가 표별로 항목·기간을 정하고 KOSIS에서 조회한 뒤, 정렬 모듈(`claview_b.align`, 파이프라인은 `claview_b_api.service`로 부름)이 단위 배율·기간·주기를 맞춤.
- 단위가 다른 지표(금액+증감률 등)는 이중 축으로 표시하고, 통화가 다르면 환율 환산 없이 축을 나눔.
- 주기가 다르면 사용자에게 맞춤 방법을 묻고, 답변 후에는 새 조회 없이 이어 실행함.
- 실제 HCX가 표마다 질문의 지표를 알맞게 나누어 고르는지(B 선택)를 골든 정답과 비교함.

A(질문 해석·표 선택)는 외부 키 연결 전이므로 골든셋의 정답 통계표로 대신함. B 이후 단계는 실제 코드가 그대로 동작함.

## 2. 골든셋 v3(5건)

파일: `eval/cases/golden/golden_set_v3_multi_table.json`(스키마 `.schema.json`, 합성 값 규칙 `.replay_values.json`). 기존 골든 22건(`golden_set_v1.json`)은 바꾸지 않음. 통계표 이름은 카탈로그의 KOSIS 통계표명과 같고, 값은 담지 않음(조회 시점 응답을 따름). 통계표마다 `indicator`(질문에 나온 지표 문구)를 두며, `--table-focus` 시험에서 B에 넘기는 `focus` 값으로 쓰임.

질문 문구 주의:

- B는 질문에 "월별·분기별·연간"이 있으면 모든 통계표에 같은 주기를 적용함. CV-BC-02는 이 때문에 질문에 주기를 쓰지 않고, 월 전용 표와 분기 전용 표를 조합함.
- "~성장률 전년동기비"처럼 증감률을 뜻하는 표현은 B가 기준 연도를 한 해 앞당겨 조회할 수 있음.
- 질문에 통계표 이름을 쓰면 이름 속 "~별"(예: "지급수단별 통계")이 분해 요청으로 읽혀 B가 세부 항목을 모두 펼침(CV-BC-03에서 7개 선택). 그래서 CV-BC-03 질문은 "지급수단 통계"로 씀. B의 판정 자체는 아직 표 이름과 분해 요청을 구분하지 않음.
- CV-BC-02의 "실질 GDP 성장률"은 표에 전년동기비·전기비 변형이 모두 있어 모호함. 실제 HCX는 계절조정 전기비를 일관되게 골랐고 경상수지가 계절조정이라 짝이 맞으므로 골든 정답을 이쪽으로 정함(B 담당 승인 필요).

## 3. 시험 단계

### 3-1. 자동 시험(키·외부 호출 없음)

```powershell

$env:PYTHONPATH = "common;modules/b"
python -B -X utf8 -m pytest modules/b/tests -q -p no:cacheprovider
$env:PYTHONPATH = "common;modules/a;modules/b;modules/c;pipeline"
python -B -X utf8 -m pytest pipeline/tests -q -p no:cacheprovider
```

`pipeline/tests/staged/test_golden_multi_table.py`가 골든 파일 형식, 표·항목 코드·단위의 카탈로그 일치, 5건 재생 결과, 판정 분류, 표별 지표 전달을 확인함. A 시험(`modules/a/tests`)은 별도 프로세스로 돌림.

### 3-2. 골든셋 점검 명령(키·외부 호출 없음)

```powershell
$env:PYTHONPATH = "common;modules/a;modules/b;modules/c;pipeline"
python -B -X utf8 pipeline/scripts/golden_replay.py check
```

- 골든 B 답을 재생하고 조회 값은 합성 시험값으로 대체해 5건을 끝까지 돌림. 네트워크는 차단됨.
- 사례마다 판정(4절)과 사유를 출력함. `--case CV-BC-02`로 한 건만 돌릴 수 있고(여러 번 지정 가능), `--out runs/golden-v3`로 사례별 기록을 저장함.
- 합성 값은 KOSIS 값이 아님. 화면과 기록에 "시험용 재생" 표시가 붙음.

### 3-4. 실제 KOSIS 조회(골든 B 선택 + 실제 KOSIS)

실제 호출이므로 호출 수를 확인하고 승인한 뒤 진행함. 전체 5건은 KOSIS 10회(계열당 1회)임. 처음에는 한 건으로 확인하는 것을 권장함.

```powershell
python -B -X utf8 pipeline/scripts/golden_replay.py check --mode kosis --allow-external --prompt-keys --case CV-BC-01 --out runs/golden-v3-kosis
```

- 시작할 때 `[계획] 실제 호출 예정: KOSIS N회`를 출력함. `--prompt-keys`는 키를 숨김 입력으로 받으며 화면·파일에 남기지 않음. 환경변수 `KOSIS_API_KEY`가 있으면 입력을 생략함.
- 확인할 것: B의 단위 검증 통과(`response_unit_conflict` 없음), 기간별 값 존재 여부(결측), 실제 단위 문자열이 골든 단위와 같은지, 정렬 결과(축·환산·주기 변환)가 기대와 같은지.
- 불일치가 나오면 골든 정답이 틀린 것인지, KOSIS 응답이 바뀐 것인지, 정렬 규칙 문제인지를 `--out` 기록의 `blocks`(정렬 결과)와 `state`로 구분함.

### 3-5. 실제 HCX B 선택 + 실제 KOSIS 조회(B 담당 확인용)

A 대신 골든 통계표를 주고, B가 HCX로 항목·기간을 고르게 함. 골든 정답과 B 선택이 같은지가 핵심임.

```powershell
if (-not $env:CLOVASTUDIO_API_KEY) { $s = Read-Host "HCX key" -AsSecureString; $env:CLOVASTUDIO_API_KEY = [System.Net.NetworkCredential]::new("", $s).Password }
if (-not $env:KOSIS_API_KEY) { $s = Read-Host "KOSIS key" -AsSecureString; $env:KOSIS_API_KEY = [System.Net.NetworkCredential]::new("", $s).Password }
python -B -X utf8 pipeline/scripts/golden_replay.py check --mode hcx --allow-external --hcx-retries 2 --case CV-BC-01 --case CV-BC-02 --case CV-BC-03 --case CV-BC-04 --case CV-BC-05 --out runs/golden-v3-hcx
```

- 호출 수: 사례당 HCX 2회(통계표 수)와 KOSIS는 B가 고른 계열 수만큼임. 5건 전체는 HCX 10회이며, 호출 간격 35초가 적용되어 약 6분이 걸림.
- HCX 한도 초과(`hcx_http_429`, 서비스 코드 42901): 같은 키를 A 파트 등 다른 곳에서 함께 쓰면 분당 토큰 한도(60,000)가 소진되어 멈출 수 있음. 이때 B 단계가 중단되어 "비교하지 못함"으로 표시되며 골든과의 차이가 아님. 다른 사용을 잠시 멈추고 다시 실행하거나, `--hcx-retries 2`(0~3, 기본 0)로 서비스가 알려 준 초기화 시각(최대 60초)까지 기다린 뒤 같은 요청을 다시 보내게 함. 재시도도 HCX 호출에 포함되며 시작 시 `[계획]`에 최대 호출 수가 표시됨.
- B가 고른 계열이 골든과 다르면 "골든에만 있음"과 "B만 선택함"으로 항목·분류 이름·코드와 기간을 나눠 보여 줌. B가 중간에 멈추면 사유 코드가 나옴.

### 3-6. 표별 지표(`focus`) 전달 비교와 규칙 비교(B 담당 확인용)

통계표가 여럿이면 각 표의 B 호출이 질문 전체를 보고 다른 표 몫의 지표를 비슷한 항목으로 채우는 경향이 있음(계획 32). A가 표마다 지표를 알려 주는 경우를 흉내 내어 비교함.

```powershell
python -B -X utf8 pipeline/scripts/golden_replay.py check --mode hcx --allow-external --hcx-retries 2 --table-focus --case CV-BC-01 --case CV-BC-02 --case CV-BC-03 --case CV-BC-04 --case CV-BC-05 --out runs/golden-v3-hcx-focus
```

- `--table-focus`: 골든 통계표의 `indicator`를 표 항목의 `focus`로 B에 넘김. 옵션이 없으면 `focus` 없이 실행함. 모든 모드에서 쓸 수 있음.
- `--no-multi-table-prompt`: B의 "통계표가 여럿일 때" 프롬프트 규칙을 끄고 실행함(규칙의 필요성 비교용).
- 같은 명령을 옵션만 바꿔 돌려 판정 건수와 추가 계열 수를 비교함. HCX 출력이 실행마다 조금씩 달라질 수 있어 한 번의 차이로 결론 내리지 않음.

### 3-7. 저장된 기록 보기(키·외부 호출 없음)

```powershell
python -B -X utf8 pipeline/scripts/golden_inspect.py runs/golden-v3-hcx CV-BC-04 --request
```

- `--out`으로 저장한 기록에서 B 호출마다 모델이 돌려준 행(항목·분류 코드·기간)을 보여 줌. 같은 행이 반복되면 표시함.
- `--request`: 모델에 준 입력도 보여 줌(다중 표 규칙 포함 여부, 질문, 함께 전달된 통계표, 표별 지표, 축별 후보 값).

## 4. 판정 기준

- 통과: B 선택이 골든과 같고, 정렬 결과(상태·공통 주기·주기 변환·단위 환산·축·안내 코드)와 카드(기본 보기·막힌 보기·계열 수)가 기대와 같음. 주기 질문 사례는 질문 선택지와 답변 후 결과까지 같음.
- 골든 계열 포함·추가 계열 N개: 골든 계열은 모두 선택했으나 B가 계열을 더 골랐음. 정렬·카드 차이는 추가 계열의 영향일 수 있어 "참고"로 표시함. 예: 추가 계열 때문에 단위가 세 종류가 되면 이중 축을 그리지 못하고 계열마다 카드가 나뉨(카드 수·계열 수를 함께 표시).
- 불일치: 골든 계열이 빠졌거나, B 이외 단계(주기 질문, 카드 구성 등)가 기대와 다름. B가 중단된 경우는 "비교하지 못함"으로 따로 표시함.
- 불일치와 추가 계열은 오류가 아니라 확인 대상임. 정답 승인 전에는 점수로 집계하지 않음.
- 종료 코드는 불일치가 있을 때만 1임.

## 5. 실제 HCX 시험에서 확인된 사항(2026-10-26)

- 골든 B 답 + 실제 KOSIS: 5건 모두 통과.
- 실제 HCX B 선택: 처음에는 5건 모두 골든과 달랐음. 골든 계열은 대부분 포함했고 표마다 1개 안팎을 더 골랐으며, CV-BC-03은 7개를 더 골랐고 CV-BC-04는 같은 행을 반복해 중단됨.
- 조치와 결과는 [계획 31의 9절](../plans/31_B_C_고도화_복수표_이중축.md)과 [계획 32](../plans/32_A_B_표별_지표_focus_제안.md)에 있음. 요약: 같은 행 반복은 B가 하나로 줄임, CV-BC-03 문구 수정, 통계표가 여럿일 때 프롬프트 규칙 추가, 표별 지표 `focus` 선택 필드 추가(A 협의 전), CV-BC-02 골든 변경.
- 표별 지표 `focus`와 프롬프트 규칙을 함께 쓰면 5건 중 2~3건이 골든과 일치하고 추가 계열이 사례당 0~1개로 줄었음. `focus` 없이는 0건 일치, 사례당 1~3개 추가였음. 규칙을 끄고 `focus`만 쓰면 1건 일치(CV-BC-03에 다시 추가 계열)였음.

## 6. 승인이 필요한 항목(B 담당)

- 5건의 질문 문구, 통계표 조합, 항목·분류 코드. 이번에 바뀐 것: CV-BC-02의 GDP 항목(원계열 전년동기비 → 계절조정 전기비), CV-BC-03 질문 문구.
- CV-BC-02의 주기 맞춤 답변(합계 사용)과 선택지 구성(평균·기말·합계·따로 보기).
- CV-BC-03의 두 통계표 항목이 같은 개념(신용카드 이용금액)인지.
- 계획 32의 `focus` 계약 제안과 A 담당 협의.

## 7. 한계

- A 단계는 골든 통계표로 대신하므로 "질문 → A → 복수 통계표 선택"은 시험하지 못함. A의 외부 키 연결 뒤 대표 질문으로 이어서 시험함.
- 합성 값 재생은 연결·정렬·표시 확인용이며 값의 정확성 근거가 아님.
- 한 질문에 주기가 명시되면 B가 모든 통계표에 같은 주기를 적용하므로, 통계표별로 다른 주기를 질문에서 직접 지정하는 경우는 현재 B가 처리하지 못함(계획 31의 한계에 기록).
- 질문에 통계표 이름의 "~별"이 있으면 B가 분해 요청으로 읽는 문제는 아직 B에서 고치지 않았음.
- 실제 HCX 시험은 사례당 한두 번 실행한 결과이며 실행마다 차이가 있음. 추가 계열이 `focus`를 주어도 사례당 0~1개 남음.
- CV-BC-02를 골든 변경 뒤 실제 HCX로 다시 돌리지는 않았음.
