# 통합 흐름 (1단계)

질문 하나가 A와 B를 거쳐 응답이 되기까지의 흐름, 판단이 있는 곳, 포트 연결, 질문→대기→재개를 적는다. 판본과 실행법은 [README](../README.md)에 있다.

## 1. 전체 순서

```text
claview_flow.FlowSession.run_question(question, as_of, decomposition)
  └─ claview_v3.agent.session.run_session(..., layer, b_port)
       └─ 바깥 그래프 "router" 변형 (claview_v3/agent/graph.py)
            START → intake → router ─┬─ interpret → router
                                     ├─ verify(V1 해석 검증) → router
                                     ├─ select → router
                                     ├─ verify(V2 선택 재검사) → router
                                     ├─ ask_user(대기) → router
                                     └─ respond → END
       └─ claview_v3.agent.b_connection.connect(state, b_port)
            ├─ 대기 중이면 B 미실행 (execution_status = awaiting_answer)
            ├─ 실행할 요구가 없으면 B 미실행 (reason = no_executable_requirements)
            ├─ 포트가 없으면 B 미실행 (reason = b_port_not_configured)
            └─ 요구 묶음마다 port(payload)
                 └─ AdapterPort (claview_flow.make_b_port가 실제 B 함수로 만든다)
                      to_b_request → check_request → run_b_request → 결과 검사 → fetch
```

## 2. 판단이 있는 곳

| 판단 | 위치 | 비고 |
|---|---|---|
| 다음에 어느 노드로 갈지 | `claview_v3/agent/session.py`의 `router_action`, `agent/nodes.py`의 `router` | 정해진 경로를 실행할 뿐 의미 규칙은 없다 |
| 질문 해석(요구·조건·관계) | `claview_v3/interpret/` | 기본은 규칙 경로. 모델 경로는 `decomposition` 설정으로만 켜고, 대화형 실행에서 `live`는 막혀 있다 |
| 표 선택과 재검사(V2) | `claview_v3/select/`, `claview_v3/verify/` | |
| 물을지, 가정하고 진행할지, 결과 없음인지 | `claview_v3/agent/question_route.py`의 `completion2_route` | 묻는 결정은 이 함수만 한다. 경로 종류: `proceed`, `assume`, `partial`, `ask`, `no_result` |
| 공개 가정(사용자에게 보이는 A 가정) | `claview_v3/agent/assumptions.py` | 판본 `a-assumptions/2026-10-21.1` |
| B에 넘길 요구와 묶음 | `claview_v3/agent/b_connection.py`의 `connect` | 관계로 묶인 요구는 함께 보낸다. 묶음 준비가 안 된 요구는 건너뛴다(`bundle_not_ready`) |
| A 상태 → B 요청 | `claview/b/adapter_v3.py`의 `to_b_request` | A 상태 모양을 아는 B 쪽 유일한 모듈 |
| B 요청·결과 계약 | `claview/b/contract.py` | 계약 `b-contract/2026-10-21.3`, 구조 판본 `structure-2026-10-21.1` |
| 계열·기간·주기 선택 | `claview/b/run.py`, `claview/stages.py`, `claview/graphs.py`, `packages/claview-period` | B 모델은 주입한다 |
| KOSIS 요청 생성·응답 정규화 | `claview/fetch.py` | 조회 클라이언트는 주입한다 |
| 연결(새 코드) | `claview_flow/` | 판단 없음. 함수를 이어 붙이고 클라이언트를 주입받는다 |

## 3. 포트 연결 (`claview_flow.make_b_port`)

- A의 `AdapterPort`에 B의 `to_b_request`, `check_request`, `check_scope_result`, `check_b_result`, `run_b_request`, `fetch_data`를 넣는다. A의 오프라인 확인 도구(`scripts/completion2_b_offline.py`)와 같은 연결이며, 합성 부분만 밖으로 뺐다.
- 포트를 만들기 전에 A의 공개 가정 판본이 B가 받는 판본(`A_ASSUMPTION_VERSIONS`)에 있는지 확인한다. 없으면 만들지 않는다.
- 요청마다 B `Services`(메타 저장소, 주입한 모델, `Config(as_of=요청의 as_of)`, 새 `Trace`)를 만든다.
- 조회 클라이언트가 없으면 KOSIS를 부르지 않고 `{"status": "not_run", "reason": "no_fetch_client", "requests": [...]}`를 남긴다. `requests`는 B가 만든 조회 요청 인자이고 키는 들어가지 않는다. 이때 A의 `execution_status`는 `completed`가 아니다.
- A는 포트를 저장하지 않는다. `FlowSession`이 매 턴(`run_question`, `answer`, `new_question`) 같은 포트를 넘긴다. B 모델이 없으면 포트를 만들지 않는다.
- A는 같은 입력(요청 내용 + 계약 판본)의 B 결과를 세션의 `b_cache`에 두므로, 같은 상태를 다시 연결해도 B를 다시 부르지 않는다.
- 실제 클라이언트는 `claview_flow.live_b_clients(allow_external=True)`로만 만든다. `True`가 아니면 거절한다.

## 4. 질문 → 대기 → 재개

1. `run_question`이 대기 경로(`ask`)로 끝나면 `response.status = "awaiting_answer"`이고 `response.question`에 선택지 ID와 이름만 보인다. B는 부르지 않는다.
2. 클라이언트는 ID만 담은 답을 보낸다: `{request_id, question_version, question_id, option_id}`. `claview_flow.make_answer(state, option_id)`가 이 모양을 만든다. 상태는 서버가 보관하고, 클라이언트가 고친 상태나 해석을 받지 않는다.
3. `answer(state, reply)`는 A의 `resume_session`을 부른다. 답이 현재 질문·판본과 맞는지 확인한 뒤 해당 요구만 다시 선택·V2 검사를 하고(해석은 다시 하지 않는다), 끝나면 포트로 B를 부른다.
4. 이미 적용한 같은 답을 다시 보내면 저장된 상태를 그대로 돌려주고 B를 다시 부르지 않는다. 다른 답·옛 판본·없는 선택지는 `response.answer_error`로 거절하고 상태를 바꾸지 않는다.
5. `new_question(state, text)`는 같은 `request_id`로 `question_version`을 하나 올려 새로 시작한다(재개가 아니다).

## 5. 시험으로 확인한 것 (`tests_flow/`)

모두 실제 349표 카탈로그, 실제 A·B 코드, 합성 B 모델·조회로 돌린다. 연결 확인이며 정확도 근거가 아니다.

| 시험 | 확인 내용 |
|---|---|
| 규칙 질문 | B 어댑터·계약·실행·결과 검사·합성 조회를 거쳐 `execution_status = completed`, B 범위 모두 `ok` |
| 가격 질문 | 대기 중 B 미호출 → 답 → 재개 턴에서 B 실행, 같은 답 재전송 시 재호출 없음 |
| 결과 없음 | B 미호출 |
| 가짜 모델 경로 | 구조 `structure-2026-10-21.1`이 B 요청에 실리고 계약 오류 없이 실행 |
| 재연결 | 같은 상태를 다시 연결해도 B 재호출 없음 |
| 조회 클라이언트 없음 | `fetch.status = not_run`, `execution_status`가 `completed`가 아님 |
| B 모델 없음 | 포트 없음, `b_port_not_configured` |
| 실호출 도우미 | `allow_external=True`가 아니면 거절 |
| 네트워크 | 시험 프로세스의 소켓 연결이 막힘 |
