# 갱신 카탈로그 대표 6문항 실호출 확인

## 결론과 범위

기존 349표 갱신 후보 `203149a1125e68f48703ac3f3dcda309d7385168`에서 A→B→KOSIS→C를 확인했다. 기준일은 비교용 `2026-10-29`이며 실제 전송은 2026-11-03에 했다. 추가 발견 34표는 활성화하지 않았다.

**6문항 중 5문항은 조회·화면 생성까지 정상, 1문항은 B 기간 해석에서 실패**했다. A의 표·기간·주기 확정은 6문항 모두 확인했고 복구·되묻기는 발생하지 않았다. 정상 5문항의 313개 관측값·시점이 KOSIS 원응답과 C 화면 데이터에서 일치한다. 이는 대표 사례 확인이며 전체 골든 정확도·독립 평가·모델 개선 수치가 아니다.

3번째 문항의 `invalid_period`에서 승인된 중단 규칙대로 멈췄다. 이후 사용자가 B 결함은 별도로 알리고 나머지를 실행하도록 지시해, **기존 중단 기록·사용량을 보존한 채 미실행 3문항만 이어 실행**했다. 실패 문항 재호출·전송 재시도는 하지 않았다. 원질문·기대값·제품 소스·메타도 실행 중 바꾸지 않았다.

## B 담당 후속: 분류 기준연도와 조회연도 혼입

재현 질문:

> 현금흐름표에서 2025년기준 C10 식료품의 당기순이익(순손실)을 2024년 연간으로 보여줘.

A의 전달 표는 `DT_501Y013`, 주기는 `Y`, 기간은 `2024-01~2024-12`, `period_phrase`는 `2024년`, `period_source`는 `quoted`다. `2025년기준`은 이 표의 기준년도구분별 분류값이며 조회 기간이 아니다.

B `stages.py`의 `stated_years`가 두 연도를 잡고 `_explicit_span`이 `(2025, 2024)`를 만든다. `explicit_period_detail`은 역전 구간으로 거절한다. 현재 A 인용 기간 대체는 `conditions_incomplete`에만 적용되므로 이 `invalid_period`는 그대로 반환된다.

저장된 실제 B 요청을 **옛 메타와 갱신 메타의 실제 BService 양쪽**에 오프라인으로 넣어 같은 오류를 확인했다. B 모델·네트워크 호출은 0이다. 메모리 대조 질문에서 분류 문구만 제거하면 양쪽 모두 2024년으로 계획된다. 따라서 기존 B 기간 파서 결함이며 카탈로그 갱신으로 생긴 A 오선택은 아니다. 옛 메타가 새 분류값을 지원하거나 전체 조회가 성공한다는 뜻은 아니다.

후속 보완은 분류 기준연도를 조회 기간에서 구분하는 것으로 범위를 잡는다. 원질문·focus·분류값은 보존하고, 모든 `invalid_period`를 A 참고값으로 덮어 통과시키지 않는다. 실제 역전 기간의 거절, 명시 조회 기간 보존, 사용자 답 우선순위도 함께 회귀 확인한다. 이번 갱신 후보에서는 이 B 로직을 수정하지 않았다.

## 화면·원응답과 확인 한계

- 현재 프론트엔드에서 실제 저장 결과를 복원해 정상 5건의 차트·수치표·요청/조회 범위와 실패 1건의 중단 위치를 확인했다. 새 질문이나 답 적용으로 모델을 추가 호출하지 않았다.
- 313값 일치는 API 응답과 화면에 넘긴 원자료의 일치다. 차트의 자리수 반올림과 원 수치표는 구분한다. 독립 공식 수치의 교차 검증은 아니다.
- CV-AB-13 특별자금의 60개 값은 실제 원응답이 모두 0이다. 결측을 0으로 채우거나 합성값을 사용한 것이 아니다.
- 광주 원화예금은 2026년 7·8월 값도 반환됐다. 해당 계열에서는 단절 의심이 확인되지 않았다. 다른 지역 18표 전체의 정의 연속성까지 확인한 것은 아니다.
- 신협 표의 개정 안내 구간에서 현재 값을 조회했다. 개정 전 실제 응답이 없어 해당 계열의 개정 전후 수치 차이는 확인하지 못했다.
- 실패한 현금흐름 사례는 B 선택·수치 조회가 실행되지 않았다. 새 `2025년기준`과 조회연도 `2024` 조합의 실제 값 존재는 미확인이다.
- 복구·되묻기가 없었으므로 이번 실호출로 그 경로를 새로 검증한 것은 아니다.
