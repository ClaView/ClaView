## Docker 전체 실행

독립 프로젝트 `claview-cleanup-1105`와 별도 이미지·포트·volume을 사용했다. 백엔드는 외부 연결이 없는 내부 네트워크, frontend만 별도 호스트 접근 네트워크에 연결했다. 시험 설정에는 합성 모드만 넣었고 실사용 키는 읽거나 복사하지 않았다.

1. backend·frontend 빌드 성공, frontend/pipeline/module-a/module-b/module-c **5개 healthy**.
2. 이미지 안에서 네 앱 import 성공. 삭제한 A 패키지와 시험·개발 스크립트·C 평가 rubric이 없는 것을 확인했다.
3. 실제 localhost frontend 포트로 HTML과 nginx→pipeline HTTP를 확인했다.
4. `예금은행 대출금리`, `가계신용`에 각각 합성 확인 식별자를 붙여 질문했다. 두 건 모두 A의 기간·주기 질문 → 답 적용 → B → 합성 조회 → C 카드까지 **ok**였다. 기본 합성 판단기는 첫 후보를 고르는 시험용이므로 자연어 정확도 시험이 아니다.
5. 요청 토큰 누락 거절, 같은 답의 중복 제출 409, 답 적용 시 A 모델 호출 0을 확인했다.
6. 저장 결과 복원 후 `ui_cases`와 `calls`가 같았다. pipeline 컨테이너 재시작 뒤에도 두 실행의 결과·호출 기록 해시가 같았으며 새 질문이나 외부 호출은 없었다.
7. 최종 이미지의 네트워크 없는 CLI에서 22문항 기록을 모두 생성했다. 상태는 ok 17, unresolved 3, needs_confirmation 2였다. **합성 실행 상태의 분포이며 17/22 정확도 점수가 아니다.**
8. 네트워크 없는 별도 컨테이너의 `live` 모드에서도 앱 import와 실행기 생성이 성공했다. 키 미설정 상태는 `openai_key_missing`으로 거절되며 합성 결과로 바뀌지 않았다. 실제 제공자 호출 시험은 아니다.

스모크는 합성 모드를 확인한 후에만 실행한다. 매번 새 시험 식별자를 사용하고 기존 질문별 호출 원장과 기록을 지우지 않는다. 원격 CI는 아직 실행하지 않았으며 로컬 검증과 구분한다.

검증 뒤 별도 시험 스택을 중지하고 재시작 복원 대조에 사용한 기록 volume을 보존한다.
