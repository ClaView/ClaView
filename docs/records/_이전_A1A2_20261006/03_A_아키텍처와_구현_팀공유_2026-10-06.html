후보 탐색과 표 확정,
현재 연결 가능한 범위

A1 후보 탐색과 A2 근거 대조·표 집합 판단을 연결한 사용자 확정형 A 초안입니다.
기본 경로와 B 전달 계약을 공유하며, 일반 자연어 자동 채택은 아직 완료되지 않았습니다.

1. 두 서브그래프와 확정 흐름

원 질문 보존
→
A1 후보 탐색규칙·사전 / 원문·보조 검색
→
A2 표 판단요구·공식 근거 / 표 집합 검증
→
사용자 확정A.tables → B

원 질문을 검색문으로 덮어쓰지 않습니다. 조건·근거·사용자 추가 답변은 별도로 관리합니다. 기본 shadow는 판단을 기록하며, 명시 auto는 제한된 공식 명칭 요구에서만 자동 확정을 허용합니다.

A1과 A2는 실제 LangGraph로 구현돼 있고 검색기·저장소를 공유합니다. A1은 후보·조건·검색 출처를 넘기며, A2 판단 이후의 확정 저장은 기존 저장 계층을 사용합니다.

한 페이지 5개는 표시 개수입니다. 필요한 표 수가 아닙니다. 한 표 안의 여러 지표는 B가 여러 계열로 처리하며, 모호하다는 이유로 대안 표를 모두 확정하지 않습니다.

3. B에 넘기는 공동 계약

원 질문과 확정 A.tables를 유지합니다. A 내부 상태를 팀 공통 스키마의 필수 확장으로 요구하지 않습니다.

{
  "tables": [{
    "org_id": "301",
    "table_id": "DT_401Y018",
    "table_name": "수입물가지수(용도별)"
  }]
}

A는 표 선택, B는 표 안의 항목·분류·기간·주기 확정을 담당합니다. 확정 전에는 B를 실행하지 않습니다. B 실패 시 A를 유지하고 B만 명시적으로 재시도합니다.

기존 에이전트의 답변 경로에서는 원문과 추가 맥락의 B 인자 처리를 통합 때 확인해야 합니다.

scripts/evaluate_a_stage6.py는 DATA와 REFERENCES의 자료·기준 기록을 추가로 요구합니다. 새 환경에 과거 기록이 있다고 가정하지 않습니다. 명령과 정확한 전달 범위는 공유 문서에 정리했습니다.

기존 정리 검수는396개 통과 기록입니다. 이후 지정 B ZIP 통합·A 분리 시에는 516 통과·2 skip을 새로 확인했습니다. A22의 정답 순위는 모두 유지됐습니다. 실제 API 호출은 없었습니다.

6. 공유 이후 A 재점검과 개선

순서검토 내용과 완료 기준
1. 현재 실행 경로CLI → A1 → A2 → 확정 → B 입력 대조. 실제 사용되는 조건·근거와 누락 구간 기록
2. A1 조건·검색조건 출처·범위·사전·보조 검색 기여 검토. 원문 보존과 정답 후보 누락 여부 확인
3. A2 근거·순위전체 통계 요구 충족과 단어 관련성 구분. Top1·Top5·누락·근거 오류를 함께 비교
4. 모델 해석 보완저장 HCX 응답의 위치 실패부터 오프라인 재현. 유효한 출력만 수용하고 실패 시 원문 복귀
5. 표 집합·확인단일 표 복수 계열·다중 표·대안·부분 충족 구분. 자동 정확도와 자동 비율을 함께 보고
6. B 연결 대조지정 ZIP의 모의 인계·대기 저장은 확인. 실제 B 의미·통계 조회·확인 답변 후 재개는 별도 검증

각 기능을 따로 비교하고 기존 정책으로 돌아갈 수 있게 합니다. 구조화·순위·자동 채택 개선을 하나의 성공으로 묶지 않습니다. 임베딩·리랭커·JEV는 남은 실패 유형을 확인한 뒤 별도 실험으로 판단합니다.

A1/A2 구조와 기본 정책을 유지하며 겹치는 A 코드를 분리하고 B ZIP을 통합했습니다. 기간 확인 대기는 저장·재시작 시 재사용하지만 확인 답변 후 B를 재개하는 기능은 아직 없습니다. 위 품질 개선과 실제 호출 검증은 후속 작업입니다.
