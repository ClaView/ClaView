# A 1차 구현과 팀 연결 안내

2026-10-06 1차 공유 기준. **A1 후보 탐색과 A2 근거 대조·표 집합 판단을 연결한 사용자 확정형 A 초안**입니다. 팀원은 이 요약과 B 전달 계약·실행 안내부터 읽으면 됩니다. 일반 자연어의 자동 표 선택 완성을 뜻하지 않습니다.

후속 반영: 지정 B ZIP을 통합하고 겹치던 A 구현을 `a_stages.py`, `a_graphs.py`로 분리했습니다. 공통 의존성은 `services.py`에서 공유합니다. B 구조 검토·담당 파일·재현 명령은 [A/B 통합 검수](../../modules/b/research/A_B_분리와_B_통합_검수_2026-10-06.md)에 정리했습니다.

## 현재 동작

**원 질문 → A1 후보 탐색 → A2 근거 대조·표 집합 판단 → 사용자 확정 → A.tables → B**

A1은 원문을 보존하고 규칙 조건·사전을 이용해 원문과 보조 표현을 검색합니다. A2는 필수 요구와 공식 메타를 대조하고 필요한 표 집합을 판단합니다. 기본 shadow에서는 사용자 선택을 기다립니다. 한 페이지5개는 후보 표시 수이며 표 선택 개수와 다릅니다.

auto는 제한된 공식 명칭 요구에만 적용하는 실험 옵션입니다. 일반 자연어 자동 채택은 아직 검증하지 못했습니다. 한 표 안의 여러 지표는 B가 여러 계열로 처리하고, 실제로 여러 표가 필요한 요구만 복수 표로 확정해야 합니다.

| 구분 | 현재 맡는 기능 | 내부 출력과 연결 |
|---|---|---|
| A1 후보 탐색 | 원문 보존, 규칙 조건·사전 적용, 원문·보조 검색 | 후보군·질문 조건·검색 출처를 A2로 전달 |
| A2 표 확정 | 공식 근거 대조, 필요한 표 집합 제안·검증, 자동/사용자/미확정 분기 | 기본은 사용자 확인 대기. 확정은 기존 저장 계층을 통해 A.tables로 반환 |

두 서브그래프는 실제 LangGraph로 구현돼 있습니다. 검색기·저장소를 공유하며, A2 판단과 확정 저장의 책임은 분리돼 있습니다. 사전 적용 코드가 있다는 사실과 사전이 운영 승인됐다는 사실도 구분합니다.

## 팀 공통 계약

원 질문과 확정 표 목록을 유지합니다. A 내부 조건·검색 출처·근거·답변·저장 상태를 공통 스키마의 필수 확장으로 요구하지 않습니다.

```json
{"tables": [{"org_id": "301", "table_id": "DT_401Y018", "table_name": "수입물가지수(용도별)"}]}
```

A는 표 선택, B는 표 안의 항목·분류·기간·주기 확정을 담당합니다. 확정 전 B를 실행하지 않습니다. B 실패 시 A는 유지하고 B만 명시 재시도합니다. 기존 에이전트의 사용자 답변 경로에서는 원문과 추가 맥락의 B 인자 처리를 통합 때 확인해야 합니다.

## 실행을 위해 전달할 파일

코드 전달은 현재 저장소 구조를 유지합니다. A1/A2 파일 두 개만 떼어 주면 검색·메타·저장·그래프 의존성이 빠집니다. 새 ZIP·배포본을 만들거나 저장소를 게시한 상태는 아닙니다.

| 구분 | 전달 범위 | 주의점 |
|---|---|---|
| 실행 코드·설정 | src/claview/, pyproject.toml, uv.lock, .python-version, .env.example, .gitignore, AGENTS.md, README.md | .env.example은 변수 이름 안내용. 실제 .env는 전달하지 않음 |
| 실행·검증 도구 | scripts/, tests/, docs/ | fixtures 포함. 모의 B 결과는 실제 모델 정확도 자료가 아님 |
| 공유 자료 | data/catalog/, data/mappings/, data/samples/ | 목록·정의·실행 사전·검수 원천. draft를 승인으로 취급하지 않음 |
| 평가·시험 자료 | eval/cases/, eval/configs/, eval/a_stage2_metric_policy.json | 기존22가 현재 평가 기준. 추가48과 기타 초안은 계약/기능 시험 전용 |
| 전체 검색용 별도 자료 | data/raw/boK_meta_raw.jsonl | Git 제외이므로 전달 여부·해시 확인 필요. 없으면 3표 fixture 기능 시험만 가능 |
| 선택적 재현 근거 | 최근 평가 JSON·시험 XML, 6개 설정 평가가 참조하는 기준 기록 | runs 전체와 후보 DB·실제 모델 trace를 일괄 공유할 필요는 없음 |

396개 오프라인 시험 통과 기록과 정리 전후 비교는 검수 문서 (원본 저장소 보관 자료·공유본 제외)에 있습니다. 이번 공유에서 다시 실행한 수치로 표현하지 않습니다. 실제 .env·키·인증 헤더·가상환경·캐시·개인 보관 자료는 공유 대상에서 제외합니다.

이후 A/B 분리·B ZIP 반영 시에는 **516 통과·2 skip**을 새로 확인했습니다. A 기존22의 정답 순위는 모두 유지됐습니다. B 확인 대기는 저장·재시작까지 연결됐지만 확인 답변 후 재개는 아직 구현되지 않았습니다.

새 환경의 1차 평가에는 아래 단일 검색 평가를 사용합니다. 전체 메타와 기존22가 필요하지만 과거 runs 기록은 필요하지 않습니다. .env가 없는 오프라인 환경은 --env-file .env를 생략합니다.

```powershell
$shareEval = "runs/share-check-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
uv run --env-file .env --locked claview evaluate-search --cases eval/cases/golden_set_v1.json --db "$shareEval/candidates.sqlite3" --as-of 2026-10-02 --retrieval-policy baseline --document-profile legacy --mapping-policy approved --a-agent-mode off --output "$shareEval/evaluation.json"
```

scripts/evaluate_a_stage6.py로 과거와 같은 6개 설정 통합 평가까지 재현하려면 해당 도구의 DATA와 REFERENCES에 열거된 자료·기준 기록을 상대 경로 그대로 추가 준비합니다. 코드만 받은 환경에서 이 기록까지 존재한다고 가정하지 않습니다.

## 공유 이후 A 재점검과 개선 순서

| 순서 | 검토·변경 범위 | 완료 기준 |
|---|---|---|

| 2. A1 조건과 보조 검색 | 조건 추출 누락·범위 혼합, 승인 사전의 적용 범위, 원문 후보 보호와 보조 검색 기여 검토 | 원문 보존, 조건 출처 검증, 기존22 후보 누락·순위 변화와 기능 시험을 분리 보고 |
| 3. A2 근거와 표시 순위 | 전체 요구의 제공 여부와 단어 관련성 구분, 상위 오답의 원인, 근거가 순위에 쓰이는 위치 검토 | Top1·Top5를 함께 비교하고 누락·불필요 후보 증가 및 근거 오류를 설명. 점수를 정답 확률로 취급하지 않음 |
