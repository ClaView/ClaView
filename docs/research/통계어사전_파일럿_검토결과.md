## 2. CSV에서 확인한 집계

### 용어 우선순위

| 항목 | 결과 |
| --- | ---: |
| 데이터 행 / 고유 공식어 문자열 | 5,887 / 5,887 |
| 우선순위 1 / 2 / 3 / 제외 | 1,086 / 1,210 / 3,145 / 446 |
| 유형: 항목값 / 표명 / 목록분류 / 분류축 / 단위 | 5,540 / 231 / 77 / 29 / 10 |
| 핵심어가 빈 행 | 128 |
| 유사어_일상어·검토자·상태가 빈 행 | 각 5,887 |
| 예시tblId 고유 개수 | 337 |

`예시tblId`는 모두 저장소의 349개 표 목록에 존재합니다. 이는 ID 존재 검사이며, 해당 표의 메타에 용어가 실제로 있는지까지 검증한 결과는 아닙니다. 예시 ID가 337개라는 이유로 나머지 12개 표가 추출에서 빠졌다고 판단할 수 없습니다. 용어별 예시 표 하나만 기록되어 있기 때문입니다.

`제외` 446행의 분류사유는 `산업분류코드→코드매핑 별도`입니다. 일상어 후보 작성 우선순위에서 구분한 것이며 프로젝트 대상에서 표를 제외한다는 뜻이 아닙니다.

노션의 추출 6,046행은 중복 정리 전 보고값입니다. 현재 우선순위 CSV는 5,887개 공식어 문자열 목록이므로, 두 자료의 유형별 개수를 같은 집계로 비교하지 않습니다. 문자열별 유형 선택·중복 통합 규칙은 추출 원본과 코드로 확인해야 합니다.

### 일상어 후보

| 항목 | 결과 |
| --- | ---: |
| 후보 행 | 136 |
| 후보가 남아 있는 공식어 문자열 | 35 |
| 고유 일상어후보 문자열 | 125 |
| 원본 판정: 자동채택 / 검토 / 폐기후보 | 18 / 68 / 50 |
| 자기매칭: Y / N | 65 / 71 |
| 직접유사도 최솟값 / 최댓값 | 0.373 / 0.894 |
| 동일 공식어·후보 쌍의 중복 | 0 |
| 두 개 이상의 공식어에 연결된 후보 표현 | 11 |

후보의 공식어 35개와 최근접공식어는 모두 우선순위 CSV에 존재합니다. 후보 행의 유형·빈도도 우선순위 CSV와 일치합니다. `자기매칭`은 공식어와 최근접공식어의 문자열 일치 여부와 136행 모두 일치합니다.

두 CSV에서 열 개수 불일치, 완전히 같은 행의 중복은 발견하지 못했습니다. 빈도는 모두 1~349의 정수입니다. 실제 표별 출현 빈도는 추출 원본이 없어 재계산하지 않았습니다.

## 3. 노션 설명과 구분할 사항

| 항목 | 확인 결과 | 후속 확인 |
| --- | --- | --- |
| 입력 공식어 40개 | 노션 보고. CSV 출력에는 35개 공식어가 있음 | 입력 목록·실패·필터링·빈 결과 로그 확인. 원인 추정으로 5개를 채우지 않음 |
| 저유사도 검토 50건 | CSV 실제 값은 `폐기후보` 50건 | 코드·문서 버전과 명칭 변경 여부 확인. 원본 값은 보존 |
| 자동채택 18건 | 자동 분류 결과이며 정답률이나 승인 건수가 아님 | 사람의 관계·조건 검수 필요 |
| 첫 실험보다 개선 | 서로 다른 용어 집합으로 진행했다는 노션 보고 | 동일 입력·평가 기준 비교 전에는 성능 개선 수치로 사용하지 않음 |

현재 136행은 `직접유사도 ≥ 0.8이며 자기매칭 Y → 자동채택`, `직접유사도 < 0.6 → 폐기후보`, `나머지 → 검토`라는 분류와 모두 일치합니다. 저장된 점수와의 대조 결과이며 실제 코드 구현·원점수 정밀도·임계값의 타당성을 검증한 것은 아닙니다.

## 4. 우선 검토할 사례

아래는 CSV에서 찾은 검토 대상입니다. 공식 정의와 표별 조건을 대조하기 전의 지적이며, 승인·기각 결과를 CSV에 반영하지 않았습니다.

| 공식어 → 후보 | 점수 / 원본 판정 | 확인할 내용 |
| --- | --- | --- |
| 정기예금 → 정기적금 | 0.886 / 자동채택 | 서로 다른 상품 구분을 동의어로 합치지 않는지 |
| 주택담보대출 → 담보 대출 | 0.871 / 자동채택 | 주택이라는 대상 조건이 사라지는지 |
| 대출기관수별 → 기관별 대출 현황 | 0.860 / 자동채택 | 기관의 개수 구분과 기관별 구분을 혼동하는지 |
| 양도성예금증서 → CD | 0.377 / 폐기후보 | 약어를 낮은 유사도만으로 버리는지 |
| 환매조건부채권매도 → RP 매도 | 0.585 / 폐기후보 | 약어와 거래 방향을 함께 확인하는지 |
| (1) 한은대출금 → 한은에서 빌린 금액의 이자 | 0.697 / 검토 | 대출금과 이자를 같은 값으로 연결하는지 |
| 매출채권 → 외상매출금 | 0.557 / 폐기후보 | 관련·포함 관계인지 동일 개념인지 정의로 확인하는지 |

`목돈 예치`, `외상값`, `금융권 대출` 등은 둘 이상의 공식어에 연결되어 있습니다. 단순 중복 삭제보다 문맥·조건과 관계 유형을 먼저 확인해야 합니다. `(2) 현금통화`와 `현금통화`처럼 번호가 다른 표현도 있으므로, 자기매칭 N 전체를 의미상 오연결로 계산하지 않습니다.

## 5. 다음 검수에 필요한 자료

1. 후보 생성에 넣은 공식어 40개의 목록과 필터링·실패 기록.
2. 생성·임베딩 코드, 모델/API 경로, 프롬프트, 점수·판정 규칙, 실행 시점. 키 값은 공유하지 않음.
3. 용어 추출 원본과 공식어별 전체 출처: 기관·표·항목·분류 코드, 메타 버전.
4. 기존 `term-mappings.json`은 [검토용 의미 매핑](../../data/mappings/review/검색용_의미매핑_초안.json)으로 확보했습니다. 현재 두 CSV와 중복·관계·조건을 대조해 승인 기록을 연결해야 합니다.
5. 추가 제안된 역방향 순위 방식의 행별 비교 결과, 실행 코드, 비교 대상 집합, 사람 판정. 이번 CSV 집계는 이전 방식의 기록이며 역방향 실험 결과로 대체하지 않습니다.

현재 후보 CSV에는 표 ID·항목·분류 코드가 없고, 우선순위 CSV에는 예시 표 ID만 있습니다. 두 파일을 공식어로 연결해도 실제 조회 가능한 계열 매핑이 완성되는 것은 아닙니다.

후보 136행의 관계와 적용 범위를 검토한 뒤 승인·보류·기각 기록을 별도로 작성하는 안입니다. 이 검토 결과와 대표 질의 평가가 나오기 전에는 자동 승인 규칙이나 모델 선정을 확정하지 않습니다.

## 6. 스냅샷 보존과 재확인

두 CSV는 `data/mappings/review/`에 원본 바이트 그대로 보존했습니다. 검토용 파일이며 검색·색인에 자동 반영하지 않습니다. 신규 생성물은 별도로 저장하고, 이 스냅샷을 바꾸면 해시·검토 결과를 함께 갱신합니다.

| 파일 | 바이트 | SHA-256 |
| --- | ---: | --- |
| 통계어사전_우선순위.csv | 581895 | `8f3a115862846a16da4124a0419e5e5ee4377233fbcad7768c50a1e437f76c49` |
| 통계어사전_후보.csv | 12083 | `b90080dd44f6db30f42946073b2d919f0db09790c11d94a1f37899bd2723d4c5` |

검토일은 API 수집·후보 생성 시각을 의미하지 않습니다. 재확인 시 UTF-8 BOM 허용, 쉼표 구분, ID·용어는 문자열로 읽습니다. CSV 헤더를 제외한 행 수로 집계합니다.

저장소 루트에서 간단한 집계를 재확인할 수 있습니다. 외부 API를 호출하지 않습니다.

```sh
uv run --locked python -c "import csv,collections; p=list(csv.DictReader(open('data/mappings/review/통계어사전_우선순위.csv',encoding='utf-8-sig',newline=''))); c=list(csv.DictReader(open('data/mappings/review/통계어사전_후보.csv',encoding='utf-8-sig',newline=''))); print('priority rows / unique terms:',len(p),len({r['공식어'] for r in p})); print('candidate rows / official terms / expressions:',len(c),len({r['공식어'] for r in c}),len({r['일상어후보'] for r in c})); print(collections.Counter(r['판정'] for r in c))"
```
