# 설계 결정·미확정 사항 검토

- 담당: 팀 공동 결정, 정리: 채진현
- 정리일: 2026-09-22
- 상태: 공통 규격 검토 중
- 근거: [수행 범위](../project/프로젝트_범위와_처리원칙.md), [처리 구조](../architecture/처리흐름과_기능별_책임.md), 팀 공통 규격 초안 검토

## 확인된 방향

- KOSIS 내 한국은행 소관 통계표 전체를 대상으로 합니다.
- 원자료는 API, 파생값은 코드 계산을 사용하고 출처·조건·가공 기록을 남깁니다.
- Python 3.12와 uv를 기준으로 환경을 준비합니다. 패치 버전의 팀 공통 고정은 별도 합의 대상입니다.
- 공통 규격과 골든셋은 작은 사례로 검토하고 구현 과정에서 보완합니다.

## 공통 규격 확정 전 확인할 내용

| 항목 | 검토 방향 | 필요한 근거 |
| --- | --- | --- |
| 모호한 질문 | 의미가 바뀌는 조건 확인, 기본값 적용 사실 표시 | 실제 후보와 대화 사례 |
| 검색 실패 | 미적중·불확실·범위 밖·API 오류 구분 | 실패 사례와 검색 기준선 |
| 복수 계열 | 단일 선택 객체만으로 제한하지 않기 | 단일 표 복수 계열·복수 표 예시 |
| 원본 수치 | DT 문자열·결측 상태와 숫자 해석값 분리 | 실제 응답·특수 기호 사례 |
| 단위 추정 | 공식 확인과 추정 구분, 검증 전 확정 금지 | 메타·자료·원표 대조 |
| 주기·기간 정합 | 집계 의미·손실 기록, 무조건 보간/절단 금지 | 구조별 비교 사례 |
| 변경 이력 | 수집 시각·공표 시각·적용 시점 구분 | 메타 변경 사례 |

미확정 정책: 기본 기간, 확인 횟수, 검색 임계값, 단위 추정 허용 범위, 주기 변환, 부분 결과 처리. 사례·기준선 검토 후 결정합니다.

## 멘토에게 확인할 질문 후보

1. 전체 목록·메타 확보와 실제 자료 조회 검증에서 각각 기대하는 완료 수준은 무엇인가요?
2. 단위가 메타 응답에 없어 추정이 필요한 경우, 검수 전 미확인으로 관리하는 방향이 적절한가요?
3. 의미가 달라지는 조건은 조회 전에 확인하는 상호작용 방향이 적절한가요?
4. 골든셋에서 반드시 포함할 구조·질의 유형과 최소 검증 수준은 무엇인가요?
5. MCP 서버·외부 클라이언트 연동의 최소 시연 수준은 무엇인가요?
6. 제공 키의 모델 권한, QPM/TPM, 비용 지원 범위·기간·팀 합산 한도는 어떻게 되나요?
7. 제공 검색·응답 도구는 비교 후 선택할 수 있는 리소스인가요?

답변 상태: 미확인. 일정·담당·질문 제출 여부는 노션에서 관리합니다.

## 결정 기록 양식

```text
상태: 제안 / 검토 중 / 합의됨 / 대체됨
결정일·참여자:
문제와 선택지:
결정 및 근거:
영향받는 문서·코드·테스트:
검증 결과 또는 남은 확인:
재검토 조건:
관련 회의·이슈·PR:
```

노션 회의록에는 논의 과정과 업무를, 이곳에는 구현에 반영할 결정과 이유를 연결합니다. 결정 변경 시 기존 문장을 조용히 덮어쓰지 말고 이유·날짜·영향 범위를 남깁니다.
