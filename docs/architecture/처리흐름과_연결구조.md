# 처리 흐름과 연결 구조

- 관리: 팀 공동 / 정리일: 2026-09-23
- 상태: 구현 전 설계 초안. 2026-09-23 노션 공통 규격과 골든셋 5건을 대조했습니다. 폴더가 존재하는 것과 기능 구현 완료는 구분합니다.
- 관련: [개발계획](../project/프로젝트_개발계획.md), [공통 입출력 초안](공통_입출력규격_초안.md), [평가](../evaluation/골든셋과_평가계획.md)

## 1. 전체 처리 흐름

```text
목록·메타 수집 → 검수·버전 관리 → 용어 매핑·검색 문서·색인
                                            ↓
질문·대화 이력 → 조건 해석 → 표·계열 후보 검색 → 메타·조건 검증
                                                   ├─ 모호: 확인 질문
                                                   │        → 답변 반영 → 재검증
                                                   ├─ 불확실·불가·오류: 원인별 안내
                                                   └─ 확정: 조회 계획
                                                            → 자료 조회·검사
                                                            → 필요한 정합·병합·계산
                                                            → 표·그래프
                                                            → 근거 설명·결과
```

새 답변으로 대상·기간·기준이 바뀌면 영향받는 후보·조회·가공·출력을 다시 검증합니다. 이전 결과가 현재 조건의 결과처럼 남지 않도록 합니다.

데이터 준비는 질문마다 전체 목록을 다시 수집하는 과정이 아닙니다. 검수한 메타·매핑·색인을 버전별로 준비하고 검색에 사용하되, 후보의 조회 가능 조건은 수집 시점·변경 여부를 고려해 검증합니다. 갱신 주기와 캐시 정책은 미확정입니다. 검토용 별칭 후보를 승인된 매핑처럼 자동 반영하지 않습니다.

실행 경로와 별도로 각 단계의 입력·출력·오류·사용 버전을 기록합니다. 평가는 이 기록을 정답과 비교하는 과정이며, 매 사용자 요청에서 전체 골든셋 평가를 실행하는 단계가 아닙니다.

## 2. 실행 경로

```text
자체 화면 → 자체 에이전트 ─┬─ 공통 기능 직접 호출
                          └─ MCP 클라이언트 경유 → MCP 서버 → 공통 기능
외부 MCP 클라이언트 ────────────────────────────→ MCP 서버 → 공통 기능

공통 기능 → KOSIS 클라이언트 → KOSIS API
검색·에이전트의 모델 사용 → NCP 클라이언트 → NCP API
```

자체 에이전트의 직접 호출과 MCP 경유는 선택 가능한 연결안입니다. 두 경로를 모두 필수 구현으로 확정한 것은 아닙니다. 외부 클라이언트 연동은 필수 결과물이며, 어떤 경로든 같은 공통 통계 기능을 사용합니다.

- MCP 서버는 도구 입출력 검사와 공통 기능 연결을 담당합니다.
- 자체 에이전트는 질문·대화 상태·실행 순서·설명을 담당합니다.
- 외부 클라이언트의 대화와 자체 에이전트의 대화 상태는 자동 공유된다고 가정하지 않습니다.
- 화면은 입력·확인·표시를 맡고 조회·가공 로직을 중복 구현하지 않습니다.
- LLM이 제안한 도구명·인자는 코드에서 검증한 뒤 실행합니다.

전체 폴더와 기능별 책임은 [README](../../README.md)를 기준으로 관리합니다.

## 3. 기능 간 인계 지점

| 인계 | 넘길 정보 | 다음 단계의 검사 |
| --- | --- | --- |
| 메타 → 검색 | 표·항목·분류·정의·주석·버전 | 누락·분할 단위·유효 코드 연결 |
| 검색 → 에이전트 | 후보·구별 조건·검색 근거·점수 종류 | 의미가 바뀌는 조건, 사용자 의도와 후보 차이 |
| 에이전트 → 조회 | 확정한 계열별 코드·기간·주기 | 기관·표·축·선택값·조회 가능 조건 |
| 조회 → 가공 | 원 응답·해석값·결측 상태·단위·조회 근거 | 시점·기준·단위의 비교 가능성 |
| 가공 → 시각화 | 출력용 자료·계열 식별자·가공 기록 | 값·축·단위·레이블의 일치 |
| 조회·가공·시각화 → 설명 | 검증한 결과·근거·경고 | 근거 없는 수치·해석 추가 여부 |
| 각 단계 → 평가 | 입력·출력·조건 버전·오류·측정값 | 해당 단계의 기대 결과와 비교 |

필드 수준의 내용은 공통 입출력 초안에서 관리합니다. 후보 점수나 모델의 자체 신뢰도를 정답 확률로 취급하지 않습니다.

현재 확보한 기본 검색 문서·상세 문서·매핑은 이 흐름의 입력 초안입니다. 상세 문서의 코드가 비어 있으므로 ‘검색 문서 확보 → 조회 계획 확정’으로 단계를 건너뛰지 않습니다. [공통 규격의 필드 대응](공통_입출력규격_초안.md#검색-자료에서-받을-정보와-변환-경계)대로 후보·관찰 근거를 전달하고 실제 메타로 조회 조건을 검증합니다. 개발 질문의 `negative` 유형도 실패 상태로 직접 변환하지 않습니다.

### LLM과 코드의 책임

- LLM: 표현 해석, 근거가 있는 후보의 차이 설명, 확인 질문·최종 설명 작성에 활용하는 안입니다.
- 검색 기능: 메타·검수한 용어 매핑에서 후보와 출처를 반환합니다. 최종 조회 조건 확정과 구분합니다.
- 코드: 공식 코드·조합·기간 검사, API 통신, 원값 보존, 합의한 계산·정합, 출력 검사를 담당합니다.
- 에이전트: 미확정 조건과 실행 상태를 보고 다음 기능을 선택합니다. LLM 제안을 그대로 API 인자로 사용하지 않습니다.

검색 기능 안에 LLM을 둘지, 에이전트에서 질문 해석·되묻기를 담당할지는 세부 구현 선택입니다. 어느 쪽이든 후보 검색 결과와 사용자 확인 결과를 구분해 기록합니다.

## 4. 정합·실패 처리 원칙

- 정합·병합은 질문에 필요한 경우에만 수행합니다.
- 같은 단위라도 신규취급액·잔액처럼 통계 기준이 다르면 서로 다른 계열입니다.
- 주기 변환은 통계 의미에 맞는 합계·평균·말값 등 근거가 있을 때만 적용합니다.
- 기간 교집합 절단·보간·재기준화를 일괄 기본값으로 두지 않습니다. 제외된 자료와 처리 이유를 남깁니다.
- 검색 미적중과 범위 밖, 유효 조회의 빈 결과와 API 오류를 구분합니다.
- 원인이 확인되지 않은 오류를 모두 일시 장애로 안내하지 않습니다.
- 일부 계열 실패는 누락 범위를 표시하고 전체 요청 성공과 구분합니다.
- 차트만 실패하면 검증된 표를 제공할 수 있습니다. 필수 차트 과업의 평가까지 자동 성공으로 바꾸지는 않습니다.
- 재시도·도구 반복에는 상한과 중단 조건을 둡니다. 구체적 횟수는 미확정입니다.

## 5. 구현·검증 순서

대표 정상 사례에서 공통 입출력을 먼저 연결하고, 같은 구조에 조건 확인·조회 오류·부분 결과를 추가합니다. 모델 호출을 넣기 전에는 고정 응답으로 기능 경계를 시험할 수 있습니다.

도구 자체, MCP 연결, 에이전트의 도구 선택은 별도 시험합니다. 한 단계 통과가 전구간 성공을 뜻하지 않습니다. 공통 규격을 바꾸면 연결된 예시·테스트·평가 판정을 함께 확인합니다.

### 골든셋 5건으로 연결 확인하기

아래는 실행 순서를 검토하는 표이며 실제 드라이런 통과 결과가 아닙니다. 질문·정답 조건은 [골든셋 초안 5건](../../eval/goldenset/골든셋_초안_5건.md)에서만 수정합니다.

| 사례 | 확인할 연결 | 빠지면 안 되는 정보 |
| --- | --- | --- |
| CV-G001 · 경제심리지수 | 해석 → 검색 → 계열 검증 → 조회 | 원계열 구분, 2024년 월별 조건, 메타·응답 버전 |
| CV-G002 · 주담대 | 용어 확장 → 공식 항목 연결 → 조회 | 주택담보대출 선택 근거, 가계대출 전체와 구별되는 코드 |
| CV-G003 · 카드 사용 | 후보 탐색 → 확인 질문 → 후속 답변 → 재검증 | 누락 조건, 질문·답변 연결, 새 조건 버전, 구매 금액 선택 |
| CV-G004 · 두 금리 비교 | 복수 선택 → 각 계열 조회 → 시점 정렬 → 표시 | 두 계열 각각의 코드·원값·근거, 기준 차이·누락 내역 |
| CV-G005 · 범위 밖 | 범위 근거 확인 → 안내 | 범위 판정 이유, 조회하지 않았다는 기록, 임의 수치 없음 |

모호 사례를 다룰 때는 다음 순서로 정보가 이어지는지 확인합니다.

```text
원 질문·미확정 조건 보존
→ 메타 후보를 근거로 확인 질문 생성
→ 사용자 후속 답변을 원래 조건과 결합
→ 조건 버전 갱신, 영향받는 후보·코드 재검증
→ 필요한 조건이 채워진 경우 조회
→ 같은 조건 버전의 결과·출처 제공
```

추가로 조회 오류·자료 없음·부분 성공은 모의 응답으로 연결 시험을 설계합니다. 이들은 현재 골든셋 5건에 없는 추가 시험이며, 정상 자료 조회 검증을 대신하지 않습니다.

## 6. 다음 작업과 근거

1. 위 5건으로 기능 담당자가 입력·출력·중단 지점을 함께 확인합니다.
2. 공통 규격의 최소 필드와 미확정 정책을 구분해 합의합니다.
3. 실제 메타·코드로 조회 사례를 검수한 뒤 공통 모델·고정 샘플·계약 테스트를 구현합니다.
4. 검색·조회·가공 기능을 연결하고, 선택한 자체 실행 경로와 외부 MCP 클라이언트 경로를 각각 시험합니다.

- [공통 입출력 규격](공통_입출력규격_초안.md): 필드·상태·근거 전달의 기준 초안.
