- 담당: 채진현 / 팀 공동 검토
- 정리일: 2026-09-22
- 상태: 설계 초안, 도구 계약·기술 스택 미확정
- 근거: [프로젝트 범위](../project/프로젝트_범위와_처리원칙.md), 제출 제안서 v0.7, 통합 구조도 v0.1, 팀 기능 분해 논의

## 전체 흐름

```text
전체 목록·메타 수집 → 검수·이력 → 검색 문서·용어 매핑·색인
                                         ↓
질문 → 조건 해석 → 후보 검색 → 실제 메타·조건 검증
                              ├─ 모호: 확인 질문 → 응답 반영 → 재검증
                              ├─ 미적중/범위 밖/오류: 원인별 안내
                              └─ 확정: 조회 계획 → API 조회
                                                     ↓
                      결과·근거 ← 표/그래프 ← 필요한 정합·병합
```

## 기능 책임과 저장소 연결

| 기능 | 입력 → 책임 → 출력 | 구현 위치 |
| --- | --- | --- |
| 데이터 준비 | 목록 → 메타 수집·검수·이력 관리 → 검색/조회 근거 | `src/claview/backend/metadata` |
| 질문 해석·확인 | 질문·후보 → 조건 추출·의미 확인 → 확정/미확정 조건 | `src/claview/agent` |
| 표·계열 검색 | 질문·매핑·메타 → 후보 회수 → 표·항목·분류 후보 | `src/claview/backend/retrieval` |
| 자료 조회 | 검증된 계획 → KOSIS 호출 → 원 응답·조회 기록 | `src/claview/backend/kosis` |
| 정합·병합 | 계열·메타 → 코드 기반 정렬·변환 → 가공 자료·기록 | `src/claview/backend/processing` |
| 시각화·설명 | 자료·질의 의도·근거 → 표/차트 생성 및 설명 | `backend/presentation` + `agent` |
| 흐름 제어·MCP | 상태·검증 결과 → 분기·도구 실행·오류 처리 | `agent` + `mcp_server` |
| 평가 | 질의·정답·실행 기록 → 단계별/E2E 판정 | `eval` + `tests` |

축약된 경로의 `backend`, `agent`, `mcp_server`는 `src/claview` 아래입니다.

## 실행 구조

```text
자체 화면 ─ 에이전트 ─ MCP 서버 ─ 공통 통계 기능 ─ KOSIS 클라이언트 ─ KOSIS API
               │           │            │
        대화 상태·모델   외부 클라이언트   메타·색인·원자료·가공 결과

평가 실행기: 공통 기능 / MCP 도구 / 전체 에이전트를 구분해 시험
```

- 에이전트: 질문 해석, 후보 비교, 확인 질문, 실행 순서, 최종 설명 관리
- MCP 서버: 도구 입출력 검증, 공통 기능 실행, 결과·오류 반환
- 공통 기능: 검색, 상세 메타 확인, 조회, 계산·병합, 차트 생성·수치 검사
- 화면: 질문·확인 답변 입력과 결과 표시
- 외부 클라이언트: 공개한 도구를 호출하고 호스트에서 대화·실행 순서 관리

자체 에이전트와 외부 클라이언트가 같은 공통 기능을 사용합니다. 외부 도구 호출에서 자체 대화 상태를 재개하는 기능은 별도 설계 대상입니다. LLM이 제안한 도구·인자는 코드에서 검증한 뒤 실행합니다.

## 앞뒤 기능이 주고받을 정보

| 묶음 | 필요한 정보 |
| --- | --- |
| 요청 | 추적 ID, 원 질문, 확인 질문·답변 이력 |
| 선택 | 복수 계열 목록, 표 ID·항목·분류 코드, 기간·주기·단위·통계 기준 |
| 조회 | 실제 파라미터, 조회 시각, 메타 버전, 원 응답 식별자 |
| 자료 | 원본 DT 문자열, 숫자 해석 결과, 결측·특수 기호 상태 |
| 가공 | 규칙·수식, 적용 계열, 전후 단위, 제외 기간·사유 |
| 결과 | 표/차트 자료, 출처, 가공 기록, 경고, 다음 행동 |

필드명·형식은 정상·모호·불가 사례를 연결한 뒤 확정합니다. 조건 변경 시 영향을 받는 조회·가공·출력은 다시 생성합니다. 큰 자료는 참조 ID로 전달하고, 외부 클라이언트가 사용할 수 있는 접근 방식과 유효 기간을 정합니다.

## 안전한 정합·실패 처리

- 같은 단위여도 통계 기준이 다르면 동일 계열로 취급하지 않습니다.
- 월·분기 변환은 합계·평균·말값 중 통계 의미에 맞는 규칙을 정한 경우에만 수행합니다.
- 단위가 다르다는 이유로 무조건 단위를 통일하거나 이중축을 사용하지 않습니다.
- 기간 절단·보간·재기준화는 자동 기본값으로 두지 않고 필요성·손실을 기록합니다.
- 검색 점수만으로 범위 밖을 판정하지 않습니다. 요청 실패를 자료 없음으로 바꾸지 않습니다.
- 복구·재시도의 조건과 횟수는 명시하며 무한 재시도하지 않습니다.
- 일부 계열만 확보한 결과는 누락 범위와 함께 표시합니다. 차트 생성만 실패하면 검증된 자료를 표로 제공하고, 자료 자체 오류는 조회·가공 단계에서 처리합니다.

검증할 조건은 [데이터 준비](../data/메타정보_검수와_검색준비.md), [설계 검토](../decisions/설계결정과_검토사항.md), [평가 초안](../evaluation/골든셋과_평가계획.md)에 연결합니다.
