# 31. B·C 고도화: 복수 통계표 결합과 이중 축

> 2026-10-27: 모듈 구조(`modules/`·`pipeline/`·`frontend/`)로 옮기면서 본문의 파일 경로를 지금 위치로 고쳤다. 6절과 9.1절의 시험 수치는 작업 당시(옛 `src/claview/`·`tests/` 구조)의 결과다.


작성일: 2026-10-26

## 1. 목적

- 두 개 이상의 통계표에서 각각 조회한 지표를 하나의 차트로 함께 보여준다.
- 기준 기간·단위·주기가 다른 지표를 B가 정렬 기준을 정해 C로 넘긴다.
- C에서 이중 축 차트(예: 왼쪽 금액, 오른쪽 증감률)를 표시한다.

## 2. 결정 사항

| 번호 | 항목 | 결정 |
|---|---|---|
| 1 | 정렬 방식 | 절충안. B가 기준을 정하고 근거를 기록, 결정적 코드(`claview_b.align`)가 계산, 원값 보존, C는 표시만 함 |
| 2 | 환율 환산 | 1차 제외. 원/달러는 환산하지 않고 이중 축 분리 또는 안내 |
| 3 | 증감률 | 1차는 KOSIS가 제공하는 증감률 항목만 사용. 금액에서 직접 계산하는 파생값은 2차 |
| 4 | 주기가 다른 지표 | 안내 후 변환 방법을 사용자에게 질문 |
| 5 | 이중 축 화면 범위 | 시안 A만 구현. 축 정보는 화면에 의존하지 않는 형식으로 정의 |

## 3. 구조

```text
요구별 조회 결과 ─(한 그래프 요청 시)→ combine_results ─→ align ─→ renderer(prepare) ─→ ui_cases ─→ 시안 A
                                                         │
                                                         └ 주기가 다르면 needs_choice → 확인 카드 → 선택 → align 재호출(조회 없음)
```

- `claview_b.align`(`modules/b/claview_b/align.py`, 서비스 흐름은 `claview_b_api.service`의 `align`·`combine_results`로 부름): 단위 분해·배율 환산·공통 기간·주기 변환·축 구성. 순수 함수이며 모델·네트워크를 쓰지 않는다. 계약: `docs/contracts/조회_결과.md`.
- `c_renderer.prepare`(`modules/c/claview_c/c_renderer.py`): `alignment.axes`가 있으면 `dual_axis` 보기를 만든다.
- 서비스 흐름(`pipeline/claview_pipeline/staged.py`): 조회 뒤 `align`을 호출한다. 주기 선택이 필요하면 `chart` 단계에서 멈추고 이미 받은 값을 서버에 보관한다. 사용자가 고르면 HCX·KOSIS를 다시 부르지 않고 이어 실행한다.
- 화면(`frontend/build/ui_build.py`): 이중 축 그리기, 항목별 단위 표시, 주기 선택 카드 문구.

## 5. 동작 요약

- 단위 배율만 다른 경우: 계열이 가장 많이 쓰는 배율로 정확히 환산하고, 환산 계수와 원래 단위를 기록한다.
- 통화·단위 종류가 다른 경우: 환산하지 않고 좌우 축으로 나눈다. 3종 이상이면 단위별 카드로 나눈다.
- 기간이 다른 경우: 공통 기간으로 자르고 안내한다.
- 주기가 다른 경우: 질문 카드에서 기간 평균, 기말값, 합계(금액일 때만), 따로 보기 중 선택한다. 비율·지수는 합계로 바꿀 수 없다.
- 이중 축 기본 모양: 왼쪽 금액은 막대, 오른쪽 증감률은 선. 질문에 "꺾은선"이 있으면 모두 선, "막대"가 있으면 왼쪽을 막대로 한다.
- 이중 축에서는 선그래프·묶음막대를 막고 이유를 보여준다. 항목별 나눠 보기와 수치표는 쓸 수 있다.

## 7. 알려진 한계와 확인이 필요한 사항

1. A(규칙 기반)는 질문에 "이중 축" 같은 표현이 있으면 해석을 확정하지 못하고 확인 질문을 낸다(합성 시험에서 확인). 이중 축을 질문으로 직접 요청하는 경우는 A 담당과 처리 방식을 정해야 한다. 이중 축은 단위가 다른 지표를 함께 요청하면 요청 표현이 없어도 기본으로 나온다.
2. 서로 다른 표의 두 지표를 A가 각각 요구로 나눠 올리는지는 실제 A 연결 뒤 확인이 필요하다. 기존 골든 22건에는 복수 표 사례가 없어, 별도 골든셋 v3 초안 5건을 만들었다(9절). 정답은 B 담당 승인 전이다.
3. 주기 질문은 C 연결층이 낸다. A·B 연결 계약에 "B가 묻는 질문" 형식은 아직 없다. 나중에 A의 질문·응답 구조로 옮기려면 A 담당과 합의가 필요하다.
4. 여러 요구를 한 차트로 합치는 조건은 질문 표현(한 그래프, 이중 축, 겹쳐 등)이다. 표현 목록은 `pipeline.py`의 `COMBINE_REQUEST`에 있다.
5. A를 거친 실제 호출 시험은 A의 외부 키 연결 뒤 대표 질문 2~3건으로 진행한다. 골든 통계표로 A를 대신한 실제 HCX·KOSIS 시험은 9절에 있다.
6. 통계표가 여럿인 질문에서 B가 표마다 비슷한 항목을 더 고르는 문제는 표별 지표 `focus`로 크게 줄지만, A가 `focus`를 넘기도록 계약을 정해야 한다([계획 32](32_A_B_표별_지표_focus_제안.md)).
7. 질문에 통계표 이름의 "~별"(예: "지급수단별 통계")이 있으면 B가 분해 요청으로 읽어 세부 항목을 모두 펼친다. B 쪽 개선은 아직 하지 않았다.
8. 추가 계열로 단위가 세 종류가 되면 이중 축 대신 계열마다 카드가 나뉜다(8절 6번과 같은 한계).

## 8. 2차 후속 작업 목록

1. 금액에서 직접 계산하는 파생값(전년동기비, 전기비 등)과 계산 정의 확인 질문.
2. 환율 환산: 환율 표를 카탈로그에 추가하고, 환율 종류(기말·기간평균)와 시점 맞춤 규칙(흐름은 기간평균, 잔액은 기말)을 정한 뒤 파생 계열로 제공.
3. 지수 기준 시점(2015=100 / 2020=100) 재기준.
4. 명목·실질, 계절조정 여부가 다른 지표의 결합 경고.
5. 지표 성격별(흐름·잔액·지수) 주기 변환 방법을 자동 추천.
6. 단위 3종 이상, 축 3개 이상 차트.
7. 골든셋 v3(초안 5건) 승인과 확대, 평가 기준 정리(초안 5건은 9절). 표 3개 이상, 한 표에서 지표 여러 개를 고르는 질문 추가.
8. 시안 A 외 다른 시안에 이중 축 반영(시안이 확정될 때).

## 9. 골든셋 v3(다중 표·이중 축 초안 5건)

- 파일: `eval/cases/golden/golden_set_v3_multi_table.json`(스키마, 합성 값 규칙 파일 포함). 기존 골든 22건은 바꾸지 않았다. 통계표 이름은 카탈로그의 KOSIS 통계표명과 같고, 항목·분류 코드와 단위는 원메타와 일치함을 시험으로 확인한다.
- 구성: 금액+증감률 이중 축(연), 주기가 다른 두 표의 주기 질문(월 전용+분기 전용), 같은 통화·다른 배율 환산, 통화가 다른 금액의 두 축 분리, 음성 대조(단위·주기 동일).
- 재생기: `pipeline/scripts/golden_replay.py`(`check`. 옛 로컬 서버를 쓰던 `serve`는 모듈 구조로 옮기지 않았다). A는 골든 통계표로 대신하고, B 이후는 실제 코드가 돈다. 모드는 `replay`(합성 값, 외부 호출 없음), `kosis`(골든 B 선택 + 실제 KOSIS), `hcx`(실제 HCX + 실제 KOSIS). 실제 호출 모드는 `--allow-external`이 있어야 하고 시작 때 호출 예정 횟수를 보여 준다. 옵션: `--hcx-retries`(429 재시도), `--table-focus`(표별 지표 전달), `--no-multi-table-prompt`(규칙 끄기, 비교용). 저장 기록은 `pipeline/scripts/golden_inspect.py`로 본다.
- 판정: 통과 / 골든 계열 포함·추가 계열 N개 / 불일치(3분류). B가 중단된 경우는 "비교하지 못함"으로 따로 표시한다.
- 시험 절차: [다중 통계표·이중 축 시험 가이드](../guides/다중표_이중축_시험_가이드.md).
- 골든셋을 만들며 확인한 사항:
  1. B는 질문에 주기 표현(반기·분기·월·연간)이 있으면 모든 통계표에 같은 주기를 적용한다. 따라서 주기 질문이 나오는 경우는 질문에 주기가 없고 표마다 제공 주기가 다를 때(월 전용 표+분기 전용 표 등)이다. 통계표별로 다른 주기를 질문에서 지정하는 경우는 현재 B가 처리하지 못한다.
  2. KOSIS 단위 `연리%`·`연%`(카탈로그 54건)를 정렬 모듈이 비율로 분류하지 못하던 문제를 고쳤다(`claview_b.align`). 고치기 전에는 금리 계열이 "기타" 단위로 취급되었다. `%`와 `연리%`는 문자열이 달라 별도 축으로 나뉜다(한 축으로 합칠지는 2차 결정 사항).
  3. 증감률·전년동기비 표현이 있으면 B가 기준 연도를 한 해 앞당겨 조회할 수 있다(B의 기존 동작).

### 9.1 실제 시험 결과와 조치(2026-10-26)

- 골든 B 답 + 실제 KOSIS: 5건 모두 통과. 정렬·축·환산·주기 질문이 기대와 같았다.
- 실제 HCX B 선택 + 실제 KOSIS: 처음에는 5건 모두 골든과 달랐다. 골든 계열은 대부분 포함했고, 표마다 1개 안팎을 더 골랐다.

| 현상 | 원인 | 조치 |
|---|---|---|
| B가 같은 행을 반복해 `duplicate_selection`으로 중단(CV-BC-04) | 질문의 지표 수만큼 행을 채우려다 반복 | B가 완전히 같은 행은 하나로 줄이고 안내(`expand_notices`의 `repeated_row_dropped`). 기간 등이 다른 중복은 이전처럼 중단 |
| 지급수단 7개 선택(CV-BC-03) | 질문 속 통계표 이름 "지급수단별 통계"의 "~별"이 분해 요청으로 읽혀 세부 항목 펼치기가 켜짐 | 골든 질문 문구에서 통계표 이름을 "지급수단 통계"로 바꿈. B의 "~별" 판정은 그대로(7절 7번) |
| 표마다 비슷한 항목 추가(01·02·03·04·05) | 각 표의 B 호출이 질문 전체를 보고 다른 표 몫의 지표를 비슷한 항목으로 채움(예: 대출금리 표에서 "정기예금" 몫으로 "예·적금담보대출") | 통계표가 여럿일 때만 B 프롬프트에 규칙 추가. A가 표별 지표를 알려 주는 선택 필드 `focus` 추가(B 쪽 반영 완료, A 협의 전, 계획 32) |
| CV-BC-02의 GDP 항목이 골든과 다름 | "실질 GDP 성장률"이 전년동기비·전기비로 모호. 실제 HCX는 계절조정 전기비를 일관되게 선택 | 골든을 "실질 계절조정 전기비"로 변경(B 담당 승인 필요). 변경 뒤 실제 HCX 재실행은 하지 않음 |
