## 2. 공개 결과 형식 AView (`a-view/2026-10-30.1`)

화면과 pipeline은 새 A 상태(`record`, `decisions`) 대신 AView만 읽는다.

- `session`: `session_id`, `question_version`, 원질문, `as_of`, 실행판(판본·모델·재검색 모델)
- `statistics[]`: `request_id`(세션·통계), `statistic`, 질문의 대상(`quote`, `name`), A 판정(`outcome` 그대로), `tables`(최종 표·기간·주기), `representative`, 적용 기준(`basis`: 축·값·출처), `focus`(통계 인용), 조건 인용, 실패 사유·경고, `answers`
- `questions[]`: `question_id`, `kind`(`basis_axis` | `period`), 적용 통계, 축, 선택지(값·표), `input`(`choice` | `choice_or_text` | `text`)
- `handoff`: `ready`(B로 넘길 요청: 표·focus·통계) / `blocked`(넘길 수 없는 통계와 이유)
- `failure`: 실행 전체 실패(판단기 오류, 계약 오류), `research`: 재검색 기록, `a_route`: A 라우터 결과 그대로

어댑터 규칙: 표를 고르지 않는다, 되묻기를 없애지 않는다, 실패를 성공으로 바꾸지 않는다. `selected`(검증)만 `ready`. `selected_unverified`·`ask_unverified`는 `blocked`(`a_evidence_unverified`).

## 3. 실행 설정

- 최초 판단 `gpt-6.1-terra`, 재검색 뒤 재판단 `gpt-6.1-sol`, 둘 다 effort low·출력 4096, 재검색 허용, 재판단 예산 질문당 1회. `screen.PROFILE`로 명시 전달한다(`entry.DEFAULT_MODEL` 미사용).
- 이번 작업에서 판단기는 합성(가짜 판단기·각본 판단기)만 쓴다. `CLAVIEW_MODE=live`에서 새 A 화면 경로는 판단기를 만들지 않고 `a_live_disabled`로 멈춘다(평가기의 호출 한도 검사를 거치지 않는 전송 경로를 만들지 않는다).

## 4. 되묻기와 재개

- 질문: `outcome == "ask"`인 통계의 `asks[]` 축마다 하나(`q:<통계>:<축>`). 선택지 ID는 `…:o<번호>`.
- 답변: `{question_id, question_version, option_id}`. 다음은 거절한다: 판(version)이 다름, 대기 중이 아닌 질문, 제시하지 않은 선택지, 같은 질문 두 번, 선택지 질문에 직접 입력.
- 적용: 그 통계의 그 축에만 기록(`answers`: 원문·통계·출처 `user_answer`). 축이 남으면 대기 유지. 모든 축이 답해지면 답한 값들을 모두 가진 선택지 표(모델 근거가 확인된 표)를 대상 표로 정하고, 표 확인 → 기간·주기 후보 → 최종 재확인을 다시 거친다. 대상 표가 없으면 `target_table_unconfirmed`(stage `answer`)로 실패 처리한다.
- 모델을 다시 부르지 않는다. 원질문·`as_of`·실행판은 바꾸지 않는다. 답변 전 결과(`record_before_answers`)를 보존한다. 판이 하나 오른다.

## 5. 기간 되묻기(연결 준비만)

- AView에 `kind: "period"`, `input: "choice_or_text"` 질문 모양을 두고, 화면은 선택지와 직접 입력을 받는다. 답변은 원문·적용 통계·출처를 그대로 보존해 B 요청의 `period_answers`로만 옮긴다. 원질문에 이어 붙이지 않는다. 화면과 pipeline은 날짜를 계산하거나 기본 기간을 채우지 않는다.
- 새 A는 지금 기간 질문을 만들지 않는다. 시험은 합성 질문 공급자로만 한다.
- 실제 B 계약에는 기간 답변 칸이 없다. `period_answers`가 있는 요청은 실제 B에 보내지 않고 `unsupported_links`(`period_answer_contract_pending`)로 보고한다. 받을 수 있다고 밝힌 합성 B로만 전달을 확인한다.
- 정하지 않는 것: 달력·자료 최신 기준, 생략 시 기본값, 답변과 원질문 충돌 해석, period_hint 불일치, 통계·판본별 기간 배정, B 주기 기본값·수록 부족.

## 6. B·C 연결

- `ready` 통계마다 B 요청 하나(최종 표 전부, 표마다 `focus` = 통계 인용). 같은 최종 표를 쓰는 통계는 기간·주기·계산·분할 인용이 같을 때만 합치고 focus를 ` / `로 잇는다. 다르면 합치지 않고 그 통계들을 `unsupported_links`(`same_table_conditions_differ`)로 보고한다. focus가 100자를 넘으면 자르지 않고 `focus_too_long`으로 보고한다.
- B·조회·C는 기존 staged 코드 그대로 부른다. 일부 통계만 넘어가면 결과는 `partial`이다.
