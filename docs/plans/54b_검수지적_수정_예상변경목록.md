# 54b. 검수 지적 3건 수정: 예상 변경 목록 (구현 전 작성, 2026-10-30)

재생 대상 71건: 계획 47 live 50 + 계획 46 live 6(55건 측정에 쓰인 5건 + 대조 SB:CQ1-03) + 계획 49 explore15 15(반례 PC:EQ-21·B:CX-Q063·S13 포함). 수정 전 재생 결과는 `runs/screen54_replay_before/replay.json`이다(합성 B·조회, 모델·KOSIS 호출 없음).

## 수정 규칙(요약)

1. 사전 차단(B를 부르기 전): 한 통계가 여러 판본 표를 나눠 쓰는 경우(`edition_period_split`), 한 표에 떨어진 기간 구간이 둘 이상인 경우(`disjoint_period_not_in_b_contract`), 전달할 요청끼리 A가 배정한 기간(월 범위)이 다른 경우(`period_differs_between_requests`).
2. 사후 대조(B를 부른 뒤, 조회 전): B가 표마다 고른 기간·주기를 A가 배정한 기간·주기와 비교한다. 다르면 조회하지 않고 `b_period_differs_from_a`로 남긴다. 예외 하나: 통계에 계산 인용이 있고 B가 A의 기간을 모두 포함한 채 그 앞에만 기간을 더한 경우는 기준 시점 추가로 보고 통과시키며 `b_fetch_includes_base_period` 안내를 남긴다.
3. 같은 표 묶기: 인용 문자열 대신 A의 최종 표·기간 구간·주기(구조값)와 기간 답변을 비교한다. 계산 인용 차이는 막지 않고 `calculation_not_in_b_contract` 안내로 남긴다.
4. 경고: A의 경고 행(코드·축·요청 값·표·단계)을 그대로 AView에 옮기고, 화면 응답 `a_warnings`와 결과 카드 경고로 보여 준다. 경고만으로 상태를 바꾸지 않는다.

## 추가(같은 날, 검토 의견 반영)

검토 의견: 기준 시점 허용은 "B가 계산 종류와 필요한 기준 시점 범위를 밝히고 그 범위만 더 조회할 때"로 좁힌다. B 결과에는 그 표시가 없음을 B 코드에서 확인했다(질문 문구로 앞 시점을 늘리고 결과에는 기간만 남김). 그래서 규칙 2의 예외를 없앴다.

|---|---|---|
| CV-AB-18 (55건) | ok + `b_fetch_includes_base_period` 안내 | 조회 안 함, `b_period_differs_from_a`(`kind: added_before_start`), unsupported |
| 그 밖 | — | 1차 수정 결과와 같음 |
