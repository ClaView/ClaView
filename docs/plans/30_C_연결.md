# 계획 30: C를 최신 A·B 흐름에 연결

- 요청(2026-10-23): "C파트 현재 코드는 참조만 하고, 현재 최신 버전의 A/B 코드에 맞게 C코드 작업을 진행", "자연어 입력 시 각 단계별로 정상 동작하도록 구현".
- 범위: `src/claview/c/`의 실행기·서버·확인 카드를 `claview.pipeline.FlowSession` 위로 옮긴다. A·B·`claview.pipeline` 코드는 수정하지 않았다. 외부 API 호출 없음(시험은 합성 B 모델·합성 조회).
- 상태: 오프라인 연결 완료. 실제 HCX·KOSIS 호출 시험은 호출 수·비용 승인 뒤에 진행한다(AGENTS.md).

## 1. 구조 변경

| 이전(계획 29 보관본) | 변경 후 |
|---|---|
| `Pipeline`이 옛 A(`claview_v3`)와 B 10/16 사본(`vendor/a`, `vendor/b`)을 직접 호출 | `Pipeline`이 `FlowSession.run_question/answer`만 호출. A가 질문·표 선택·B 호출·조회를 수행 |
| 확인 카드: 옛 A 후보 묶음 + 해석 확인 체크 | 확인 카드: A의 대기 질문(`control.pending_question`)을 카드로 변환. 브라우저는 `option_id`만 전송 |
| 재개: B 조건 편집 `/api/conditions` 포함 | 재개는 `/api/resume` 하나. `/api/conditions`는 404 |
| B 사후 보정(`named_selections`, `preserve_rate_periods`, `normalize_b_query`), 조건 편집기(`b_conditions`) | 적용하지 않음. 해당 파일은 `abc_integration/legacy_old_ab/`로 옮겨 보존(삭제 없음) |
| `dependencies.py`가 vendor 경로·해시 검사 | 레포 경로(`REPO_ROOT`) 기준. `claview.*`는 설치된 패키지에서 import. 평면 import용 C 폴더만 `sys.path`에 추가 |

## 2. 단계별 진행 기록

`STAGES = question / table / conditions / fetch / chart`는 화면과 같다. A·B·조회는 한 호출 안에서 끝나므로 모델·조회 클라이언트에 호출 감시 래퍼를 끼워 B 시작·조회 시작 시점에 단계 이벤트를 먼저 내보내고, 종료 뒤 A 상태로 각 단계의 요약·목록·메모를 확정한다.

| 단계 | 출처 | 중단 시 상태·코드 |
|---|---|---|
| question | A `analysis.interpretation`, 공개 가정(`assumptions`) | 예측 등 미지원 요청: `unsupported`(A 호출 전) |
| table | A `selections`, `response.status` | 질문 대기: `needs_confirmation`(`a_selection_unsettled`). 표 없음: `failed`(`a_no_table`) |
| conditions | `response.b.requirements[].result.b_outcome` | HCX 키 없음 `hcx_key_missing`, B 이슈 코드 그대로 |
| fetch | `result.fetch` | KOSIS 키 없음 `kosis_key_missing`, 조회 이슈 코드 |
| chart | `c_analysis.renderer` | `invalid_c_input` |

- 요구가 여러 개면 요구별(B 호출별)로 렌더러를 따로 돌려 카드를 이어 붙인다. 일부만 성공하면 `partial`과 실패 코드 목록을 메시지에 남긴다.
- `Pipeline.run(through="A"|"B"|"C")`로 단계별 시험이 가능하다. `A`는 모델 없이, `B`는 조회 클라이언트 없이 실행한다.
- A가 답변 후 다시 질문하면 같은 방식으로 다시 멈춘다(체크포인트 재저장).

## 4. 알려진 제약

- 시험 실행 명령: 묶음별 별도 프로세스. `uv run python -B -X utf8 -m pytest tests/c -q -p no:cacheprovider`.
- `abc_integration/dist/`는 `.gitignore` 대상이다. 처음 실행 전 `uv run python -X utf8 src/claview/c/abc_integration/ui_build.py`로 생성한다.
- 서버는 한 번에 한 질문만 처리하고(`busy` 잠금), `FlowSession` 포트가 스레드 안전하지 않다. 로컬 단일 사용자 전제다.
- `c_analysis.calculate_rates`(표 `DT_404Y016`·`DT_402Y014` 전제), `composition.py`(M2 `DT_161Y008`), `chart_rubric.py`는 표 ID 하드코딩이 그대로 남아 있다. 해당 표가 아니면 동작하지 않는 보조 규칙이다.
- `request_capabilities.py`는 A 호출 전 정규식 거절(예측·주어 없는 후속 질문·환율)을 유지한다. 환율은 `MetadataStore.catalog` 제목으로 확인한다.
- `kosis_compat.py`는 B `fetch.py`의 NFKC 단위 정규화와 겹쳐 `legacy_old_ab/`로 옮겼다.

## 5. 결정이 필요한 사항

1. **조회 조건 편집 화면(옛 `/api/conditions`)을 되살릴지.** 현재는 숨겼다. A의 질문·선택 흐름과 B의 코드 기반 기간 결정만 쓴다. B가 조건을 확정하지 못하면 이유(코드)를 보여 주고 질문을 다시 쓰게 한다. 되살리려면 B 실패 결과(`b_outcome.result`)를 편집 기준으로 삼는 새 편집기가 필요하다(옛 편집기는 옛 B 상태에 묶여 있음).
2. **B 사후 보정 3종(공표 증감률 기간 보존, 지정 항목 보완, 날짜 표기 정규화)을 어디에 둘지.** 현재 적용하지 않는다. 이 보정은 B 결과를 바꾸므로 B 담당 확인 대상이다. 선택지: (가) B 쪽으로 이관, (나) 포트와 조회 사이에 C 보정 단계 삽입(`claview.pipeline` 수정 필요), (다) 폐기하고 골든 22건 결과로 필요성 재검증.
3. **표 ID 하드코딩 규칙(M2 합산 검증, 지수 증감률 계산)을 유지할지.** 골든 9·18·20번 화면에만 쓰인다.
4. **실제 호출 시험 범위와 한도.** 질문 수, HCX 호출 상한, 비용 한도(7절).
5. **배포 형태.** 팀 PC 개별 실행인지, 공용 서버인지에 따라 키 관리·동시 처리가 달라진다(`docs/c/키_관리_가이드.md`).

## 7. 실제 호출 시험 제안(승인 필요)

| 순서 | 내용 | HCX | KOSIS |
|---|---|---|---|
| 1 | `through=A` 시험(키 불필요) | 0 | 0 |

## 8. 실제 실행에서 확인된 사항(2026-10-23)

- 질문 `2024년 공산품과 서비스의 생산자물가가 어떻게 달랐는지 월별로 비교해줘`: A는 `DT_404Y016`(생산자물가지수 품목별)을 고르고 B가 항목 2개를 정했으나, KOSIS가 첫 조회에서 `err 30`(데이터가 존재하지 않습니다)을 돌려줬다. 요청 조건: `orgId 301, tblId DT_404Y016, itmId 13103134764999, objL1 13102134764ACC_CD.3AA, prdSe M, 202401~202412`. 메타정보상 이 조건은 유효하다(분류 `3AA`=공산품, 수록 기간 196501~202608).
- 골든 기대 표는 `DT_404Y014`(생산자물가지수 기본분류)다. A는 선택 상태 `confirm`으로 `DT_404Y016`을 1순위로 진행(`assume`)했고, `DT_404Y014`는 대안 후보 첫 번째다. 품목별 표가 공산품 합계 값을 제공하지 않아 `err 30`이 난 것으로 추정하나, KOSIS로 직접 확인하지는 않았다.
- 현재 A는 거의 모든 질문을 `confirm`+`assume`(질문 없이 1순위로 진행)으로 처리한다(골든 22건 중 20건). 옛 C는 `confirm`이면 후보 카드를 띄웠다. 동작 차이이므로 A 담당과 정책을 정해야 한다.
- 골든 22건의 A 표 선택(오프라인, 모델 불필요): 기대와 일치 15건. 불일치: 07번(기대 `DT_121Y006`, A `DT_121Y006`+`DT_141Y004`), 10번(`DT_301Y015` vs `DT_132Y001`, 조회 안 함), 16번(`DT_404Y014` vs `DT_404Y016`), 17번(같은 표 `DT_404Y015` 두 번, 표 단위로는 일치), 20번(`DT_402Y014` vs `DT_401Y015`), 22번(`DT_405Y007` vs `DT_200Y120`, 조회 안 함).
- C 쪽 보강: 조회 실패 시 KOSIS 응답·요청 조건 표시와 `trace_events` 저장, `err 30`은 `kosis_no_data`로 구분, 통계표 단계에 "A가 확정하지 못하고 1순위로 진행" 표시와 다른 후보 목록 추가.
