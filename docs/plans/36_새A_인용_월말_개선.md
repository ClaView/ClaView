# 36. 새 A 개선: 이어 붙인 인용(GV4-01)과 '월말·연말'(GV4-07)

- 상태: 승인(2026-10-28 14:59 UTC), 구현·검증 완료, 커밋 전. 브랜치 `a/quote-monthend`(`main` `d264108`에서 생성).
- 범위: 새 A(`modules/a/claview_a`)만 고친다. 기존 A(`claview_a_legacy`, `tests_legacy`), 채점기, 기준·정답 파일은 바꾸지 않는다. CV-AB-10(되묻기 정책 보류)은 손대지 않는다. 실호출 없음.
- **이 계획은 2026-10-13 Q3 결정의 일부를 바꾼다.** 그때는 "월말·연말은 계산 방식이라 주기가 아니다"로 정했다. 이번에는 새 A에 한해 단독 "월말"을 월(M) + 끝 시점, "연말·년말"을 연(Y) + 끝 시점으로 읽는다. "월평균"을 주기가 아닌 것으로 보는 부분은 그대로다.

## 1. 문제와 원인 (golden26 실호출 결과 기준)

| 문항 | 결과 | 원인 |
|---|---|---|
| GV4-01 | 표 선택은 맞음, 최종·완료 틀림 | 모델 인용 오류. 통계 `quote`를 질문의 떨어진 두 부분을 이어 붙여 만들었다. 코드는 `quote_not_in_question`으로 멈췄고, 이 거절은 계약대로다. |
| GV4-07 | 모델 의미·대표 집합·계약 맞음, 최종·완료 틀림 | 코드의 주기 읽기 범위. 모델이 주기 칸에 "월말"을 인용했는데 주기로 읽지 못해 `frequency_unresolved`로 멈췄다. |
| GV4-20 | 완료 맞음 | 모델이 "연말"을 인용하지 않았고, 코드가 기본 연간 주기로 골라 정답과 같아졌다. '연말' 조건을 보존했다는 증거는 아니다. |

## 2. 결정

1. **월말·연말(A1)**: `conditions/q_rules.py`의 주기 규칙에 단독 "월말" → M, "연말"·"년말" → Y를 더하고, 끝 시점은 지금 규칙(`frequency_anchor`)대로 `anchor="end"`가 된다.
   - 앞에 숫자·한글이 붙은 말("7월말", "2024년 말", "작년 말", "전월말")은 지금처럼 기간·시점이고, "지난·이번 월말" 같은 시점·비교 앞말 뒤도 지금 규칙대로 주기가 아니다.
   - "월말잔액"·"월말잔"처럼 "말잔"으로 이어지는 말은 지금처럼 주기로 읽지 않는다(기준어 쪽).
   - "월평균"은 범위 밖이다(지금처럼 주기가 아니다).
   - 끝 시점으로 말잔·평잔이나 다른 기준을 자동으로 정하지 않는다. 기록만 남긴다.
2. **분기말·반기말**: 지금도 Q·H + `anchor="end"`로 읽지만, 기간 읽기(`periods.read_quotes`)가 남은 "말"을 못 읽은 말로 보고 `frequency_partially_read`를 낸다. 주기 조건에 끝 시점(`anchor="end"`)이 있을 때만 그 뒤의 "말"까지 읽은 범위로 본다. 남은 "말"을 무조건 무시하지는 않는다. "매 월말"·"월말마다"는 지금처럼 통과한다.
3. **끝 시점 기록**: 결과 기록의 통계별 판단에 `frequency_quotes`를 둔다. 인용한 주기 말마다 원문(`quote`), 걸린 통계(`for`), 읽은 주기(`frequency`), 기간 안의 시점(`point_in_period`: 끝이면 `"end"`)을 적는다. 기간 해석기의 `anchor`(요청을 거꾸로 셀 때 쓰는 최신 자료 시점)와는 다른 개념이라 이름을 나눴다. B가 이 칸을 받는다고 보지 않는다(화면 연결은 다음 작업).
4. **GV4-01(지시문)**: `data/prompt_tl.md` 규칙 1에 아래 문구를 넣는다. 인용 검사(`quote_not_in_question`)는 느슨하게 하지 않는다.
   > statistics.quote는 질문에 실제로 연속해서 있는 구절을 그대로 인용한다. 떨어진 부분을 이어 붙이거나 순서를 바꾸지 않는다. 필요한 말이 흩어져 있으면 통계를 식별할 수 있는 연속 구절을 인용하고, name에는 질문 전체를 바탕으로 통계와 대상을 요약한다. 명시 기준·기간·주기·계산 표현은 각각 해당 필드에 원문 그대로 인용하고 for로 연결한다. 대상 표현을 넣기 위해 splitters나 periods를 다른 용도로 사용하지 않는다.
   - 지시문은 실행 정보의 `prompt_sha256`으로 추적된다. 출력 계약(형식)은 바뀌지 않으므로 계약 판은 올리지 않는다. 기간 읽기·검사 판(`PERIODS_VERSION`, `CHECK_VERSION`)은 올린다.

## 3. 시험과 확인

- 정상·오류 짝 시험: 월말 → M·end, 연말·년말 → Y·end, 분기말·반기말 → Q·H·end(`read_quotes`에서 일부만 읽힘 없음), 매 월말·월말마다 그대로, 월평균은 주기 아님, "말"만은 주기 아님, "지난 월말"은 지금 규칙대로, "2024년 말"은 기간, "월말잔액"은 주기 아님, 결과 기록의 `frequency_quotes`(원문·for·주기·끝 시점).
- 새 A 시험 전체(`tests`, `tests_tl` 평가 묶음 연결 전·후)가 통과해야 한다.
- 저장 응답 재생(코드 효과): golden26 26문항, full40g 40문항. 지시문이 바뀌어 요청 해시가 달라지므로, 문항별 저장 응답을 지시문 칸을 뺀 요청이 같은지 확인한 뒤 넣는다.
  - 판단(통계별 선택·되묻기·실패, 라우팅, 최종 표)을 기록 바이트와 따로 비교한다. 기대: GV4-07만 나아지고 나머지 65문항은 판단이 같다.
  - 기록 차이는 (a) 허용(지시문 해시·판 문자열, 새 끝 시점 칸)과 (b) 예상 밖(그 밖의 모든 것)으로 나눈다.
  - 기존 채점기로 다시 채점하고 GV4-07·GV4-20의 실제 채점 결과를 적는다.
- 지시문 효과: 재생으로 잴 수 없다. 다음 고정판 평가에서 확인한다. 코드 효과와 섞지 않는다.
