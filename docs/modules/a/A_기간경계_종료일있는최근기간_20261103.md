# A 기간 경계와 종료일이 있는 최근 기간 보완

사용자가 지정한 월 범위를 주기에 맞추며 넓히던 경로를 막고, 종료일과 최근 기간 길이를 함께 전달하는 모델 출력 계약을 추가한다. A는 사용자 답·기간 출처를 보존하고 B 송신 예정 값을 조립한다. B 수신 적용과 파이프라인 자동 전달은 이번 범위에 포함하지 않는다.

기준은 PR #32·#33·#34가 포함된 main `6067254`와 그 위의 공용 계약·A 송신부 작업이다. 최근 N을 표·주기의 최신 수록 시점에서 계산하는 정책, 기간 누락 시 되묻기, 사용자 답 우선, 한 번의 제한된 복구는 유지한다.

## 1. 명시 기간과 주기를 정확하게 맞추기

`2024년 2월부터 5월까지 분기별`은 두 개의 완전한 분기가 아니다. 기존 경로는 2~5월을 1~6월로 넓혀 확정할 수 있었다. 보완 후에는 명시된 날짜를 확대하지 않고, 지정 주기로 정확히 표현할 수 없는 범위로 처리한다.

| 입력 | 처리 |
|---|---|
| 2024년 2~5월, 월별 | 2024-02~2024-05 유지 |
| 2024년 2~5월, 분기별 명시 | 2024-01~2024-06으로 확대하거나 주기를 바꿔 성공시키지 않음 |
| 2024년 1~6월, 분기별 | 완전한 두 분기로 처리 |
| 최근 6개월, 분기별 | 정확히 두 분기로 환산하는 기존 동작 유지 |
| 최근 5개월, 분기별 | 불완전한 분기를 올림해 처리하지 않음 |

주기가 미정이면 원래 기간을 정확히 표현하는 지원 주기를 확인한다. 사용자가 명시하거나 답한 주기를 다른 주기로 바꾸지는 않는다. 달력 표현의 한 기간과 그 기간 안의 미공표 구간은 명시 월 범위를 확대하는 경우와 구분한다.

되묻기 직접 입력도 같은 경계 검사를 거친다. 분기별 질문에 `2024년 2월부터 5월까지`라고 답하면 거절하고, 기존 질문·세션·다른 답을 보존한다. 이어서 `2024년 1월부터 6월까지`로 수정하면 같은 세션에서 처리한다. 답 적용 중 새 모델 호출은 없다.

`최근 3개년`처럼 개수 표현을 쓰는 직접 입력도 기존 최근 기간 계산으로 연결한다. 문항 전용 정답이나 표 ID를 판독기에 넣지 않는다.

## 2. 종료일과 최근 길이를 함께 구조화하기

기존 `.9` 계약은 상대 범위의 `start`·`end`에 달력 값을 넣지 못했다. 따라서 `2025년까지 최근 3년`의 종료일과 길이를 한 행에 함께 보존할 수 없었다.

새 모델 출력 계약 `tl-contract-2026-10-28.10`은 `form=relative`에서 명시 종료일을 `end`에 둘 수 있게 한다. `start`는 `none`이며 시작일은 코드가 계산한다. 종료일을 말하지 않은 최근 N은 기존처럼 표·주기의 최신 수록 시점을 쓴다.

```json
{
  "for": ["s1"],
  "quote": "2025년까지 최근 3년",
  "meaning": "range",
  "form": "relative",
  "start": "none",
  "end": "2025",
  "count": "3",
  "unit": "Y",
  "refers_to": [],
  "read": "ok"
}
```

이 의미와 월별 주기를 받으면 코드는 요청 범위를 2023-01~2025-12로 계산한다. 모델이 시작 연도를 계산해 절대 범위로 바꾸도록 요구하지 않는다. 종료일이 표의 최신 시점보다 뒤인 경우에도, 요청 종료일을 먼저 잘라 시작일까지 앞당기지 않는다. 요청 범위 보존과 수록 범위 검증·미공표 처리는 별도다.

잘못된 종료일 형식, 시작일과 최근 길이의 중복 지정, 해당 주기로 정확히 표현할 수 없는 경계는 검사한다. 복구 시 정상 조건은 보호하고 실패한 부분만 교체할 수 있다. 종료일·길이를 지워 조건이 줄어든 응답을 정상 복구로 채택하지 않으며, 복구 상한은 기존 1회다.

## 3. 판 구분과 호환

- `.9` 이하의 저장 응답은 원래 계약으로 검사한다. 새 계약으로 이름만 바꿔 재생하지 않는다.
- 새 `.10` 합성 입력은 코드 경로 확인용이며 실제 모델 응답으로 세지 않는다.
- 새 지시문·검사·답 처리의 판과 소스 해시가 달라진다. 기존 실호출 승인은 재사용하지 않는다.
- 기존 실측, 기존 원응답 재검사, 새 계약 합성, 추후 새 계약 실측을 별도 결과로 보고한다.

## 4. A 송신부와 B 연결 경계

[공용 계약·A 송신부](../../contracts/A_B_기간조건_공용모델과_A송신부.md)는 최종 기간·주기, 각각의 출처, 적용 통계와 원답 참조를 `handoff.ready[].b_request.tables[].period_condition`으로 조립한다. `focus`와 원질문은 유지하며 기간 우선순위의 근거를 focus에서 추정하지 않는다.

현재 B HTTP는 `period_condition`이 있으나 서비스의 `accepts_period_condition`이 명시적으로 `True`가 아니면 `period_condition_not_supported`로 0호출 거절한다. `/b/resolve`와 `/b/run` 모두 적용하며, 조건이 없는 기존 요청은 유지한다. 이 보호가 B 수신부 구현을 뜻하지는 않는다.

B는 이후 다음을 구현한다.

1. 필드별 `user_answer` 우선 적용과 참고값 처리.
2. 정확한 주기 환산·수록 범위 검사, 요청·조회·미수록·계산용 추가 범위 반환.
3. 적용 출처·대체 여부·안내와 명시적인 수신 지원 표시.

그 뒤 파이프라인이 지원하는 B에만 새 요청을 전달한다. 표별 최신 시점 차이에 따른 A의 `period_differs_between_requests`, 수록 기간이 짧을 때 A 선차단, B 결과와의 단순 참고값 차이는 연결 단계에서 조정한다. 사용자 답, 같은 표의 상충 조건, 판본 분할·불연속 구간을 함께 해제하거나 합치지 않는다.

PR #34의 B 계산에는 명시 종료일이 표 최신보다 뒤일 때 끝을 먼저 줄이고 최근 개수를 거꾸로 세는 경로가 남아 있다. 이 동작을 A의 요청 범위 계산으로 복제하지 않는다. PC-18 같은 사례에서 요청 범위와 조회 범위를 공통 예시로 대조한다.

## 5. 확인 결과와 남은 확인

오프라인 검증 결과다. 기존 시험의 동작 단언은 유지했고, 계약·지시문·재판단 판 문자열 세 곳만 새 판으로 바꿨다.

| 자료 | 확인 결과 | 의미 |
|---|---|---|
| 기존 실제 `.9` 첫 응답 40건 | 보완 전 기준과 결과 변화 없음 | 두 골든셋의 저장 응답 재검사 |
| 옛 `.6` 상대기간 응답 4건·기존 합성 6건·별도 BOK08 응답 1건 | 앞의 40건과 합친 51건 재생에서 결과 변화 없음 | 원자료 종류·시점 구분 유지 |
| 새 `.10` 합성 4건 | 4건 통과 | 종료일 있는 최근 기간, 분기 답 거절·수정, 최근 3개년 직접 답, 명시 월 범위 확대 금지 |
| 회귀 | A 333 통과·4 건너뜀, A 판단 1,532 통과·52 건너뜀, A API 178 통과, 공용 1,377 통과 | 묶음별 별도 프로세스 |
| 연결·B·C 회귀 | 파이프라인 182, 파이프라인 API 4, B 791·2 건너뜀, B API 23, C 59 통과 | 외부 호출 없음 |
| 정적 검사 | Ruff 통과, import 경계 9개 유지·위반 0 | 모듈 책임 유지 |
| 실제 브라우저 | 직접 기간 답 거절→수정 적용, 최근 3개년 답, 종료일 있는 최근 기간, 저장 응답 재생 확인 | A만 실행, B 연결 미지원 안내 유지 |
| 새 계약 실제 모델·B·KOSIS 호출 | 0회 | 새 모델 해석 품질·전체 조회 완료는 미검증 |

원래 40문항에서 실패한 BOK08과 나중에 별도로 호출한 BOK08 결과를 합치지 않는다. 저장된 복구 원응답이 없는 경우 합성 응답으로 채우지 않는다.

정확 경계 재현 시험 5건 중 3건은 보완 전 실패하고 보완 후 모두 통과한다. 직접 답 판독 추가 시험은 보완 전 12실패·5통과, 후 17통과다. B 미지원 보호는 전 8실패·4통과, 후 12통과다. 화면의 기간 오류 안내는 전 5실패·1통과, 후 6통과다. 기간·주기 불일치를 입력 길이 오류로 보이던 문구도 수정했다.

검증 중 발견한 현재 분기의 옛 응답 경로 회귀와, 미수록 후보 때문에 완전 수록 후보까지 탈락하는 문제는 고치고 반례를 추가했다. 미래 미수록 범위를 잘라 성공시키는 것은 막되, 이미 요청 전체를 수록한 후보를 다른 후보 때문에 탈락시키지는 않는다.

현재 main 프론트엔드는 A만 실행한 기록도 이력에서 `중단 기록`으로 표시하며, 답 거절 행에는 단계 정보가 없는 카드가 붙는다. 오류 사유와 기존 답변 폼은 남고 수정 답은 적용할 수 있다. 이번 확인을 전체 조회·차트 완료로 세지 않으며, A 단독 전용 상태 표시는 후속 화면 작업이다.

새 계약 실호출은 후보·실행기·문항·기대값·기준일·호출 및 비용 상한을 고정한 새 승인 뒤 진행한다. 첫 판단, 복구 결과, 최종 조건, B 송신 예정 값을 나눠 비교하며, B 수신부 연결과 전체 화면의 실제 조회 검증은 별도 후속이다.
