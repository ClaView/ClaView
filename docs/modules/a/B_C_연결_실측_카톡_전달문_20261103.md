# B·C 담당 카톡 전달문

아래 문구를 그대로 공유할 수 있습니다.

---

12문항을 A→B→KOSIS→C 실제 경로로 확인했습니다. A 최종 표·기간·주기는 기대와 같았고, 조회된 23계열·428개 값도 원응답부터 화면 전달값까지 일치했습니다. 이후 A의 표별 기간 전달을 보완했고, 남은 B·C 작업을 정리했습니다.

**B 담당 확인 부탁드립니다.**

1. **먼저 사용자 기간 답 전달:** A는 `2024년 월별`을 `period_source=user_answer`로 정상 전달했지만, B 모델 요청에는 `resolved_period:null`이 들어가 빈 selection으로 멈췄습니다. 확정 기간을 계열 선택 모델에도 제공하고, 필드별 출처와 코드 검증은 유지해 주세요.
2. **다음 전년동월비 기준 구간:** 필요한 전년도 자료가 조회에서 빠졌습니다. 표시 기간을 유지하면서 비교 구간을 `calculation_extra`로 구분해 조회해 주세요. 두 수정 모두 표별로 나눠 B를 부르는 실제 파이프라인 경로에서 확인이 필요합니다.

**C·연결·화면 담당 확인 부탁드립니다.**

현재 C는 이 M2 증감률 계산을 지원하지 않아 원자료만 보여 주는데 상위 상태는 `ok`입니다. 계산 지원 범위를 정하고, 우선 **“원자료 조회 완료 · 요청 계산 미완료”**를 요약·화면·저장 복원에서도 구분해 주세요. 이 표시는 계산 구현을 기다리지 않고 병행할 수 있습니다. 공표값 표시와 C의 직접 계산도 구분해야 합니다.

A의 서로 다른 표 기간 차단은 보완했고 오프라인·화면 확인을 마쳐 A 보완 PR에 담았습니다. 기간 조건과 문맥을 받는 B에만 전달하며, 구형 B·같은 표 충돌·불연속 기간·판본·사용자 답 보호는 유지합니다. 저장 12문항 중 11건은 불변이고 해당 차단 문항만 저장 A+합성 B/KOSIS로 풀렸습니다. 새 실호출 성공으로 세지는 않습니다.

일반 Docker 실호출 기본 경로·**서버 복원**·호출 횟수의 **HCX→B 모델** 표시는 [별도 서비스 PR #46](https://github.com/ClaView/ClaView/pull/46)에 올렸습니다. 이 작업은 위 B 기간 처리·C 계산 문제를 해결한 것이 아닙니다.

focus에서 단위/기준연도 문구가 빠진 3건은 별도 기록했습니다. 이번 실제 메타·조회 결과는 조건을 충족했지만, 그 사실과 focus 생략을 같은 것으로 처리하지 않겠습니다.

저장 응답·가짜 전송으로 재현과 수정 확인 → 기존 회귀 → 실제 화면 순서로 확인한 뒤, 항목별 해결 여부와 남은 제한을 알려 주세요. 추가 실호출은 필요한 범위만 따로 정하면 됩니다. 상세 근거와 수락 조건은 **[B·C 연결 실측 보완 요청](B_C_연결_실측_보완요청_20261103.md)**에 있습니다.
