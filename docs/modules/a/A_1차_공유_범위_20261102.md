# A 1차 기본 기능 공유 범위

이 변경은 A 본체와 A API, A 결과를 표현하는 공용 AView 계약을 공유하는 초안이다. 기준은 PR #28까지 반영된 main이며, B·C 구현과 전체 화면 연결은 이번 변경에 포함하지 않는다.

## 이번에 공유하는 동작

- 질문을 통계별로 나누고 후보 통계표와 명시 조건을 검사한다.
- 모델이 기간·주기 의미를 구조화하고, 코드는 기준일 계산·카탈로그 지원 여부·조건 보존을 검사한다.
- 사용자만 정할 조건을 되묻고, 답한 통계의 해당 조건만 갱신한다.
- 내부 해석 오류는 기존 한 번의 복구 범위에서 처리하고, 정상 조건을 보존한다.
- B 송신 예정 focus와 원문 근거를 보존한다. 인용 검증 자체가 의미 정확성을 보장하지는 않는다.
- 실제 카탈로그의 숫자 포함 분류값이 질문에 명시되면 카드에 근거로 노출하고, 선택한 표의 focus에서 빠진 경우 성공으로 넘기지 않는다. 값의 의미·극성은 모델이 판단하며 코드가 새 선택값을 만들어 넣지 않는다.
- 이 검사는 동일한 형식의 숫자 포함 라벨이 둘 이상 있는 카탈로그 축에 한정한다. 여러 통계에서는 해당 통계의 인용으로 귀속이 확인된 조건만 검사한다. 임의 표현의 의미나 모든 focus 누락을 판정하는 장치는 아니다.
- 유효하게 구조화된 기말 주기가 잔액 기준을 이미 정한 경우 불필요한 되묻기를 줄인다. 다른 통계의 주기를 빌리거나 명시 기준·배제 조건을 덮지 않는다.
- 실행 기록과 호출 원장은 기본 한도를 유지한다. 실제 모델 전송은 별도 승인 없이 켜지지 않는다.

새 A의 공개 진입점은 `claview_a_api.screen`의 Python API와 기본 HTTP `/a/select`·`/a/answer`이다. HTTP는 필수 계약 판 `a-http/2026-11-02.1`과 AView 응답을 사용하며, 서버에 저장한 세션 ID로 답 적용·기록 조회를 한다. `GET /a/records/{session_id}`는 저장된 A 결과를 읽으며 모델을 호출하지 않는다. 예전 `claview_a_api.service` → `claview_a_legacy` HTTP는 `/a/legacy/select`·`/a/legacy/answer`에 유지한다. [HTTP 전환 계약](../../contracts/A_HTTP_전환_20261102.md)

A HTTP는 기본 합성 모드이며, 실제 모델은 기존 승인과 호출 한도를 통과한 경우에만 사용할 수 있다. 키·실행 모드·기록 위치·checkpoint를 요청 본문으로 받지 않는다. 저장 응답을 업로드해 실행하는 HTTP API는 제공하지 않는다. 기존 화면은 Python service 직접 호출을 유지하며, A HTTP 전환으로 화면의 실호출이 켜지는 것은 아니다. 화면의 실호출은 기록·호출 상한 연결 후속 작업까지 명시적으로 꺼 둔다.

## 이번 변경으로 완료되지 않는 것

- main B는 A 확정 기간·주기를 받는 최소 C2 계약을 아직 지원하지 않는다. A의 조건 조립 함수는 송신 예정 자료이며 연결 완료의 근거가 아니다.
- A의 `basis`·`evidence`·근거 인용은 현재 B로 직접 전달하지 않는다. 검토한 원화 조건 관련 6표도 B가 원질문을 읽는 경로에 의존한다. A에서 확인한 기준과 근거를 B가 어떻게 받는지는 후속 연결 계약으로 정해야 한다.
- 후보 작업본에서 확인한 화면 상태·선택지·기록 재개 개선은 후속 연결 PR에서 반영한다. 이 PR의 범위를 전체 프론트엔드 완료로 해석하지 않는다.
- 기존 화면 시험은 주기 기본값에 의존하지 않도록 합성 질문·응답에 주기를 명시했다. 기존 동작 단언은 그대로 유지했다. A 승인 환경변수가 있더라도 현재 화면의 실호출 게이트가 열리지 않는 시험을 추가했다.
- B 항목 선택, KOSIS 조회 수치, C 계산·표시 정확도는 이번 A 검증 범위가 아니다.
- 저장 응답 재검사와 합성 시험은 코드 동작 확인이다. 다른 계약·지시문의 모델 결과를 합쳐 정확도 개선으로 보고하지 않는다.

## 확인 방법

저장소 루트의 [시험 안내](../../../README.md)를 따라 A 본체·표 단위·API, 공용 계약, 기존 파이프라인 시험을 별도 프로세스로 실행한다. 외부 연결 없는 시험을 기본으로 한다.

평가 자료 묶음을 지정하지 않으면 관련 기존 평가 시험은 건너뛴다. 극성 확정본 외부 원본과의 추가 비교는 `CLAVIEW_A_POLARITY_SOURCE`에 원본 파일 경로를 명시한 경우에만 실행한다. 저장소 안 극성 fixture와 직접 시험은 이 설정 없이도 실행된다.

최종 수정 커밋·실행한 시험 수·저장 응답 비교 결과는 PR 본문에 고정한다. 이 문서는 아직 실행하지 않은 확인을 통과로 기록하지 않는다.

## 후속 변경: 최근 범위와 되묻기 선택지

최근 N년·반기·분기·개월은 A 카탈로그의 해당 표·주기 최신 수록 시점을 포함한 연속 N기간으로 계산한다. 월별 표의 끝이 2026-08이면 최근 3년은 2023-09~2026-08이다. 기간을 말하지 않으면 여전히 묻고, 선택하지 않은 기본 기간을 적용하지 않는다. 모델은 기간의 의미·수량·단위만 구조화하며 실제 날짜는 코드가 계산한다.

명시 날짜와 달력 상대 구간(올해·작년 등)의 기준은 이 변경에서 유지한다. B가 제공할 상대 표현 예시표와 대조해 추가 정렬할 범위는 별도로 기록한다. '2020년부터' 같은 열린 범위, 여러 판본의 이어 붙이기, 여러 통계의 공통 기준을 최근 N기간의 규칙으로 일괄 바꾸지 않는다.

되묻기 선택지는 실제 적용할 표·주기별 범위를 표시한다. 주기가 아직 여러 개면 주기별 범위를 구분하고, 하나의 확정 범위인 것처럼 합치지 않는다. 사용자 답의 원문·선택값·대상 통계·출처는 보존한다. 기간과 주기를 모두 결정하기 전에는 B 송신 준비가 완료된 것으로 보지 않는다.

이번 변경은 A의 계산과 선택지·답 적용 검증에 한정한다. B의 실제 수록 정보와 조회 결과, 연결 파이프라인의 우선순위, B의 입력 계약을 구현한 것이 아니다. 새 지시문으로 모델을 호출하지 않으므로 저장 응답 재검사는 새 모델 품질의 근거가 아니다.

## B 계약 후속 협의와 A 요청 회신

되묻기로 확정된 필드는 A 값을 우선하고, 그 밖의 A 기간은 참고하며 B가 최종 조회 범위를 정한다. 단순 참고값 차이로 중단하지 않도록 하는 연결 변경은 본 수정과 분리한다.

현재 보장되는 값, 아직 B에 전달되지 않는 출처, 주기 경계와 계산용 구간, B 수신부 후속 순서는 [A 최근 기간 수정과 B 되묻기 연결 회신](A_최근기간_수정과_B_되묻기_연결_회신_20261102.md)에 정리했다. B의 수신 지원이 확인되기 전에는 기존 미지원 보류를 해제하지 않는다.
