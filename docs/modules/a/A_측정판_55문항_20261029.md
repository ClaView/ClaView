# A 측정판: 기간·주기 검사와 제한 재검색, 55문항 측정 (2026-10-29)

> 이 문서는 작성 당시의 공유·측정 이력이다. 현재 단일 AView 실행 경로와 API는 [구조](../../ARCHITECTURE.md)·[HTTP 계약](../../contracts/A_HTTP_전환_20261102.md)을 따른다. 종료한 실행 경로와 과거 점수는 현재 동작을 뜻하지 않는다.

> **상태: 화면 연결 전.** 새 A(`claview_a`)는 패키지·CLI·평가기에서만 쓴다. `claview_a_api`(`/a/select`, `/a/answer`)와 staged 화면은 아직 기존 A(`claview_a_legacy`)를 부른다.
>
> **결과의 성격: 개발 문항 측정.** 아래 수치는 개발에 반복해 쓴 문항을 이 판으로 한 번 돌린 결과다. 독립 정확도가 아니고, 모든 질문의 성공을 뜻하지도 않는다.

- 이전 기준판: [A 기준판: 표 단위 경로 (2026-10-28)](A_기준판_표단위경로_20261028.md)
- 이 문서는 이 판을 이후 변경(카드 정보 보완 등)과 비교할 기준으로 남긴다. 남은 문제는 4절에 적었고, 해결된 판으로 보지 않는다.

## 1. 무엇이 바뀌었나

역할 분담은 그대로다. 의미·기준·되묻기는 모델이 판단한다. 코드는 근거·참조·명시 기준을 검사하고, 같은 기준 안에서 주기·기간·판본을 고른다.

| 영역 | 내용 | 버전 |
|---|---|---|
| 기간 읽기 | 명시 기준년(`2020=100`, `기준연도 2020년`, `2015년 기준년`)만 관측 기간에서 뺀다. 홀로 쓴 'YYYY년 기준'은 그 연도다. 인용 표현 하나 안에서 그 바로 뒤에 다른 기간이 붙은 경우(`2015년 기준 2024년`)만 `period_base_year_ambiguous`로 멈춘다. '최근 N개 분기·반기'는 '최근 N분기·반기'와 같다. 기본 기간을 쓰면 이유를 기록한다 | periods .10, q_rules |
| 요청 주기와 되묻기 | 질문이 주기를 하나 명시하고 읽을 수 있으면, 되묻기 선택지 값마다 그 주기를 주는 표가 있어야 한다. 선택지 표 자체나, 같은 기준의 주기·판본 후보가 인용 항목을 보존하는 경우를 센다(기간·판본 선택과 같은 보존 규칙). 주는 표가 없으면 `ask_invalid`, 주기는 있으나 보존을 확인하지 못하면 보류다. 지시문 판단 순서 4·6·7도 같은 내용으로 맞췄다 | check .19, 지시문 |
| 명시 기준 검사 | 카드의 갈림과 별개로, 통계가 명시한 기준을 선택 표와 되묻기 선택지에서 확인한다(충돌은 멈춤, 확인 못 하면 경고) | check |
| 제한 재검색 | 네 조건을 모두 만족할 때만 재검색 뒤 재판단을 최대 1회 한다: ① 실행이 그 문항에 재검색을 허용했다. ② 첫 판단의 모든 통계가 구조 검사를 통과한 `missing`이다. ③ 재검색에서 카드에 없던 새 후보가 나왔다. ④ 입력 24,000자와 호출 한도를 넘지 않는다. 하나라도 어긋나면 이유를 기록하고 재판단하지 않는다. 기존 카드는 순서대로 남긴다. 추가 상한 10은 형제 표로 넓히기 전의 검색 적중 표 수다. 형제 표까지 합친 최종 추가 표는 10개를 넘을 수 있다(found·added·cut 기록). 재판단 입력에는 미해결 통계와 조건 인용(`unresolved`)이 들어가고, 출력 계약은 같다. 다시 missing이면 끝내며 세 번째 판단은 없다 | graph .4(research .2), pool .3, contract |
| 평가기·실행기 | 통계별 조건 진단, 요청 대상 목록, 되묻기 선택지 사실, 모델 비교(`compare.py`), 개발 탐색 실행기(`explore.py`)를 더했다. 재판단 모델과 지정 문항, 문항·모델·전체 호출 한도는 전송 직전에 검사한다. 키는 레포 루트 `.env`의 `OPENAI_API_KEY`에서 읽는다(값은 기록하지 않음) | score .20, report .4, live .6, explore .4, compare .2 |

## 2. 측정 구성

- 문항: 골든 42(CV-AB 16 + golden26 26) + 개발 탐색 13 = 55문항. 골든과 탐색이 겹치는 GV4-01·16은 한 번만 돌렸다.
- 모델: 최초 판단 `gpt-6.1-terra`, 재검색 후 재판단 `gpt-6.1-sol`. 둘 다 effort low, 출력 4096, 재시도 0.
- 같은 판의 결과를 재사용한 문항과 새로 실행한 문항을 나눈다.

| 출처 | 문항 | 호출 |
|---|---|---|
| 재사용(계획 46, 같은 판) | CV-AB-02, CV-AB-03, CV-AB-22, B:CX-Q093, Q082 | Terra 6 + Sol 3(대조 문항 SB:CQ1-03 포함) |
| 신규(계획 47 2차) | 나머지 50 | Terra 50 + Sol 1 |
| 계획 47 1차(별도 기록) | 같은 50 | Terra 50회 전송, 모두 `http_403`(키 권한). 사용량은 0이지만 호출 시도 50회로 센다 |

- 계획 47의 전송 시도는 101회(1차 50 + 2차 51)다. 2차는 키 권한을 고친 뒤 재승인을 받아 새 폴더에서 돌렸다.
- 비용은 사용량과 적용 단가로 계산했다. 계획 46은 약 $0.0645, 계획 47 2차는 약 $0.253이다. 캐시 쓰기는 입력 단가로 가정했으므로 확정 청구액이 아니다.

  - Q082: 카탈로그 밖 질문이다. 재검색 뒤에도 missing으로 끝났고, 이것이 목적에 맞는 결과다.

## 4. 남은 한계

- **카드 정보 부족(Q058, 확인됨)**: 카드에는 질문 낱말과 맞은 항목만 보인다.
  - Q058은 카탈로그의 결제수단 값(신용카드·계좌이체·가상계좌·기타)이 카드에 없어, 모델이 결제수단별 분해를 확인하지 못하고 missing을 냈다.
  - 새 후보가 없어 재판단도 하지 않았다. 별도 변경으로 다룬다.
- **기존 후보를 놓친 missing(Q004, 원인 미확정)**: 맞는 표가 첫 카드에 있었는데 최초 판단이 missing을 냈다. 카드 정보 부족인지 모델 판단 문제인지는 추가 진단이 필요하다.
- **조건 인용 누락 시 기본 기간**: 모델이 질문의 기간·주기 표현을 인용하지 않으면 코드는 기본 기간(예: 최근 10년·연간)으로 진행한다. 최초 판단과 재판단 모두 그렇다. 이번 55문항에서는 0건이지만 가짜 출력 반례로 확인한 구조적 빈틈이다.
- **명시 기준 확인 경고**: 질문의 명시 기준을 표 제목에서 확인하지 못하면 `stated_basis_unverified`가 남는다. 이번에 11기록이고 채점은 맞았다. 경고는 풀린 것이 아니다.
- **기간 부족 경로**: CV-AB-05는 이번에는 맞았다. 하지만 기간이 모자라는 표를 고르면 `period_not_covered`로 멈추는 경로는 그대로이고, 다른 기준의 표로 바꾸지 않는다.
- **정책 결정 대기**: CV-AB-10·14 정책 보류, 그리고 2024년 요청에 2016·2014년에 끝나는 판본으로 되물은 Q079의 처리는 결정 대기다.
- **실행기**: 첫 401·403에서 이후 전송을 멈추는 장치는 아직 실행기에 없다(측정 2차는 실행 스크립트에서 감싸 돌렸다).

## 5. 재현

평가 문항·정답·원응답은 레포 밖 평가 묶음에 있다. 팀장에게 받아 레포 밖에 푼다.

|---|---|
| `claview_a_eval_20261029.zip` | `9eb6256b5d5242980a2aa1442caff1d8908b9c5683f9b5c57e5f532bb80c49eb` |

- 묶음 안의 `README.md`(구성·배치·실행)와 `SHA256SUMS.txt`(73개 파일)로 내용을 확인한다.
- 2026-10-28 묶음의 파일을 모두 포함한다. 키·`.env`·인증 정보는 없다.

```bash
export CLAVIEW_A_EVAL_DIR=<푼 폴더>/tl_eval
PYTHONHASHSEED=0 PYTHONPATH=modules/a python -B -X utf8 -m pytest modules/a/tests_tl -q -p no:cacheprovider -rs
python -B -X utf8 <푼 폴더>/scripts/replay_run.py <푼 폴더>/runs/plan47/live   # 50문항: all same: True
```

- 재생은 원응답을 바이트까지 같은 요청에만 되돌려 주고, 최종 결과를 원기록과 비교한다. 레포 코드가 같은 입력에서 같은 결과를 낸다는 확인이며, 새 입력에 대한 모델 성능 확인은 아니다.
