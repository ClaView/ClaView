## 1. 무엇이 바뀌었나

새 A는 질문과 후보 카드를 모델에 그대로 주고, 모델이 통계표 단위로 고른 결과를 코드가 검사한다(표 단위 경로). 모델 호출은 질문당 1회다.

| | 기존 A (`claview_a_legacy`) | 새 A (`claview_a`) |
|---|---|---|
| 판단 | 규칙 경로(질문 분해 → 단계별 규칙·검증) | 모델이 카드를 읽고 표 단위로 판단, 코드가 검사·보정 |
| 쓰는 곳 | `claview_a_api`(`/a/select`, `/a/answer`), staged 화면, `claview` 명령, 골든 22 평가 | `claview_a.run`, `python -m claview_a`, 평가기 `modules/a/scripts/tl_eval` |
| 시험 | `modules/a/tests_legacy` | `modules/a/tests`, `modules/a/tests_tl` |

새 A가 쓰던 이전 A 코드(카탈로그·검색·형제 묶음·기준어·조건어·기간 보조·모델 전송)는 실제로 쓰는 함수·상수·데이터만 골라 `claview_a` 안의 역할별 폴더로 옮겼다. 본문은 그대로 두고 import 줄과 파일 경로만 바꿨다. 옛 파이프라인 코드와 개인 폴더 의존은 없다.


### 기간 패키지를 `claview_a/periods/`에 둔 이유

- 팀장 결정(10/28): 레포에서 이 패키지를 쓰는 곳은 A뿐이라 A의 `periods`와 한 폴더로 합친다.
- 파일 하나로 합치지 않은 것은 이름이 겹치는 정의(`FREQUENCIES` 등)를 바꾸지 않기 위해서다.
- 원본(0.2.0) 대비: `resolver.py`, `policy.py`, `contract.py`, `_version.py`, `period_policy.json`은 바이트가 같다. 원본 `__init__.py`는 `core.py`가 되었고, 위치를 알리는 설명 3줄만 더했다. 판본(`0.2.0`)과 정책 판본(`period-policy/2026-10-21.1`)은 그대로다.

## 2. 실행

새 환경(외부 호출 없음):

```bash
uv venv .venv --python 3.12
uv pip install --python .venv/Scripts/python.exe -r requirements-dev.txt
```

```bash
PYTHONPATH=modules/a .venv/Scripts/python -B -X utf8 -m claview_a "2015~2025년 연간 실질 GDP 성장률 추이를 그래프로 보여줘." --as-of 2026-10-22 --judge fake
```

- `--judge fake`(기본): 고정 답으로 배선만 확인한다. 모델을 부르지 않는다.
- `--judge replay --replay-from <폴더>`: 그 폴더의 `calls.jsonl`에서 같은 요청의 저장 응답을 읽는다. 없으면 오류로 끝나고 실호출로 넘어가지 않는다.
- **CLI는 fake·replay만 한다. 실호출은 평가 실행기(`modules/a/scripts/tl_eval/live.py`: 승인된 manifest의 gates·호출 한도 검사)로만 한다.** `--judge live`나 `--manifest`를 주면 승인된 manifest여도 폴더·전송기·요청을 만들기 전에 거절한다.
- 결과는 `runs/a_cli/<시각>/`(git 제외)에 `calls.jsonl`, `state.json`으로 남고 화면에는 action·record·호출 수가 나온다.

코드에서는 `claview_a.run(question, judge, as_of=...)` 하나만 쓴다. 판단기는 `claview_a.judges`에 있다.

예전 pipeline CLI(`python -m claview_pipeline`, `claview` 명령)와 골든 22 통합 평가는 **기존 A(`claview_a_legacy`)**로 돈다. 그 17/22는 새 A의 결과도, 화면 연결 결과도 아니다.

동작과 관계없이 위치·이름 때문에 달라진 값이다.

- 보고서에 적는 기준 파일 경로: `eval/tl_eval/<파일 이름>`(파일은 `CLAVIEW_A_EVAL_DIR`에서 읽음)
