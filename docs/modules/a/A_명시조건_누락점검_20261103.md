# A 명시 조건 누락 점검

## 변경 범위

원문에 있는 금액의 통화·배율과 `YYYY=N` 형태의 지수 기준이 A 산출물에서 모두 빠지는 경우를 검사한다. 기존 출력 계약의 focus, 극성과 적용 통계가 있는 splitter, 실제 선택된 표의 검증된 카드 인용과 범위가 확인되는 카탈로그 단위를 대조한다.

통계 이름이나 원문을 넓게 인용했다는 사실만으로 조건이 반영됐다고 보지 않는다. 표 전체에서 변하지 않는 단위나, 실제 선택 근거와 유일하게 연결된 항목의 단위는 별도 카탈로그 근거로 인정한다. 다른 표의 근거, 일부 항목의 단위, 동명이거나 연결이 불확실한 항목을 전체 요청의 보장 근거로 확대하지 않는다. 문항 ID·표 ID별 예외나 사후 골든 정답 변경은 추가하지 않는다.

혼합 단위 표의 항목 근거는 카탈로그 계층에서 자식이 없는 항목으로 한정한다. 부모 항목 단위로 자식의 단위를 보장하지 않는다. 이 제한 때문에 부모 집계값 자체를 요청했지만 모델이 단위 조건을 빠뜨린 경우에는 추가 근거가 필요할 수 있다. 인용 항목 목록이 자연어 요청의 모든 대상을 담았는지까지 코드가 증명하는 것은 아니다.

이는 제한된 형식의 **누락 검사**다. 자연어 전체의 의미나 B의 조건 적용, 조회·계산 완료를 증명하지 않는다. 조건의 적용 대상과 극성은 모델이 판단하며, 코드는 발견한 표현을 모든 통계의 필수 조건으로 자동 적용하지 않는다.

## 복구와 보존

누락이나 극성 해석 실패는 기존 A 자체 복구 1회를 공유한다. 별도의 호출 슬롯이나 재시도를 추가하지 않는다. 정상 focus·기간·주기·계산·기준 조건은 유지하며 누락된 조건만 기존 `splitters`의 `other` 행으로 보완한다. 복구에 실패하면 확정이나 성공으로 표시하지 않는다.

사용자가 이미 명시한 조건을 새로 선택하도록 되묻지 않는다. 사용자가 정해야 할 정보가 부족할 때의 기존 되묻기 정책은 유지한다.

## 연결 경계

- A 출력 계약과 AView, B 수신 계약에는 새 필드를 추가하지 않는다.
- `other` 행을 남겼다는 사실은 B가 그 조건을 적용했다는 보장이 아니다. 현재 B는 원질문과 기존 focus·기간 조건을 받는다.
- A 전용 화면은 `A 조건 확정 · 조회 미실행`으로 표시하고, 조회하지 않은 이유를 미확정과 확인 범위 밖으로 구분한다.
- 사전 검색 연동은 이번 변경에 포함하지 않는다. A 보완을 병합한 뒤 별도로 구현·측정한다.

## 확인 방법과 결과 해석

기능별 반례로 누락 탐지, 선택된 표 근거, 적용 통계, 극성, 정상 조건 보존과 1회 복구를 확인한다. 과거 실제 응답을 재검사할 때 새 복구 응답이 저장되어 있지 않으면 공백으로 기록한다. 합성 복구 응답으로 코드 경로가 통과해도 모델이 실제로 복구했다고 보고하지 않는다.

최초 A62 실측과 수정 후 저장 응답 재검사는 별도로 기록한다. 지시문이 달라졌으므로 기존 응답 재검사를 새 지시문의 정확도 측정으로 사용하지 않는다.

메타 보장 보완 뒤 실제 저장 응답 62문항의 표·기간·주기·확정/되묻기 결과는 기준판과 같았다(확정 59, 되묻기 3). GV4-06·GV4-19·BOK-NEW-19는 카탈로그 근거가 확인되어 추가 복구가 필요하지 않았다. 최초 실측의 공식 60/62·엄격 59/62 판정은 사후에 바꾸지 않는다. 새 지시문의 실측은 별도 승인 대상이다.
