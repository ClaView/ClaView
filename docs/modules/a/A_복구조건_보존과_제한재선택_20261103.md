# A 복구 조건 보존과 제한된 표 재선택

## 범위

A 기간 조건 송신부 이후 보완이다. 변경은 `modules/a`와 이 문서에 한정한다. 출력 계약, 지시문, AView, B 수신 계약은 바꾸지 않았다. 재판단 판은 `.14`, 기간 처리 판은 `.23`으로 올렸다. 실호출과 사전 연동은 포함하지 않는다.

## 바뀐 동작

1. **정상 조건 보존.** 복구 대상이 아닌 focus, 계산 요구, 집계 의도, 기준 극성은 유지한다. 정상 focus와 계산 요구는 최초 판단에서 복사해 새 표를 다시 검사하며, 모델이 이를 바꿔 썼다는 이유만으로 유효한 표 교정을 거절하지 않는다. 공백만 다른 통계 인용은 유일하게 대응될 때만 연결한다. 기준 극성 수정은 실제 진단에 연결된 축·값·인용에만 허용하며 `필수`를 `허용`으로 약화하지 못한다. 실제 복구 응답과 코드가 보존한 최종 입력은 따로 기록한다. 인용 존재 확인은 의미 정확성의 증명이 아니다.
2. **명시 요청 기간 보존.** 최종 표 선택·판본 연결의 우회 경로에서도 원래 요청 범위를 유지한다. 허용되는 미공표 꼬리 구간은 마지막 표의 요청과 미공표 정보에 남긴다. 호환 판본들이 요청 전체를 실제 수록하면 개별 표의 미래 미수록만으로 막지 않고 기존 연결 검사를 진행한다. 그렇지 않은 미래 범위는 기존 사유로 중단한다. `2015~2027년`을 `2015~2025년`으로 줄여 성공시키지 않는다.
3. **명시 대상 보호.** 최초 후보 카드에서 확인되는 표 ID, 표명, 조사·기관 경로, 판본을 통계별 원문·focus 인용 범위와 대조한다. 고유한 명시 대상과 어긋나면 잘못된 표를 그대로 유지했더라도 채택하지 않는다. 양립할 수 없는 대상이 함께 언급되면 모두 필수 조건이라고 단정하지 않고 모호성을 기록한다. 이때는 최초 선택 표를 고정한 채 다른 오류만 고치며, 새 표를 고르지 못한다. 다른 통계에만 나온 이름은 빌려 쓰지 않는다. 이는 복구 단계의 보호이며 첫 선택 전체의 의미 검증을 대체하지 않는다.
4. **제한된 재선택.** 선택한 표의 과거 수록 범위만 부족하고, 최초 후보 안에 명시한 전체 기간·주기와 인용 항목을 모두 지원하는 대체 표가 있을 때 기존 복구 1회에서 재선택을 검토한다. 코드가 정답 표를 대신 고르지 않는다. 두 번째 모델이 카드 근거를 제시해야 하고, 재검사 뒤 채택한다.

## 재선택 제한

- 명시된 닫힌 단일 기간과 명시 주기(Y/H/Q/M)에만 적용한다.
- 최초 선택의 focus·카드 인용이 검증되어야 한다. 사용자 답, 부분 기간, 집계 요구, 명시 표·조사·기관·판본이 있으면 이 새 재선택 경로를 열지 않는다.
- 같은 기관, 동일한 알려진 기준·단위, 동일한 인용 항목을 가지며 요청 전체를 수록하는 최초 후보만 제시한다. 이 조건은 의미적 동등성의 증명이 아니다.
- 새로 검색한 표를 이 경로의 대체 후보로 추가하지 않는다. 기간·주기·대상 범위를 줄여 해결하지 않는다.
- 교정·재검색과 복구 1회를 공유한다. 이미 썼다면 추가 판단을 하지 않는다.

## 유지하는 기간 정책

`최근 N기간`의 최신 수록 기준 계산은 그대로다. 이번 기간 수정은 명시 기간을 조회 가능 범위로 잘라 성공시키던 문제를 다룬다. 요청 범위, 조회 가능 범위, 미공표 구간은 서로 구분한다. B의 사용자 답 우선·참고값 처리 계약도 바꾸지 않는다.

## 오프라인 확인

- 추가·보완 직접 시험: 정상 조건 보존 22건, 명시 기간 보존 8건, 재선택·명시 대상 보호 28건, 복구 입력 보존 14건, 모호한 명시 대상 9건, 미래 수록 판본 연결 11건 통과.
- A 회귀: 본체 333건(환경 의존 4건 건너뜀), API 178건, 판단 1,624건(자료 부재 등 52건 건너뜀) 통과. 판단 시험 중 가짜 키 파일을 만드는 7건은 검수 실행기의 보호가 시험 임시 파일까지 차단해 첫 실행에서 실패했다. 실제 키 경로 차단을 유지하고 이 실행의 가짜 임시 파일만 허용한 뒤 해당 파일의 9건을 재실행해 통과했다. 제품 코드는 이 때문에 바꾸지 않았다.
- 되묻기·복구 조합 반례 7건과 기존 API 핵심 17건 통과. 사용자 미정은 되묻고 내부 오류만 1회 복구하며, 답 적용 중 모델 호출이 없고 정상 통계는 보존되는 것을 확인했다.
- 저장 응답 62문항: 기존 최종 결과 변화 0, 보관 응답 63개와 요청 해시 63/63 일치. 기존 정상 복구 문항도 그대로다.
- CV05의 새 재선택에는 실제 두 번째 응답이 없다. 저장 첫 응답과 별도 합성 두 번째 응답으로 정상 재선택·원래 표 유지·조건 유실을 각각 확인했다. 모델 정확도 향상으로 세지 않는다.
- 백엔드 재생에서 명시 요청 기간 보존을 확인했다. 실제 프론트엔드에서는 정상·실패 결과, 재선택 표·focus, 되묻기 답 적용을 확인했으며 아래의 기존 상태 표시 문제도 재현했다. 모델·B·KOSIS 실호출은 없다.

## 남은 확인과 후속 작업

- CV05의 실제 재선택 품질은 별도 승인한 모델 호출로 확인해야 한다. 현재 재생으로 성공 실측을 주장하지 않는다.
- 누락 분류 조건을 고치면서 focus 전체를 다시 쓴 경우, 현재 계약은 수정할 분류 조건만 분리하지 못한다. 기존 범위를 확인할 수 없으면 보수적으로 거절한다. 원래 focus와 복구 문구 전체를 붙여 성공시키지 않는다. 그 방식은 새 제외·축소 요구가 섞이는 것을 막지 못하기 때문이다.
- 제외한 표 이름 하나만 등장하는 경우는 현재 명시 대상 추출만으로 긍정 요구와 구별할 수 없다. 모호한 여러 대상의 보호를 완화한 것이 이 단일 제외 표현까지 해결한 것은 아니다.
- A만 실행해 `a_verified`인 경우에도 현재 프론트엔드가 `ui_cases` 부재를 중단으로 표시하는 문제가 있다. B·C 조회를 하지 않은 것과 A 실패를 구분하는 파이프라인·화면 후속 작업이 필요하다. 이 보완에서 해당 소스는 바꾸지 않았다.
- PR #37 병합으로 지원 B에 `b_request`를 보내고 참고 기간 차이는 기록하며 진행하는 연결이 추가됐다. 사용자 답 보호, 요청·조회·미수록·계산 구간의 화면 전달은 각각 구분해서 확인한다. 서로 다른 통계 기간을 A 단계에서 보류하는 기존 조건은 별도 검토 대상이다.
- `period_differs_between_requests`는 이번에 없애지 않는다. 서로 다른 표에 2023년·2024년을 각각 요구한 합성 반례에서 A 조건은 그대로 전달됐지만 현재 B는 두 표 모두 원질문의 전체 2023~2024년으로 계산했다. B의 표별 문맥 해석, 지원 확인 및 준비 실패 경로를 함께 보완한 뒤 해제해야 한다. 참고 출처를 `user_answer`로 바꿔 우선 적용을 강제하지 않는다. 나머지 판본 연결·비연속 범위·같은 표의 다른 조건 차단도 유지한다.
- 통계어사전은 추후 검색 후보를 넓히는 데 사용한다. 검수된 동의어·축약어로 검색어를 확장하고 원문 검색 결과와 합친다. 사전의 관련어는 표의 실제 메타 근거나 사용자 조건을 대신하지 않는다.
