# 기간 조건 화면 안내 (2026-11-03)

- 대상: 화면 경로 `pipeline/claview_pipeline/staged.py`(카드 모델), `frontend/src/service_ux.js`·`service_ux.css`(요약 블록). B 수신부(#36)와 파이프라인 연결(#37)이 `main`에 들어간 뒤의 후속이며 B 코드는 바꾸지 않음.
- 범위: B가 표마다 돌려주는 `period_resolutions`를 카드로 옮김. 사용자가 고르는 값이나 B의 판단은 바꾸지 않고 보여 주기만 함.

## 1. 표시 범위 (`requested_period`)

B가 비교 계산용으로 요청 기간 앞을 더 읽으면(`calculation_extra`) 조회 결과에는 그 구간이 들어 있음. 지금까지 B가 `requested_period`를 채워 주지 않아 카드에 조회한 전체 기간이 그대로 나왔음.

- `display_range(rows)`: 행마다 `requested`와 `fetched`의 겹침을 구하고, 모든 표가 같은 주기·같은 범위이며 계산용 구간이 있을 때만 `{frequency, start, end}`를 돌려줌. 표마다 범위가 다르거나 겹침이 없으면 None이며 기존대로 조회한 전체 기간을 보여 줌.
- `_render_data`가 이 값을 `requested_period`로 넣음. 기존 경로(주기 맞춤 시 변환, 여러 요구 합치기 시 일치할 때만 유지, C의 표시 기간 검사)를 그대로 씀.
- C가 이 범위를 받아들이지 않으면 한 번만 `requested_period` 없이 다시 그림(`state["display_range_dropped"]`). 조회한 전체 기간이 보이고 계산용 구간이 섞였다는 기존 안내가 붙음.

## 2. 카드 `periodInfo`

카드의 표(`table_ids`)에 해당하는 `period_resolutions` 행마다 한 항목을 싣음. B가 기간을 알려 주지 않은 경우(지원하지 않는 B, 조건 없음)에는 키 자체가 없음.

| 필드 | 내용 |
|---|---|
| `requested` / `fetched` | 요청한 기간 / 실제로 읽은 기간(계산용 구간 포함). `2024년 1월 ~ 2024년 12월` 형식 |
| `missing` | 요청했지만 표에 없는 기간 |
| `substituted` | 요청한 기간이 통째로 표에 없어 조회 가능한 기간으로 바꿨는지 |
| `extra` | 계산용 구간과 목적(`전년 같은 기간과 비교하기 위한 기준 기간` 등). 화면에는 표시하지 않음 |
| `sources` | 기간·주기를 누가 정했는지(`사용자가 고른 값`, `질문 문구로 B가 계산`, `A가 질문에서 읽은 기간`) |
| `alternatives` | 가능하지만 자동으로 조회하지 않은 다른 주기 |

화면(`service_ux.js`)은 요약 아래에 "요청한 기간 · 조회한 기간 · 표에 없는 기간 · 대체 조회 · 계산용 기준 기간 · 결정 근거"를 작은 블록으로 보여 줌. 표가 둘 이상이면 표 이름을 제목으로 붙임. `periodInfo`가 없으면 기존 "요청 표시 기간" 문장을 그대로 씀. 폭 520px 이하에서는 항목을 세로로 쌓음.

## 3. 안내 문구

- B가 `visible: true`로 표시한 안내(`table_lag`, `requested_period_partly_unavailable`, `requested_period_substituted`, `stated_end_beyond_table`, `confirmed_period_partly_unavailable`, `a_quoted_period_used`)를 카드 경고에 한 번만 싣음. 기존 `period_notices`로 이미 카드 안내에 같은 문구가 있으면 다시 싣지 않음(첫 줄 기준).
- `visible: false`(`reference_period_differs`, `calculation_range_extended`)는 화면에 내지 않음.
- 요청 표시 기간이 없을 때 붙던 "비교 계산용 기준 시점이 포함될 수 있습니다" 안내는 B가 기간을 알려 줬고 계산용 구간이 없으면 붙이지 않음(실제로 기준 시점이 없는데 있다고 안내하던 경우).

## 4. 이번에 바꾸지 않은 것 (후속)

- 안내 문구 안의 기간은 B가 쓴 그대로(`202610` 형식)임. 문구는 B 소관이며 화면 블록의 기간만 `2026년 10월`로 표시함.
- 표마다 표시 범위가 다른 경우의 개별 표시. 지금은 조회한 전체 기간을 보여 주며 `periodInfo`로 표마다의 범위를 확인할 수 있음.
- 명시 연도 일부 미수록 시 교집합 처리(B 1.3), A `_handoff` 차단 완화, 실호출.
