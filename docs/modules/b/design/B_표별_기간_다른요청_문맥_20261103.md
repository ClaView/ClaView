# 다른 요청의 기간 문구 전달 (2026-11-03)

- 대상: B `claview_b_api/service.py`(`resolve`의 선택 인자 `period_context`), `claview_b/period_condition.py`, `claview_b/stages.py`, 연결 `pipeline/claview_pipeline/staged.py`·`screen.py`. A·B 계약 필드(`PeriodCondition` 등)는 바꾸지 않음.
- 배경: A 검수 회신(`B_전달_PR39_실제호출경로_보완요청_20261103.md`). PR #39의 표별 기간 분리는 여러 표를 한 B 호출로 보낼 때만 동작하고, 실제 화면은 요구 묶음마다 B를 따로 호출함.

## 1. 원인

- `ScreenPipeline._run_b`는 A가 넘긴 묶음마다 `b.resolve(전체 질문, 그 묶음의 표)`를 부름. 정상 묶음에는 표가 하나임.
- `table_period_query`는 한 호출에 든 표들의 `period_phrase`로만 가림. 표별 호출에서는 다른 표의 문구가 호출에 없어 가려지지 않고, 기존 판독기가 질문 전체의 연도를 하나의 범위로 읽음.
- 같은 이유로 A가 넘기지 못한 통계(표를 못 찾음 등)의 기간 문구도 남은 표로 번짐. 이 경우는 A의 `period_differs_between_requests` 차단과 무관하게 현재도 발생함(PC-08).
- 표별 호출로 다시 돌린 기존 시험 사례: TP-01, 02, 02b, 03b, 04b, 07이 어긋나고 TP-03, 04, 05, 06, 08은 같았음.

## 2. 결정 사항(A·B·연결 합의)

- 실행 단위(표별 B 호출)와 다표 지시문·계열 보정·실패 격리·계열 상한은 그대로 둠.
- 다른 요청의 기간 문구만 선택 인자로 전달하며 가리는 데에만 씀. 표·계열·기간을 추가하지 않음.

## 3. 변경

- B 호출 인자: `BService.resolve(query, tables, as_of, period_context=None)`. `period_context`는 `[{"ref": 문자열, "period_phrase": 문자열}]`이며 `ref`는 다른 표 ID 또는 A가 넘기지 않은 통계 ID임. 항목 50개, 문구 200자 이하, 형식이 어긋나면 `invalid_a_result`. `BService.accepts_period_context = True`로 사용 가능 여부를 밝힘(HTTP API에는 아직 없음).
- 가리는 규칙: `table_period_query(query, key, conditions, outside)`가 `outside`의 문구를 다른 소유자의 문구로 취급함. 이 호출의 표와 같은 문구를 쓰면 공통 기간으로 가리지 않고, 다른 요청의 긴 문구 안에 든 짧은 문구는 긴 문구 쪽에 남는 규칙은 호출 안 다른 표와 같음.
- 파이프라인: `_run_b`가 묶음마다 `period_context`를 만들어 `accepts_period_context`가 참인 B에만 보냄. 내용은 (1) 같은 질문의 다른 묶음 표의 `period_phrase`, (2) B에 넘기지 않은 통계(차단·실패·답변 대기)의 기간 문구(A 판단의 `conditions.periods`를 ` / `로 이음). 보낼 것이 없으면 인자를 보내지 않음.
- 그대로 둔 것: 우선순위(사용자 답 필드 우선, 그 외 B 계산, `quoted`는 문구를 못 읽을 때의 예비값), `period_resolutions`, `quoted`→`user_answer` 변환 없음, A 참고값 강제 적용 없음.

## 4. 수락 시험

- 실제 파이프라인: `pipeline/tests/staged/test_screen_table_period_calls_1103.py`. 스크립트 A 판단 + 실제 BService(합성 모델) + 합성 조회로 `ScreenPipeline._run_b`의 묶음별 호출을 그대로 사용함. 사례는 `eval/cases/b/period/table_period_pipeline_calls_b.json`이며 기대값은 표별 질문 의도로 코드 수정 전에 정했음. 기록(`원질문 → 호출별 표·받은 기간·함께 전달한 문구 → 요청 범위 → 읽은 범위 → 조회 파라미터`)은 시험 파일을 직접 실행하면 출력됨.
- A의 차단 완화 이후 구조를 재현하려고 시험에서만 `view._months`를 같은 값으로 바꿔 `period_differs_between_requests`를 비활성화함. A 코드는 바꾸지 않음. PC-08만 현재 코드에서도 같은 결과임.
- B 단위: `modules/b/tests/b_part/test_b_period_context.py`. 표별 호출 재현(#39 사례를 표마다 따로 호출, 문구 전달 포함)과 가림 규칙·형식 검사.

## 5. 이번 범위와 남은 한계

| 항목 | 상태 |
|---|---|
| 표별 명시 연도·범위·순서 반전·최근 N기간 혼합 | 완료(실제 묶음별 호출로 확인) |
| 사용자 기간 답·주기 답·일부 표만 답함 | B 호출 단위로 확인(TP-05, TP-06을 표별 호출·문구 전달로 재현). 두 묶음이 이어지는 화면 흐름은 현재 A가 기간 인용이 없는 통계를 `period_quote_missing`으로 걸러 재현하지 못함 → A 완화 뒤 확인 |
| 공통 기간·단일 표·조건 없는 기존 요청 | 기존 동작 유지(PC-06, 단일 요청 시험, 기존 시험) |
| 인용 누락·원문 불일치·60자 초과로 문구가 없는 표 | 부분 지원: 그 표는 질문 전체를 읽음(어떤 단어가 그 표의 기간인지 알 수 없음). 다른 요청의 문구가 있어도 가리지 않음 |
| 표별 주기(`월별과 연간`) | 미지원: 주기 표현은 질문에 남아 두 표가 같은 주기로 읽힘. 표별 주기 문구 전달이 필요함 |
| 통계별 계산 요구(`M2만 전년 대비`) | 미지원: 계산 요구가 어느 통계에 붙는지 알 수 없어 모든 표에 적용(읽는 범위만 넓어지고 요청 범위는 정확). 필요 정보: 계산 요구의 대상 통계 |

- A 차단 완화의 범위는 위 표의 완료 항목까지로 권함. `period_quote_missing`, 표별 주기, 통계별 계산 요구가 걸린 질문은 A 차단을 유지하는 것이 안전함.
