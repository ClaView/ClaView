# 기간 조건 파이프라인 연결 (2026-11-03)

- 대상: 화면 경로(`pipeline/claview_pipeline/screen.py`). A 송신부(#35)와 B 수신부(#36)가 `main`에 들어간 뒤의 연결 단계이며 계약은 [A_B_기간조건_공용모델과_A송신부.md](../../../contracts/A_B_기간조건_공용모델과_A송신부.md), [B 회신 v2](B_회신_기간_조건_수신_계약_제안_20261102.md), [B 수신부 구현](B_기간조건_수신부_구현_20261103.md)을 따름.
- 범위: 지원하는 B에만 `period_condition` 전송, `period_answer_contract_pending` 조건부 해제, 기간 불일치 중단을 `period_resolutions` 기준 검사로 대체. 화면 안내 개선, 실호출, A의 차단 완화는 포함하지 않음.

## 1. 동작

| 상황 | 처리 |
|---|---|
| B가 `accepts_period_condition is True` + A의 `b_request` 있음 | `b_request.tables`(focus와 표별 `period_condition`, 사용자 답 포함)를 B에 보냄. 기간 답변은 조건 안에 있으므로 보류하지 않음 |
| 지원 B + `b_request` 없음 + 기간 답변 있음 | 답을 뺀 채 보내지 않음. `period_condition_not_prepared`(사유 `b_request_issue`)로 보류하고 미지원 연결 항목에 남김 |
| 지원 B + `b_request` 없음 + 기간 답변 없음 | 기존 요청을 보냄(A가 조건을 만들지 못한 경우의 기존 동작) |
| 지원을 밝히지 않은 B | 기존 요청. 기간 답변이 있으면 기존대로 `period_answer_contract_pending` |

`BService`는 `accepts_period_condition = True`이므로 기본 화면 경로(`b_factory = BService`)는 지원 B로 동작함.

## 2. B 응답 확인 (`b_answered_period_not_applied`)

지원 B로 보낸 요청은 표마다 B의 `period_resolutions` 행을 확인함. 아래의 경우에만 조회하지 않고 중단함(`kinds`로 구분).

- 행이 없음(`resolution_missing`).
- 사용자가 답한 기간을 B가 그대로 적용하지 않음(`answered_period_not_applied`): `applied_sources.period != a_user_answer` 또는 `reference.differs.period`가 참.
- 사용자가 답한 주기를 B가 그대로 적용하지 않음(`answered_frequency_not_applied`).
- 선택 항목의 주기·기간이 행의 조회 범위(`fetched`) 밖임(`selection_outside_resolution`).

그 밖의 A·B 차이(상대 표현, 질문·표 기준 주기, 계산용 앞 구간)는 중단하지 않고 `state["period_reference_differences"]`에 기록함. 화면에 내는 안내는 B가 기존 `period_notices`로 함께 돌려주는 것(`table_lag` 등)을 그대로 씀. 지원하지 않는 B에는 기존 `b_period_differs_from_a` 검사가 그대로 적용됨.

## 3. B가 조건을 지킬 수 없어 멈춘 경우

`period_condition_not_representable`, `_frequency_unsupported`, `_out_of_coverage`는 B의 중단 코드가 그대로 `error_code`가 되며 사용자 문구(`MESSAGES`)를 추가함(다른 기간·주기로 바꾸지 않았다는 점을 밝힘). `period_condition_invalid`, `_answer_missing`, `_answer_conflict`는 A→B 계약 불일치 문구로 안내함.

## 4. 이번에 바꾸지 않은 것 (후속)

- A `_handoff`의 차단(`period_differs_between_requests`, `same_table_conditions_differ`, `edition_period_split`, `disjoint_period_not_in_b_contract`)은 A 소관이며 B 수신 지원 여부를 모르는 채 계산됨. B가 표별 조건을 받으므로 일부는 풀 수 있으나 A와 합의 후 진행함.
- 화면의 범위·미수록·대체 안내 문구와 카드 표시(`period_resolutions`를 화면 모델로 옮기기).
- `b_port.py`(옛 A 포트)의 표 필드. 옛 경로는 조건을 쓰지 않음.
- 실호출. 이 변경으로 소스 해시가 달라지므로 기존 실호출 승인을 그대로 재사용하지 않음.
