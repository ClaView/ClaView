# B 기간 조건 수신부 구현 (2026-11-03)

- 기준: A 송신부 초안 PR(`a/period-condition-sender-1102`, `00fd06c`) 위에 구현. 계약은 `docs/contracts/A_B_기간조건_공용모델과_A송신부.md`와 B 회신 v2(`B_회신_기간조건_계약_확정안_20261102.md`)를 따름.
- 범위: 표별 `period_condition`의 검증·필드별 우선순위·범위 계산·`period_resolutions` 반환, `BService.accepts_period_condition` 켜기. 파이프라인 자동 전송, 화면, `period_answer_contract_pending` 해제, A·B 불일치 비차단(다 묶음)은 이 PR에 넣지 않음.

## 1. 처리 흐름 (코드 위치)

| 단계 | 내용 | 위치 |
|---|---|---|
| 읽기·검증 | `BSteps.load`가 표마다 `PeriodCondition`으로 검증하고 계약 코드(`period_condition_invalid`, `_answer_missing`, `_answer_conflict`)로 거절함. 없는 표는 기존 경로 | `period_condition.parse_condition` |
| 계획 | `BSteps.context`가 표별로 `plan_table_period`를 호출해 주기·요청 범위·조회 범위를 정함 | `stages.plan_table_period` |
| 모델 | 모델에는 조건을 보내지 않음(`selected_tables`에서 `period_condition` 제거). 확정·quoted 기간은 코드로 적용하고 모델에 보이지 않음. 상대 표현으로 계산한 기간만 기존대로 보임 | `BSteps.context` |
| 반환 | 마지막 표에서 `result["period_resolutions"]`를 표마다 조립함. 조건이 하나도 없으면 키 자체가 없음 | `period_condition.resolution_row` |

## 2. 필드별 우선순위 (구현된 동작)

| A가 보낸 출처 | 기간 | 주기 |
|---|---|---|
| 기간·주기 모두 `user_answer` | A 값. 질문을 다시 해석하지 않음. 표가 가진 부분만 조회(교집합), 나머지는 `missing` | A 값. 표에 없으면 `period_condition_frequency_unsupported` |
| 기간만 `user_answer` | A 값 | 질문이 말한 주기. 없으면 표가 가진 주기 중 그 기간을 정확히 표현하는 가장 긴 주기, 나머지는 `frequency_alternatives`. 정확히 표현하는 주기가 없거나 질문이 말한 주기가 그렇지 않으면 `period_condition_not_representable` |
| 주기만 `user_answer` | B가 질문에서 계산(A 기간은 참고) | A 값 |
| 둘 다 아님 | B가 계산(A 값은 기록만, 달라도 중단하지 않음) | B가 정함 |
| B가 기간을 읽지 못함 + 기간 출처 `quoted` | A 기간을 사용하고 `a_quoted_period_used`를 안내함. 정확히 표현되고 표 범위 안일 때만. 아니면 기존처럼 `conditions_incomplete` | 질문·표 기준으로 B가 정함 |

- 확정 기간이 표와 전혀 겹치지 않으면 `period_condition_out_of_coverage`로 중단함. 다른 기간으로 바꾸지 않음.
- B가 계산하는 달력 표현(작년·올해 등)의 대체 규칙은 2026-11-02 합의 그대로임. 요청 범위는 as_of 달력으로 유지하고 `substituted: true`와 `missing`으로 표시함.
- "전년 대비" 같은 비교 표현이 있으면 표시 범위 앞 구간을 더 조회하고 `calculation_extra`(`yoy_baseline`, `previous_period_baseline`)로 구분함. 확정 기간에도 마찬가지임.
- 안내(`notices`)는 코드와 `visible`로 구분함. 화면에 내는 것: `table_lag`, `requested_period_partly_unavailable`, `requested_period_substituted`, `stated_end_beyond_table`, `confirmed_period_partly_unavailable`, `a_quoted_period_used`. 기록만: `reference_period_differs`, `calculation_range_extended`.

## 3. 오류의 상태 값

- 입력 검증 실패(`period_condition_invalid/_answer_missing/_answer_conflict`): `error`.
- 사용자 확정 조건을 지킬 수 없어 중단(`_not_representable`, `_frequency_unsupported`, `_out_of_coverage`): `unresolved`. 재질문·지원 불가 안내는 A·파이프라인이 정함.

## 4. 리뷰 때 확인할 판단

1. 질문에 명시한 연도가 표 범위를 일부 벗어나는 경우는 이번에 바꾸지 않아 기존대로 `metadata_refresh_required`로 중단함. B 회신 1.3절은 "교집합 조회 + 미수록 표시"로 읽힐 수 있어 이 부분은 후속에서 합의 후 바꿀 수 있음.
2. `a_quoted_fallback`은 A 기간이 표 범위 안에 전부 있을 때만 사용함. 일부만 있을 때 자르지 않고 중단함.
3. `reference_period_differs`(기록만)는 기간을 B가 계산했고 A의 참고 기간과 다를 때만 만듦. 이에 맞춰 공통 예시표 PC-43의 두 번째 표 기대값에 이 안내를 추가함(이전 판은 빠져 있었음, 다른 항목 변경 없음).
4. 조건이 있는 요청에서 B가 기간을 정하지 못한 표(조건 없음 + 모델이 고른 기간)는 `period_resolutions`에 행을 만들지 않음. 같은 요청의 다른 표는 행이 있음.
5. 계산용 구간은 표시 구간 바로 앞에 이어 붙여 하나의 연속 구간(`fetched`)으로 조회함. A 합성 예시(`both_answers`)처럼 전년 동월만 따로 떼어 조회하지 않음.
6. `frequency_alternatives`는 비어 있어도 항상 포함함(A 합성 예시와 같은 모양).
7. 확정 기간 일부 미수록과 quoted 사용에는 기존 화면이 읽는 `period_notices` 항목(`period_requires_confirmation`)도 함께 만듦.
8. 기존 HTTP 가드 시험은 실제 `BService` 대신 지원을 표시하지 않는 대역 수신기로 바꿈. 실제 `BService`는 `accepts_period_condition = True`로 지원을 표시하며 별도 시험이 이를 확인함.
