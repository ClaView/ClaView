## B-1. 사용자 답 기간을 계열 선택 모델에도 제공

### 수정

- 위치: `modules/b/claview_b/stages.py`의 `BSteps.context`와 새 보조 함수 `period_not_in_question`.
- 규칙: 계획된 기간의 출처(`applied.period`)가 `a_user_answer` 또는 `a_quoted_fallback`이면 `resolved_period`를 모델 요청에 넣는다. 질문에 적힌 연도의 기간은 지금까지처럼 모델에 보이지 않으며(CV-AB-04에서 하위 항목 과선택이 있었던 기록), 상대기간 문구로 계산한 기간만 기존대로 보인다.
- 모델 응답 뒤의 처리는 그대로다. 코드가 `apply_resolved_period`로 기간을 덮어쓰고 검증한다. `period_condition` 자체(출처·답 기록·A 문구)는 모델 요청에 넣지 않는다.
- 기간만 답한 경우와 주기만 답한 경우를 구분한다. 주기만 답하고 기간은 질문의 연도에서 읽을 때는 기간을 보여 주지 않는다. 필드별 출처는 `period_resolutions.applied_sources`에 그대로 남는다.

### 완료 기준 확인

1. 실제 `BService`와 기록용 가짜 모델로 모델에 보내기 직전 입력의 `resolved_period`를 확인했다(`test_b_answered_period_yoy.py`, 사례 `eval/cases/b/period/answered_period_yoy_b.json` AP-01~04).
2. 기간만 답함(AP-01), 주기만 답함(AP-02), 둘 다 답함(AP-03)을 구분했다. 두 표 중 한 표만 답한 경우 다른 표의 질문 연도가 섞이지 않음을 확인했다(AP-04).
3. 실제 화면 경로(A 대본 → 표별 B 호출)에서 같은 동작을 확인했다(`test_screen_yoy_answered_1104.py`). 조회 파라미터는 답한 범위(M 202401~202412)를 유지했다.
4. 사용자 답을 적용할 수 없는 경우의 중단(`period_condition_*` 코드)은 바꾸지 않았다.

### 한계와 주의

- 기존 시험 `test_the_model_never_sees_the_condition_or_an_answered_period`(B API)는 "답한 기간도 모델에 보이지 않는다"는 이전 계약을 확인했다. 이번 변경으로 계약이 바뀌어 "조건은 보이지 않고 답한 기간은 보인다"로 고쳤다.
- 원인은 코드 읽기로 확인한 추정이다. 프롬프트가 "근거가 부족하면 selections를 비운다"고 하는데 기간 없는 질문에 `resolved_period: null`이 겹쳤다. 다만 지난 실호출 점검의 L2(분기별 질문, 답 "2024년 1월부터 6월까지")는 같은 구조에서 통과했으므로, 모델이 빈 응답을 낸 원인이 입력 부재 하나라고 단정하지 않는다. 입력 공백은 해소했으며 실제 모델의 반응은 재확인이 필요하다.
- 합성 모델은 입력과 무관하게 계열을 고른다. 따라서 오프라인 시험은 "모델에 보이는 입력"과 "조회 파라미터 유지"를 확인한 것이며 "실제 모델이 계열을 잘 고른다"는 증거가 아니다.

## B-2. 전년 동월 대비 기준 구간

### 수정

- 위치: `stages.py`의 `YEAR_OVER_YEAR` 한 곳. `detect_baseline_extension`, `baseline_purpose`, 명시 연도(`explicit_period_detail`), 사용자 답 기간(`_confirmed_detail`), 상대기간, `validate_period`가 모두 이 패턴을 공유하므로 경로별로 따로 고치지 않았다.
- 인식하는 표현: 전년(도)·작년 뒤의 대비, 보다, 동기, 동월, 동분기, 같은 달·분기·기간. 예: "전년 동월 대비", "전년동월대비", "전년동월비", "전년 같은 달보다", "작년 동월 대비". "전월 대비"는 이전처럼 전기 대비로 1기간만 확장하며, "전년도 말 잔액"처럼 비교 뜻이 없는 문구는 확장하지 않는다.
- 조회 방식은 기존 계약대로 **연속 조회**다. 2024년 월별 요청이면 2023-01~2024-12를 한 번에 읽고, `calculation_extra`는 2023-01~2023-12에 `purpose: yoy_baseline`을 붙인다. 요청 범위는 2024년으로 유지하며 카드에는 2024년만 표·내려받기 파일로 나간다. 2023년은 차트에 흐리게 표시한다(#42).
- 주기별 확장은 월 12, 분기 4, 반기 2, 연 1이다. 표에 없는 앞선 구간은 읽지 않으며 요청 기간 변경이나 0 대체는 하지 않는다.

### 확인

- 사례 YY-01~08: 표현별 6종, 사용자 답 기간(YY-06), 분기별(YY-07), 비교 표현 없음 대조(YY-08).
- 수정 전 코드로 같은 시험을 돌려 22건이 실패함을 확인했다(전년 동월 계열 표현의 확장 0, 답한 기간 미표시).
- 표별로 나눠 호출하는 실제 파이프라인 경로: 2024년 월별 요청의 KOSIS 호출이 M 202301~202412, 카드 표시는 2024년 12개월, 기준 연도는 `baseline`으로 분리됨을 확인했다.

### 한계

- "작년"은 상대기간 낱말이어서 "작년 동월 대비"는 상대기간 경로를 탄다. 확장 계산은 같지만 별도의 회귀 시험은 늘리지 않았다.
- 표별 주기와 통계별 계산 요구는 여전히 지원하지 않는다(질문 전체의 주기·비교 표현을 읽는다).

## C-1. 금액·수량 단위 계열의 직접 계산

### 구현

- 위치: `modules/c/claview_c/c_analysis.py`의 `yoy_amounts`(새로 추가)와 `calculate_rates`·`renderer`·`decorate_cards`.
- 계산식: **(해당 시점 값 ÷ 1년 앞선 같은 시점 값 − 1) × 100**. `Decimal`로 계산하며 단위는 %, 월은 12개월 전, 분기는 4분기 전, 반기는 2반기 전, 연은 전년과 비교한다.
- 계산 대상: 질문에 전년 대비 표현이 있고, 모든 계열의 단위가 금액·수량 단위인 경우. %·퍼센트·비율, 지수(`2020=100` 포함), 단위 미제공은 대상이 아니다. 이미 공표된 증감률(%)은 C가 계산하지 않고 공표값을 그대로 표시하며 기존 안내 문구가 유지된다. 단위가 비어 있어도 분류명(예: 금액(십억원))에서 확인되면 기존 `display_units`가 복원한 단위를 쓴다.
- 계산 시점 결정 순서: B가 알려 준 요청 표시 기간 → 사용자가 확정한 기간 → 질문에 연도가 하나뿐일 때 그해 전체. 어느 것도 없으면 임의로 정하지 않고 계산하지 않는다.
- 결측·0 처리: 현재값 또는 기준값이 없으면 그 시점을 비워 둔다. 기준값이 0 이하(음수 포함)여도 계산하지 않는다. 0%로 채우지 않으며 일부만 계산했으면 `complete: false`이며 계산 카드에 "일부 변화율은 기준값 누락·0 이하로 계산하지 않았습니다" 경고가 붙는다. 유효한 값이 하나도 없으면 계산 카드를 만들지 않는다.
- 원자료와 파생값의 분리: 계산 결과는 `derived` 카드로 원자료 카드 앞에 따로 둔다. 원자료 카드의 값·기준 시점·기준 구간은 바꾸지 않으며 안내에 "C에서 계산한 값이며 한국은행이 공표한 증감률이 아님", 계산식, 사용한 원자료 단위를 적는다. 계산 카드 제목은 주기에 맞춰 "전년 동월 대비 증감률" 등으로 나온다.
- 계산하지 못한 사유: 전년 대비를 물었는데 계산하지 못하면 사유를 `warnings`에 코드 `calculation_not_calculated`로 남긴다. 기존 "C에서 별도 증감 계산을 하지는 않습니다" 문구는 계산하지 않은 경우에만 나온다.

### 함께 고친 점

- 원자료 카드의 기준 구간(`baseline`, 흐리게 표시)은 원자료 단위 값이다. 계산 카드는 원자료 카드를 복사해 만들기 때문에 `baseline`이 따라와 % 차트에 원자료 값이 흐리게 붙을 수 있었다. 계산 카드에서는 `baseline`을 제거했다. 코드 읽기로는 기존 지수 전년 대비 카드도 같은 경로를 쓰므로 함께 해소된다.

### 확인

- C 직접 시험 23건(`modules/c/tests/test_c_yoy_amounts.py`): 정확한 값(합성 값으로 월별 증감률이 정확히 1~12%), 결측·기준값 0·음수, 주기별 기준 시점, 복수 계열, 단위 구분, 시점 결정 순서, 계산 카드와 원자료 카드의 분리, 사유 경고.
- 실제 화면 경로 시험: 합성 조회 값이 항상 "1"이므로 증감률은 0%로 나온다. 값이 아니라 배선(요청 기간 12개월, `baseline` 분리, 안내 문구)을 확인한 것이다. 합성 값에 의한 시험이며 실제 계산 검증으로 세지 않는다.
- 저장된 실제 원자료로 M2 증감률을 재생 대조하는 시험은 하지 않았다. 저장 자료에 비교 구간(전년 값)이 없고, 임의 값을 보충한 계산을 실제 검증으로 보고하지 않기 때문이다.

### 한계

- 통계별 계산 요구는 구분하지 않는다. 질문에 전년 대비 표현이 있으면 같은 카드의 금액 계열 전체를 계산한다(%·지수 계열이 섞이면 카드 전체를 계산하지 않는다). 카드가 둘 이상으로 나뉘면 계산 카드를 붙이지 않는다.
- 지수 계열은 기존처럼 특정 표 두 곳에서만 계산한다. 이번에 넓히지 않았다.
- 증감액·기여도·연쇄가중·최대 변화 시점은 금액 계열에 대해 지원하지 않는다.

## 회신 요청 항목 대응

1. B는 B-1·B-2를 구분해 수정 위치, 모델 전송 직전 입력, 조회 파라미터, 오프라인 확인 결과를 위에 적었다. 표별 실제 파이프라인 경로도 포함했다.
2. C는 금액·수량 단위 원자료의 전년 동기 대비 계산을 지원하며 미지원·부분 계산 상태는 위 한계와 `complete`·경고 코드로 구분한다. 연결·화면 표시는 별도 합의가 필요하다.
3. 사용자 답 우선순위, 표별 기간 분리, 요청·조회·계산 범위 보존은 신규 시험과 기존 B·파이프라인 회귀로 확인했다.
4. 수정 전 재현과 수정 후 검증을 모두 가짜·합성 전송으로 수행했고, 실제 프론트엔드 재확인은 하지 않았다.
5. 항목별 판정은 요약 표에 적었다. 추가 실호출이 필요하면 위 제안 범위로 별도 승인을 받는다.
