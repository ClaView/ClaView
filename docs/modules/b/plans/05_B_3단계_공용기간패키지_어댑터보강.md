## 2. 규칙 바로잡기 (합의 반영)

- 범위: 일부 겹침 → 겹치는 구간만 조회, 빠진 구간 보존(`periods.requested / covered / missing / calc_base / assigned`). 완전 비겹침 → 상태 `no_data_in_range` + 수록 범위. 해석기는 `metadata_refresh_required`를 내지 않는다.
- 주기: 명시 주기는 따로 판정(표에 없으면 `table_unsuitable`). 추론 주기(힌트 또는 기간 단위 재해석)는 가정일 뿐, 표에 없어도 표 탈락 근거가 아니다(단일 → 가장 긴 주기 + 대안, 안내). 혼합 단위는 조건 단위 중 표가 지원하는 가장 세밀한 주기, rule `period_unit_finest`. `inferred: []`와 칸 부재는 구분해 기록(`hint_state`)하고 둘 다 원 기간 조건을 다시 읽을 수 있다.
- `period_unsupported`: 해석이 풀지 못한 기간(`period_diagnosis: unsupported`, `invalid`, `extract_status != explicit`, B가 풀 수 없는 표현) → 요구 `unresolved` + 사유 코드, 기본 기간으로 대체하지 않음. malformed(`period_diagnosis: malformed`, 조건 구조 오류) → 상태 `invalid_input`, B에서는 입력 계약 오류(재개 지점 없음).
- 카탈로그 전체 무결성 오류(`duplicate_catalog_id`, `duplicate_metadata_id`, `invalid_catalog_path`)는 재개 지점 `none`(오류로 종료).

## 3. 묶음 기준점과 담당 구간

- 입력 `context = {bundle_id, anchor_source: bundle_common | table_latest, anchor: "YYYY-MM" | None, simultaneous: bool}`: bundle_common이면 상대·열린·가정 기간을 그 시점에 맞춘다(명시 닫힌 기간은 영향 없음). anchor가 표 최신보다 뒤면 `invalid_input`.
- 입력 `assignment = [{"start": "YYYY-MM", "end": "YYYY-MM"}]`(표의 담당 구간, 판 연결): 원 요청 구간은 그대로 두고, 그 표는 원 요청 ∩ 담당 ∩ 수록 범위만 조회.
- B 실행기는 scope의 표들로 담당 구간 합집합(`covered`)과 미충족 구간(`unmet`)을 월 단위로 보고한다. 수록 범위 밖으로 데이터가 없는 표는 다른 표가 있으면 빼고 안내한다.
- A→B 입력 칸(제안, A 계획 17이 채울 자리): `selections[].bundle = {bundle_id, context, assignments: {table_id: [...]}}`.

## 4. 어댑터 보강

- 요구 키 `requirement_key = {reading_id, requirement_id}`(규칙 모드는 reading_id None).
- 조건 보조 칸: `analysis.decomposition.condition_fields`를 조건 ID로 병합해 `hints.condition_fields`(source·confirmed·period_diagnosis 보존, A의 applied는 버림). 조건 목록에 없는 ID는 요청 `input_errors`(계약 오류).
- 추론 힌트: `decomposition.inferred[requirement_id]`가 있으면 그대로(빈 배열 포함), 없으면 칸 부재.
- 묶음 전체 표(3표 이상 포함), 첫 대안 묶음 `alternatives`(조회 안 함), 참고 후보 `reference_candidates`(조회 안 함, 대안과 분리).
- 값 행 `hints.value_rows`: `analysis.mentions[].candidates` 중 scope 표의 target·basis·indicator·breakdown·ITEM 행, 요구 조각에 묶인 등장만(조각에 안 묶인 등장은 `bound: false`), 부정 표시.
- 다른 해석(`decomposition.alternative`)은 읽지 않는다(현재 요구에 부분 적용하지 않음).
- B 결과: 요구별 `condition_fields`(B가 applied를 채움), 공용 가정 `shared_assumptions`(stage B).

### 7.1 바뀐 동작

- `attrs.invalid: true` → `invalid_input` / `malformed_condition`(문제 `...attrs.invalid: marked invalid by the interpretation (malformed)`). 조건 칸이 없거나 `period_diagnosis`가 ok·unsupported로 모순돼도 같다. B는 모델·조회 전에 종료하고 기본 기간으로 바꾸지 않는다.
- `attrs.extract_status`는 문자열인지만 본다. 구조가 정상인 기간은 해석기가 직접 읽고, 못 읽으면 unresolved / `period_unsupported`(detail은 읽지 못한 부분, 예 `period_expression`). 명시 `period_diagnosis: unsupported`는 `period_unsupported`(detail `diagnosed_unsupported`), `malformed`는 `invalid_input`. 새 기간 판정기는 만들지 않았다.
- `assignment`: 목록 형태 유지. None이면 기존과 같다. 지정하면 구간 하나만 허용하고, 둘 이상이면 `check_assignment`가 `assignment: one continuous segment per table expected, got N`을 내며 해석기는 `invalid_input` / `invalid_assignment`(다른 입력 문제와 같이 있으면 `malformed_condition`에 문제 목록 전부). 메우거나 첫 구간만 쓰지 않는다. B는 사유 코드 `invalid_assignment`(input, 재개 지점 none)로 모델·조회 전에 종료한다. B 진입점 `check_request`도 같은 `check_assignment`를 쓴다. 여러 표 묶음과 사용자의 여러 기간 조건은 제한하지 않는다.
- 담당 구간 사이 안내 `assignment_gap_queried`는 없앴다(한 구간만 허용하므로 생길 수 없음).
- 판본: 계약 `period-contract/2026-10-21.2`, 패키지 `0.2.0`(B `pyproject.toml` 핀과 `uv.lock`의 `claview-period` 판본 줄만 변경, 다른 패키지 판본 그대로, `uv lock --offline --check` 통과). 정책은 그대로 `period-policy/2026-10-21.1`.
