# 골든셋과 평가 계획

- 관리: 팀 공동 / 갱신일: 2026-09-23
- 상태: 대표 사례 5건의 MD와 별도 검색 개발 질문 48건의 JSON을 반영했습니다. 둘 다 미승인 초안이며 승인된 자동 채점용 정답셋·채점 코드는 아직 없습니다. 최종 건수·비율·목표 점수는 미확정입니다.
- 적용 범위: [프로젝트 개발계획](../project/프로젝트_개발계획.md)의 기능별 평가와 전체 과업 평가.

## 1. 현재 준비한 사례와 남은 범위

[골든셋 초안 5건](../../eval/goldenset/골든셋_초안_5건.md)에 질문·기대 행동·통과/실패 기준·검수 상태를 모았습니다. 표 ID는 원문에서 선정한 후보이며, 각 사례의 실제 코드·수치 정답이 승인됐다는 뜻은 아닙니다. 5건은 팀의 판정 기준을 맞추기 위한 자료로, 전체 통계표의 성능을 대표하지 않습니다.

| 사례 | 확인할 능력 | 현재 상태 |
| --- | --- | --- |
| CV-G001 · 경제심리지수 원계열 | 같은 표 안에서 계열·기간·주기 선택 | 후보·행동 초안, 코드·수치·팀 검수 대기 |
| CV-G002 · 주담대 신규취급액 금리 | 일상어 연결과 사용자가 지정한 기준 보존 | 후보·행동 초안, 코드·수치·팀 검수 대기 |
| CV-G003 · 카드 사용 | 조건 확인 후 후속 답변을 조회 조건으로 연결 | 되묻기 정책 합의·코드·수치·팀 검수 대기 |
| CV-G004 · 가계대출 두 기준 비교 | 필수 계열 모두 선택, 정합·비교 | 두 계열 코드·수치·팀 검수 대기 |
| CV-G005 · 개별 종목 주가 | 범위 밖 안내, 임의 수치 생성 방지 | 범위 판정 팀 검수 대기, 수치 정답 해당 없음 |

### 별도로 작성된 개발 질문과의 관계

[검색평가 초안 48건](../../eval/goldenset/review/검색평가_초안_48건.json)을 받아 구조와 질문을 대조했습니다. 명확·모호·오연결 방지 각 16건이며, 모두 미실행·의미 검수 전입니다. 문자열이 완전히 같은 질문은 Q01-P와 CV-G001의 1건입니다. 유사 의도·공통 계열도 있으므로 단순 합계 53건이나 중복 1건을 뺀 52건을 독립 골든셋 규모로 제시하지 않습니다.

| 기존 사례 | 개발 질문과 관계 | 처리 |
| --- | --- | --- |
| CV-G001 | Q01-P와 질문 완전 일치 | 승인 시 하나의 기준 사례로 연결. 두 번 채점하지 않음 |
| CV-G002 | Q15-P와 표는 같지만 주담대/가계대출 전체·기간이 다름 | 별도 선택 조건, 같은 정답 코드로 병합하지 않음 |
| CV-G003 | Q13-A와 초기 의도 유사, 후속 답변은 Q13-P와 관련 | 두 턴 평가와 단일 질문을 구분, 구매 금액·집계 기준 추가 검수 |
| CV-G004 | Q15-P·Q16-P의 계열과 관련되지만 기간·복수 비교 요구가 다름 | 단일 표 질문 둘을 통과해도 복수 비교 성공으로 계산하지 않음 |
| CV-G005 | 48건에 같은 질문 없음 | 범위 판정 사례로 별도 유지 |

이 표는 원본 ID를 잇는 검토표이며 원본 JSON을 수정한 통합 정답셋이 아닙니다. 검색·매핑 개발에 사용한 질문은 개발셋으로 관리하며 최종 비교용 독립 평가셋으로 그대로 사용하지 않습니다. 자동 채점 기준본을 만들 때 승인된 항목만 변환하고 원본 ID·검수 근거를 연결합니다.

`negative`는 ‘오연결 방지’ 유형이지 곧 `out_of_scope`가 아닙니다. Q01-N은 소비자심리지수의 다른 표를 탐색해야 하고, Q16-N은 두 금리를 합산하지 않도록 처리해야 합니다. 사례마다 기대 행동을 별도로 판정합니다. `acceptable_candidate_table_ids`도 모두 필수인 집합인지 허용 대안인지 합의 전에는 자동 채점에 사용하지 않습니다.

모호한 질문의 `suggested_question`은 예시일 뿐입니다. Q01-A는 경제심리지수/소비자·기업 심리 중 지표 확인이 필요한데 원문 예시는 원계열/순환변동치만 질문합니다. 의미 검수 후 필요한 조건과 고정 후속 답변을 보완합니다.

### 이후 추가할 사례

- 자료 없음: 고정한 메타·응답 기준에서 수록기간 밖이거나 해당 계열 값이 없는 요청.
- 조회 오류: 유효한 요청에 모의 오류를 주입해 자료 없음과 구분하는지 확인.
- 구조 차이: 다중 분류축, 주기·단위·기준시점 차이, 구/신 계열과 개정 이력.

이 항목들은 추가 계획이며 현재 5건에 포함되지 않습니다. 오류 주입은 모의 시험으로 표시하고 실제 장애 관찰 결과로 사용하지 않습니다.

## 2. 사례마다 남길 정보

정답은 통계표 ID 하나만으로 정의하지 않습니다.

| 구분 | 기록할 내용 |
| --- | --- |
| 식별·조건 | 사례 ID, 유형, 질문, 필요한 이전 대화, 기준 시점 |
| 기대 행동 | 바로 조회 / 조건 확인 / 범위 밖 안내 / 자료 없음 안내 / 오류 처리 |
| 정답 선택 | 허용 표·항목·분류·통계 기준·기간·주기, 허용 가능한 대안 |
| 기대 결과 | 필수 표·그래프·설명·출처·주의사항 |
| 판정 기준 | 반드시 충족할 조건, 허용하지 않는 행동, 파생값별 비교 규칙 |
| 근거 | 메타 버전, 조회 조건, 응답 스냅샷, 원표 대조 범위 |
| 검수 | 작성자·검수자, 검수 상태·날짜, 미확인 항목 |

복수 계열 요청은 필요한 계열을 모두 기록합니다. 같은 의미를 충족하는 여러 정답 경로가 있다면 대안 묶음으로 표시합니다. 모든 대안을 동시에 찾아야 성공하는 것으로 채점하지 않습니다.

질문·정답 파일은 `eval/goldenset/`, 테스트 응답은 `tests/fixtures/`, 평가 요약은 `eval/reports/`에 둡니다. 전체 원본의 확보 상태는 [데이터 파일 안내](../../data/README.md)에서 확인합니다. 공통 필드와 원값 보존 방식은 [입출력 규격 초안](../architecture/공통_입출력규격_초안.md)을 따릅니다.

## 3. 작성·검수 순서

1. 검수할 자료와 메타 버전을 정합니다. 수집 성공과 수치 검수 완료를 구분합니다.
2. 질문과 기대 행동을 작성합니다. 정상 조회 사례는 코드·조건의 조회 가능성을, 모호·불가 사례는 확인이 필요하거나 처리할 수 없는 근거를 확인합니다.
3. 수치 정답이 필요한 사례는 실제 API 응답을 저장하고 같은 조건의 원표와 대조합니다. 아직 조회하지 못한 사례는 수치 정답 검수 대기로 둡니다. 모호·범위 밖·자료 없음 사례에 불필요한 수치 조회를 요구하지 않으며, 오류 주입 사례는 모의 응답과 기대 처리를 검수합니다.
4. 다른 팀원이 선택 기준·수치·판정 조건을 확인하고 의견 차이를 기록합니다.
5. 검수한 사례만 평가 기준본으로 사용합니다. 개발에 사용하는 사례와 최종 비교용 사례를 분리합니다.

승인은 평가 단계별로 구분합니다. 표 후보·기대 행동만 검수했으면 해당 검색·행동 평가에만 사용하고, 코드·원자료·출력 조건까지 검수한 뒤 수치 포함 E2E 평가에 사용합니다. `미검수`, `검수 완료`, `해당 없음`을 구분하고 검수자·일자·근거를 남깁니다. 현재 5건은 팀 검수 전이므로 점수 집계에서 제외합니다.

다음 검토에서는 ① 5건의 기대 행동 합의 ② 사례별 코드·근거 연결 ③ 필요한 수치 대조 ④ 단계별 승인 범위 기록 순서로 진행합니다. 자동 평가용 형식은 공통 규격과 맞춰 정하며, MD와 JSON을 독립적으로 수정하는 이중 기준을 만들지 않습니다.

LLM이 만든 질문·별칭·정답은 검수 전 후보입니다. 모델 답변이나 임베딩 유사도를 정답 근거로 삼지 않습니다. 최종 비교용 질문을 보며 매핑·프롬프트를 수정했다면 개발용으로 전환하거나 별도 새 평가셋을 확보합니다.

## 4. 단계별 측정

| 단계 | 지표 후보 | 판정 방법 |
| --- | --- | --- |
| 검색 | Recall@k, 필수 후보 전체 포함률 | 정답이 있는 사례에서 요구한 표 또는 계열이 후보에 포함되는지 확인 |
| 조건 선택 | 필드별 정확도, 전체 조건 일치율 | 표·항목·분류·기준·기간·주기를 정답 조건과 비교 |
| 사용자 확인 | 필요한 확인 수행률, 불필요한 확인 비율 | 모호한 사례의 필수 질문과 명확한 사례의 불필요 질문을 각각 집계 |
| 조회 | 유효 파라미터 비율, API 호출 성공률 | 인자 유효성, 통신 성공, 반환 자료의 조건 일치를 구분 |
| 수치·가공 | 원값 일치율, 정합·계산 규칙 통과율 | 같은 시점의 원본·가공 정답과 대조 |
| 시각화·설명 | 필수 항목 준수율, 루브릭 판정 | 값·축·단위·범례·기간·출처·가공·경고의 정확성과 누락 확인 |
| 전체 과업 | Task Success Rate | 해당 유형의 필수 조건을 모두 충족했는지 판정 |
| 운영 특성 | 지연·호출 수·토큰·재시도 | 동일한 실행 조건에서 전체 과업과 단계별 사용량 기록 |

각 지표의 대상과 분모를 고정합니다.

- 검색 단위가 표인지 계열인지 먼저 정합니다. Recall@k는 각 질문에서 필요한 정답 중 상위 k개 후보로 회수한 비율로 계산하고 질문별 평균을 냅니다. 허용 대안은 미리 정한 동등한 정답으로 처리합니다.
- 필수 후보 전체 포함률은 복수 계열 등 필요한 후보를 모두 찾은 질문 수 / 평가 대상 질문 수입니다.
- 정답 후보가 없는 질문은 검색 Recall 분모에 넣지 않고, 적절한 한계 안내 여부로 평가합니다.
- 과업 성공률은 모든 필수 조건을 충족한 사례 수 / 실행 대상 사례 수입니다. 일부 결과만 제공했거나 필수 그래프가 빠지면 완전 성공으로 계산하지 않습니다.
- 검수 대기 사례는 실행 전에 별도 분리합니다. 실행 후 실패한 사례를 임의로 분모에서 제외하지 않습니다. 외부 장애는 별도 표시하고, 제외·재실행 여부와 전체 건수를 함께 보고합니다.
- 모호한 질문은 첫 응답의 조건 확인과 후속 답변 반영을 나눠 판정합니다. 확인 질문의 문장 일치가 아니라 필요한 조건을 확인했는지 평가합니다. 후속 답변은 고정해 실행 간 조건을 맞춥니다.
- 명확한 질문에서 불필요한 확인이 있었는지는 별도 집계합니다. 그것만으로 E2E 실패로 볼지는 실행 전에 과업별 필수 조건으로 정합니다.

## 5. 수치와 설명의 검증 기준

원본 응답의 `DT`는 그대로 보존합니다. 원본 보존 검사는 문자열 변형 여부를, 표시·계산 검사는 결측 기호·단위·정밀도를 처리한 값의 일치 여부를 확인합니다. 이 두 검사를 혼동하지 않습니다.

파생값은 계산식·입력 계열·집계 기준·반올림 규칙을 먼저 정하고 정답과 비교합니다. 모든 계산에 같은 오차나 소수 자릿수를 일괄 적용하지 않습니다. 허용 오차가 필요하면 절대·상대 오차와 0 근처 값의 처리 기준을 해당 계산별로 기록합니다.

차트는 이미지 유사도만으로 채점하지 않습니다. 차트에 전달된 데이터와 축·단위·범례·시점의 명세를 검사하고, 가독성은 별도 사람이 확인합니다. 설명은 근거가 있는 주장인지, 조회되지 않은 수치나 인과관계를 추가했는지 확인합니다.

## 6. 도구·에이전트 평가 분리

- 도구 시험: 올바른 인자를 직접 전달했을 때 조회·계산·응답이 맞는가?
- MCP 연결 시험: 외부 클라이언트의 도구 발견·호출·결과 수신이 정상인가?
- 에이전트 시험: 질문에서 적절한 도구와 인자를 선택하고, 모호함·실패를 처리하는가?

도구가 정상 작동해도 에이전트가 잘못된 계열을 선택할 수 있습니다. 반대로 의도 해석이 맞아도 외부 API가 실패할 수 있으므로 단계별 결과를 함께 남깁니다.

단계별 시험은 검수된 중간 입력을 직접 넣어 앞 단계 오류와 분리합니다. 예를 들어 조회 도구에는 정답 조회 조건을, 시각화에는 검수한 자료를 전달합니다. E2E 평가는 질문부터 실제 선택 경로를 실행하므로 중간 정답을 주입하지 않습니다.

## 7. 개선 전후 비교

같은 질문·정답·메타·수치 스냅샷을 사용하고 코드, 모델, 프롬프트, 검색 문서·색인 버전을 기록합니다. 최신 API를 직접 조회하는 시험은 자료 개정 영향을 구분할 수 있도록 실행 시점을 남깁니다.

키워드 기준선부터 시작해 매핑·임베딩·재정렬 등을 한 번에 하나씩 추가하는 비교를 우선합니다. 모든 조합을 시험할 필요는 없으며 발견한 오류에 따라 우선순위를 정합니다. 반복 실행의 변동과 유형별 실패 사례를 함께 보고하고, 적은 표본의 차이를 전체 성능 개선으로 단정하지 않습니다.

최종 목표 점수·유형별 비율·건수·반복 횟수는 기준선 측정 후 정합니다. [NCP 초기 호출 기록](NCP_초기호출_검증결과.md)은 API 접근 확인 자료이지 모델 선정용 벤치마크가 아닙니다. 확정한 정책은 [설계결정과 검토사항](../decisions/설계결정과_검토사항.md)에 남깁니다.
