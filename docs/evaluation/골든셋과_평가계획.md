# 골든셋과 단계별 평가 초안

- 담당: 팀 공동 작성, 정리: 채진현
- 정리일: 2026-09-22
- 상태: 평가 설계 초안. 평가셋 규모·목표 점수·최종 지표는 미확정.
- 근거: [프로젝트 범위](../project/프로젝트_범위와_처리원칙.md), 팀의 정상·모호·불가 사례 논의

## 먼저 작성할 사례

초안은 같은 대표 표와 메타를 사용한 정상·모호·불가/오류 3~5건으로 구성합니다. 최종 평가셋 규모·유형별 비율은 별도 합의합니다.

| 사례 필드 | 작성 내용 |
| --- | --- |
| 식별자·유형 | 단일/복수 계열, 모호, 범위 밖, 자료 없음, 조회 오류 |
| 입력 | 질문과 필요한 대화 이력 |
| 기대 행동 | 바로 조회 / 조건 확인 / 한계 안내 / 재시도 안내 |
| 정답 조건 | 허용 표·항목·분류·기준·기간·주기와 대안 |
| 기대 결과 | 표/차트·조회 조건·출처·가공 기록·경고 |
| 근거 | 검증된 메타·수치 스냅샷과 원표 대조 기록 |
| 판정 | 반드시 충족할 조건, 허용 오차, 제외 사유 |
| 검수 | 작성자·검토자·상태·버전 |

LLM으로 만든 질문은 초안이며 정답 검증을 대신하지 않습니다. API 장애는 자료 없음과 구분하며, 가능한 경우 모의 응답으로 재현해 외부 장애에 의존하지 않게 합니다.

## 평가 축과 후보 지표

| 단계 | 확인할 것 | 지표 후보 |
| --- | --- | --- |
| 검색 | 정답 표·계열이 후보에 포함되는가 | Recall@k, 모든 필수 후보 포함률 |
| 조건 선택 | 항목·분류·기간·주기·기준이 맞는가 | 필드별 정확도, 전체 조건 일치율 |
| 상호작용 | 필요한 확인만 하고 답변을 반영하는가 | 필요 확인 수행률, 불필요 확인 비율 |
| 조회·가공 | 유효 요청·원본 보존·변환 규칙이 맞는가 | 요청 성공률, 수치 대조·정합 통과율 |
| 시각화·설명 | 값·축·단위·출처·주의사항이 맞는가 | 필수 항목 통과율, 근거 기반 루브릭 |
| E2E | 유형별 필수 조건을 모두 만족하는가 | Task Success Rate |
| 실행 비용 | 응답시간·토큰·호출량·재시도 | 사례별 실측 및 충분한 표본의 분포 |

단일 정답과 복수 필수 정답은 구분하고, 지표의 분모·실패·제외 기준을 먼저 적습니다. 불가 질문의 성공은 그래프 생성이 아니라 올바른 한계 안내입니다. 도구에 올바른 인자를 직접 넣는 시험과 에이전트가 인자를 선택하는 시험은 분리합니다.

## 비교 실험 원칙

1. 개발용 사례와 최종 평가용 사례를 구분합니다.
2. 메타·자료 스냅샷, 코드·모델·프롬프트·검색 설정 버전을 기록합니다.
3. 같은 사례에서 모델 또는 검색 방식 등 한 변수를 우선 비교합니다.
4. 원본 값은 원문과 상태를 보존하고, 파생값은 변환별 허용 오차를 정합니다.
5. 실패 유형·표본 수를 함께 보고합니다. 소수 연결 시험을 모델 성능이나 p95 결과로 확대하지 않습니다.
6. 기준선과 오류 분석 후 목표·개선 우선순위를 합의합니다.

## 주요 지표의 판정 기준

- Recall@k: 상위 k개 후보에 포함된 필수 정답 수 / 해당 질문의 필수 정답 수. 표 또는 계열 중 평가 단위를 고정합니다.
- 필수 후보 전체 확보율: 필요한 정답 집합을 모두 확보한 질문 수 / 평가 대상 질문 수.
- Task Success Rate: 유형별 필수 조건을 모두 충족한 질문 수 / 평가 대상 질문 수. 부분 결과는 전체 성공과 구분합니다.

범위 밖·자료 없음 질문은 검색 Recall 분모에서 분리하고 한계 안내 정확도를 평가합니다. 허용 가능한 대체 표 조합과 제외 조건은 골든셋에 명시합니다.
